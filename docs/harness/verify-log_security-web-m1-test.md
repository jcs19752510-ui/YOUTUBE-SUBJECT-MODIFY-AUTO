## 1차 검증 — 작성자 관점 자가 재검토
- 방법: 에이전트 정의의 최소 점검 항목 19개를 체크리스트로 삼아 하나씩 수행했다. 입력 문서(CLAUDE.md 현황·brief·위협 모델 Part W·02 위험 평가·DESIGN Part B·6단계 결과서 4건·요구서 §9·이전 SBOM)를 읽고, 소스(`ytweb/**` 전체, 프런트 위험 싱크 전수 grep + 핵심 파일 정독, nginx·compose·DB 초기화·스크립트·CI 예시)를 정독한 뒤 도구(pip-audit·npm audit·Trivy·레지스트리 조회)와 시험(오프라인 → 실스택)을 순서대로 돌렸다.
- 발견된 결함/문제:
  1. **시험 자신의 오류 12건**(내 잘못된 기대): FastAPI 0.143 의 `include_router` 가 라우트를 `_IncludedRouter` 로 감싸 `app.routes` 가 비어 "전수 시험"이 빈 반복이 됨(→ OpenAPI 로 목록 생성, 최소 개수 단언 추가), 시계가 같아 세션 상한 시험이 축출을 못 봄, `LOCALHOST:8080` 이 nginx 에서 통과하는 것을 우회로 오판, 로그인 시험이 쿠키를 갈아끼워 CSRF 토큰이 낡음, 승인자 제로폭 문자를 "거부"로 기대(→ 실제로는 허용=결함 DEF-9-004), `GRANT` 가 경고만 내고 rc 0 인 것을 권한 상승으로 오판, 실스택 시험이 이전 실행의 후보를 소진 등. 전부 시험 쪽을 고쳤다.
  2. **제품 결함 후보**: 상한 없는 정수→500(DEF-9-001), 롤백 덮어쓰기 재현(DEF-9-002), 세션 갭(DEF-9-003), 제로폭 승인자(DEF-9-004), CI 예시(DEF-9-005), `.gitignore` 의 `client_secret*.json` 누락(DEF-9-006), **면책·AI 고지 문구 미노출(DEF-9-007·008)**, pip 잔존(DEF-9-009), 이미지 OS 패키지 취약점(DEF-9-010), edge 경유 호스트/LAN 도달(DEF-9-011), 복원 fail-open(DEF-9-012), 보관·파기 미구현(DEF-9-013), 감사 체인 키 없음(DEF-9-014), 의존성 신선도(DEF-9-015), nginx 오류 로그 요청 줄(DEF-9-016).
  3. **이전 SBOM 결함**: npm 12개 누락·라이선스/그래프/OS 패키지 없음 → 6종으로 대체하며 유지보수자 이메일 302건을 제거(처음 한 번의 일괄 치환이 purl 문자열을 훼손해 원본에서 다시 만들고 `supplier.name`·`author` 필드만 정확히 처리하도록 고침).
- 조치: 시험 쪽 오류는 수정. 제품 결함은 **고치지 않고** 재현 시험(통과 시 재현)과 `xfail(strict)`(바람직한 동작, 고치면 XPASS 로 알림)로 남기고 결과서 6절에 기록(소스 수정 금지 지시, 대부분 사용자 결정·타 단위 소유).

## 2차 검증 — 독립 심사자·공격자 관점 재검토
- "내가 이 시스템을 공격한다면" 관점으로 다시 읽고, **시험이 정말 보안 통제를 잡는지**를 변이 점검으로 확인했다. 방법: 소스 사본에 한 곳씩 일부러 결함을 넣고(대상 문자열은 원본에 정확히 1곳) 시험이 실패하는지 본다. 원본 미수정.
  - 코드 변이: 1회전 58곳 → **8곳 생존**(교차 출처 별도 한도·CSV 주석 행·승인 1회용·승인 만료·감사 `prev_hash`·롤백 후속 변경·배치 확인 문구·`/docs` 변이 자체가 동치였음) → 시험 12건 추가/강화 → 2회전(생존분 8 + 신규 16곳): 신규 2곳 생존(PIN 실패 기록 commit·수정 가능 상태 검사) → 시험 2건 추가 → **최종 회전 74곳 [[MUT_CODE_FINAL]]**.
  - 설정 변이(compose·nginx·보안 헤더·pg_hba·역할·Dockerfile·`.gitignore`·잠금 파일·프런트·스크립트·CI): 1회전 45곳 → **5곳 생존**(assets location 헤더 include·X-Frame-Options 값·CSP 인라인·앱 계정 슈퍼유저·잠금 파일 해시 줄 주석 처리) → 정적 시험을 "이름 존재"에서 "값·구조 검사"로 강화 → 2회전 5/5 잡음 → **최종 회전 45/45 잡음**.
  - 변이 점검이 가짜 검출이 아님을 확인: 동치 대조군(독스트링만 변경)은 정상적으로 생존했고, 변이 대상이 0곳/2곳이면 오류로 중단되며, 오프라인 시험은 `YTWEB_SEC_BACKEND_DIR` 로 사본을 가리킨 것을 시험 안에서 확인하지 않아도 변이가 실제 사본에 적용되지 않으면 모든 변이가 생존하므로(1회전에서 49/58 잡힘) 사본 경로가 유효함을 입증한다.
- **연쇄 공격 점검(카테고리 교차)**: 인증 우회+출력 새니타이즈 누락, 프롬프트 인젝션+엄격 모드 우회, 공급망+컨테이너 격리+edge 망, 호스트 비밀+감사 체인, 세션 축출 DoS, 백업 변조+복원 fail-open, DNS 리바인딩+Host/Origin, 세션 탈취+PIN 변경 — 9경로(결과서 부록 H-2). 이 과정에서 **새 사실 2건**을 확인: web→호스트 게이트웨이 0.0.0.0 서비스 도달(DEF-9-011 범위 확대: 6단계의 DEF-VI-001 해소 후에도 남은 경로), nginx 오류 로그 요청 줄에 쿼리 잔존(DEF-9-016).
- 의심한 점과 확인:
  (a) "결함 없음"으로 읽히는 통과가 사실 빈 반복이 아닌지 → 전수 시험에 최소 개수(라우트 ≥ 25, 변경 라우트 ≥ 11) 단언, 변이 점검으로 실효성 확인.
  (b) Trivy 가 "0건"을 내는 건 아닌지 → 감도 확인(알려진 취약 입력으로 pip-audit·npm audit 검출 확인, Trivy 는 실제 결과 다수).
  (c) 6단계 "해소" 주장 재검증 → DEF-VI-001(web→db 이름·IP 도달 불가 실측), DEF-VI-002(`alembic_version` 권한 `f`), DEF-VF-B01(PostgreSQL 에서 PIN 동시 추측 직렬화 실측)을 직접 다시 재현 시도해 해소를 확인. DEF-VI-003 은 잔여가 있음을 확인.
  (d) 심각도 자의적 축소 여부 → 계획서가 "중"으로 본 RISK-036(면책 미노출)을 규칙 I 에 따라 Critical 로 상향. 이미지 취약점은 도달성 근거(네트워크 입력 경로 밖, 비루트·읽기 전용, 상류 수정본 없음)를 적고 Medium 으로 판단했으며 이 판단은 사용자 질문(Q-S9-4)으로 돌려 확인받게 했다. DEF-9-002 는 M1 영향 없음을 근거로 Medium, **M3 진입 시 High** 로 명시.
  (e) 내가 쓴 도구를 믿어도 되는가 → Trivy 는 `aquasec/trivy:latest` 태그로 받았으나 다이제스트·버전을 기록했고 서명 검증은 못 했음을 한계로 적었다(위협 모델 TW-13 의 "도구 침해 이력").
- 발견된 결함: 변이 생존 8+2+5 건은 모두 **시험의 구멍**이었고 보강으로 해소. 제품 결함 신규 2건(DEF-9-011 확대·DEF-9-016 실측).

## 한계 (정직한 기록)
- 같은 모델이 시험 설계자·실행자·판정자를 겸했다. 변이 점검(119곳)과 실스택 시험으로 실효성을 보강했지만 독립된 사람의 검토는 아니다. 외부 침투 테스트가 필요하면 별도 승인된 점검이 필요하다(규칙 A).
- Linux 엔진·파이썬 3.13(시험)·3.12(이미지)에서만 확인. Windows Docker Desktop·PowerShell 5.1·Windows ACL·실제 브라우저(CSP·확장프로그램)는 **미수행**이며 PASS 로 세지 않았다.
- 빌드는 프록시 CA 를 builder 단계에 주입한 Dockerfile 사본으로 했다(최종 단계는 저장소와 동일). 이미지 ID 는 재현 불가.
- Trivy 는 태그로 내려받았고 서명 검증은 못 했다. Trivy DB·pip-audit 의 취약점 DB 는 조회 시점(2026-10-11) 기준이다.
- 프런트 페이지 컴포넌트를 줄 단위로 전수 정독하지는 않았다(위험 싱크 전수 grep·ESLint 규칙·번들 검사로 대체).
- `git status` 원문은 지시 충돌로 첨부하지 않았다.
