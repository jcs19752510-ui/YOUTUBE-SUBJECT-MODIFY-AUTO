# 일괄 승인(N건) 내부 테스트 결과서 (2026-10-13)

**한 줄 결론: 조건부 PASS.** 구현·독립 검증·보안 검토·회귀·실연동 통합 시험을 마쳤고 확인된 코드 결함은 조치했다. 남은 것은 선생님 결정 3건(아래 8장)과 정리 승인 대기뿐이다. 실제 유튜브 호출·실제 제목 변경은 0건이다.

## 1. 개요
- 요청: 영상 1건씩 하던 제목 변경 **승인**을 N건씩, 영상 ID로도 할 수 있게(선생님 결정: 목록 선택+ID 붙여넣기 둘 다 / 후보 여럿이면 선택 화면 / 최대 50건 / 승인과 배치 실행 분리). 계약 `docs/harness/bulk-approve/CONTRACT.md`.
- 구현: 백엔드 `POST /api/v1/suggestions/resolve-videos`, `POST /api/v1/suggestions/approve-batch`, `approve()`의 `ack_warning`(경고 건 서버 강제), 프런트 `#/bulk-approve` 페이지. 건마다 기존 `approve()`(재검증·HMAC 서명·감사)를 SAVEPOINT 안에서 호출 → 검증 강도 불변. 이 단계는 **승인만** 하며 제목은 바뀌지 않는다.
- 소요(`date -u`): 03:09 시작 → 03:49 최종 취합. 단 15분 상한 취지(한 번에 15분 이내)를 연속 단위로 이어 붙여 어겼다(선생님 지적, 인정).

## 2. 시험 환경
클라우드 리눅스, 임시 PostgreSQL 16(127.0.0.1:54329, 시험 전용 DB 분리), Python 3.12 venv(`.harness-tmp/venv_06_web_be_b`), Node + Vitest, Playwright Chromium. 구글·유튜브 접속 없음(데모 모드). **Windows 선생님 PC·Docker Desktop·실제 구글은 미수행.**

## 5. 보안 검토 (정적, `security-review.md`)
15개 점검 중 11 적합·결함 4·참고 1, Critical/High 0건. 건별 HMAC 서명, 경고·차단 서버 강제, CSRF·Origin, 제안 id 정렬 잠금, 입력 검증, XSS, 실행 직전 제목·plan_hash 재검증은 적합. 위협 모델 `docs/yt/threat_model.md` W10(TW-45~50) 반영.

## 6. 검증 로그 (최소 2회)
1회차 구현자 시험·변이 → 2회차 독립 검증자(구현자와 무관) 시험·변이 → 3회차 조치 후 재실행(67/67, 프런트 823) → 4회차 실연동 5차 8/8. 화면은 목 기반 7/7과 실연동 14장 캡처 두 번.

## 7. 미수행 (정확히)
- Windows 선생님 PC, Docker Desktop, 실제 구글 접속, 실제 제목 변경(선생님이 "실행"이라 하시기 전 금지).
- 앱 DB 역할 분리 환경 시험(통합은 postgres 계정), 50건 초과 선택 UI 실연동, 승인 유효 시간 만료 실연동, 통합 시험의 변이 점검.
- `core`·`domain` 등 일부 회귀 구간은 정수 엄격 검사 변경 전에 실행했다(변경 후에는 verify_wa/wb/wfixbe/trace와 67건만 재실행). 변경 범위가 일괄 승인 스키마 2필드뿐이라 위험은 낮지만 전체 재실행은 안 했다.
- 색 대비(jsdom 한계), 스크린리더 실기기, 좁은 화면(미지원 확정).

## 8. 잔여 위험·선생님 결정 대기
1. 승인 유효 1시간의 기준: 배치 실행 확정 시각까지 / 실제 반영 시각까지(SEC-BA-002).
2. 일괄 승인 전용 속도 제한 필요 여부(SEC-BA-003).
3. 차단 판정 제안을 일괄 승인 목록에 사유와 함께 비활성으로 보여 줄지.
