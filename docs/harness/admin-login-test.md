## 6. 남은 위험·미확인

- Windows 실기·브라우저·실제 스택 확인 전이다. 첫 사용 시 `start.ps1` 이 아이디·비밀번호를 물으므로 선생님 PC에서 한 번 확인이 필요하다.

- `restore.ps1`·`reset-demo.ps1` 은 비밀 파일이 없으면 시작이 실패하므로 `start.ps1` 을 먼저 실행해야 한다.

## 8. 개정 3(DEC-057) 최종 시험 결과 — 로그인 화면만, 계정은 `web\.env` 값 (2026-10-15 03:14 UTC)

선생님이 DEC-056 의 "웹에서 계정 만들기"를 거부했다("로그인 화면만, 다른 사람이 계정을 만들면 절대 안 됨"). 웹·API 로 계정을 만드는 경로를 모두 삭제하고, 관리자 아이디·비밀번호는 선생님 PC `web\.env` 의 `YTWEB_ADMIN_ID`·`YTWEB_ADMIN_PASSWORD` 로 api 가 시작할 때 해시로 준비한다. 값이 없으면 아무도 로그인할 수 없다(409 `login_not_configured`, 화면에 설정 방법 안내). 소요: 03:08 시작 ~ 03:14 시험 완료(약 6분, 병렬 에이전트 3개).

| 시험 | 결과 |
|---|---|
| 백엔드 `tests/core`+`verify_wa`+`verify_spec`+`domain`(PostgreSQL 16 임시 DB 포함) | **1135 통과 / 실패 0** |
| 프런트 vitest 전체 | **955 통과 / 예상 실패 1 / 건너뜀 21 / 실패 0**, 빌드·eslint·tsc 통과 |

새 시험(TC-AL-301~308): 계정 생성 경로 없음(`/auth/setup`·register 등 404/405, 임의 계정으로 로그인 401), OpenAPI 에 생성·초기화 경로 없음, DB 관리자는 `.env` 값 1개·해시만, 값 없으면 로그인 불가(409+안내), `.env`→계정 반영(생성/변경 없음/비밀번호 변경 시 세션 종료/값 없음/형식 오류/아이디 변경 시 1명 유지), 특수문자 비밀번호와 repr 비노출, 파일 설정 제거. 프런트: 계정 만들기 화면·API 삭제, 409 안내 표시.

**첫 실행 실패(기록)**: ①인프라 5개 — 기존 "환경 변수 비밀은 `*_FILE` 만" 규칙 4개가 새 설계(api 의 `YTWEB_ADMIN_PASSWORD`)와 충돌 → api 의 `${YTWEB_ADMIN_PASSWORD:-}` 형태 하나만 예외로 허용(다른 서비스·키·실제 값은 계속 실패), 새 시험 정규식 1개 수정 ②백엔드: 이전 개정에서 만든 최초 설정 시험·`admin_cli` 시험은 기능 삭제로 제거(사유: 선생님 요구).

**안 한 것(정확히)**: Windows PC·실제 Docker 스택에서 `.env` 값이 api 컨테이너로 들어가 로그인되는지 확인, `start.ps1` 실행(정적 검사만), 실제 백엔드와 붙인 화면 캡처(응답은 `page.route` 모의).

**잔여 위험**: 비밀번호 원문이 `web\.env` 와 api 컨테이너 환경 변수에 남는다(같은 PC 의 Docker 권한자가 `docker inspect` 로 열람 가능). 인프라 시험의 `*_FILE` 원칙에 이 한 건만 예외로 둠 — 수용 사항(DEC-057).
