## 1차 검증 — 작성자 관점 자가 재검토 (이전 진행분 + 정적 검사)
- 검증자(역할): 시험 작성자(심사자 1차)
- 방법
  1. 구현 노트(§13)의 인수 조건과 요청서 중점 항목에 시험 ID 를 연결(AC 18개, 연결 없는 AC 0개).
  2. 이전 진행분 시험(TC-VF-001~189, 7파일) 전부 읽고 재사용 여부 판단. 기준선 실행: `397 통과 + 11 expected-fail(it.fails)` — expected-fail 10곳이 이미 알려진 앱 결함(DEF-6-001~011)이었다.
  3. `tsc`·ESLint·Prettier·`vite build`·`npm audit` 기준선 확인 → 모두 통과.
  4. 소스 직접 읽기: `client.ts`, `BatchDetailPage`, `SuggestionCard`, `HistoryPage`, `SettingsPage`, `PinForm`, `AuthGate`, `JobPanel`, `Modal`, `ErrorPanel` 등.
- 발견된 결함
  1. 앱 결함 10건(DEF-6-001~011, 결번 009) — 시간 제한 없음, 한도 정규식, 말투 40자 제한, 작업 창 닫기 불가, 오류 경계 없음, 랜드마크 중복, 쪽 크기 200, 불러오기 중복 시작, 배치 상태·작업 종류 영문 표기
  2. 앱 결함 신규 — DEF-VF-001(엄격 모드 경고를 일반 경고로 취급; 서버 `is_blocked` 와 불일치), DEF-VF-002(200개 초과 선택), DEF-VF-003(사라진 선택 항목 전송), DEF-VF-004(403 을 틀린 PIN 으로 안내), DEF-VF-006(문구 하드코딩)
  3. 시험 설계 결함 — TD-1(경고 제안에 `strict: true` 고정), TD-2(TC-VF-179 선택자 모호 → 엉뚱한 이유로 실패), TD-3(TC-VF-095 가 Esc 결과 미확인)
- 조치: 앱 결함은 `web/frontend/` 안이라 직접 수정하고 회귀 시험 추가(TC-VF-190~241). `it.fails` 11곳을 일반 시험으로 전환(전환 시 "Expect test to fail" 10건 = 이제 통과 확인, 나머지 1건 TC-VF-179 는 TD-2 정정). → v1

## 2차 검증 — 독립 심사자 관점 재검토 (변이 점검 + 실서버 + 실브라우저)
- 검증자(역할): 구현자·1차 작성자의 시험을 믿지 않는 심사자
- 방법
  1. **변이 점검 1회전**: 안전 로직·경계값·내가 고친 결함의 되돌림 71개를 격리 사본에서 적용. 63 잡음 / 8 놓침(M13, M16, M22, M32, R04, M59, R11, M60).
     - 놓침 분석: M13·M22 동치(근거 부록 A), R11 환경 동치, M16/M32/M59/M60/R04 는 시험 공백 → TC-VF-220·221·228·229·230·095 강화/추가.
  2. **실서버 계약 연동**: 임시 PostgreSQL(54333) + 백엔드 + 워커 기동, 프런트 실제 `ApiClient`/`endpoints` 로 21건(TC-VF-300~320). 처음엔 7건 실패 — 원인 조사 결과 **프런트 결함이 아니라 백엔드의 commit-after-response 경쟁**(DEF-VF-B01). 재현 스크립트로 40회 중 7회 재현(PIN 변경이 `current_pin` 없이 통과). 계약 시험은 변경 직후 250ms 대기로 안정화하고, 대기 0ms 실행은 B01 증거로 보존.
  3. **프런트 완화(DEF-VF-005)**: 방금 만든 작업 조회가 404 일 때 즉시 오류를 띄우던 문제를 JobPanel 재확인(0.5초×3)으로 완화. 근본 수정은 백엔드(B01).
  4. **실브라우저**: Chromium 1194 로 전체 흐름·axe(**색 대비 포함**, wcag22aa)·1024/1280/375px·다크 모드·Tab 순서. 위반 0(34조합), 375px 가로 넘침은 설계 비대상 관찰.
  5. **서버 오류 코드 전수 대조**: 백엔드 `ProblemError` 코드 49종을 열거해 hint 유무 확인 → 대표 22개 코드와 hint 없는 6개 경우를 TC-VF-222~226 으로 시험. 서버 hint 누락 5개 코드는 B02 로 보고.
  6. 보안 관점 읽기: 저장소(localStorage 등) 미사용(소스 규칙+번들 검색 0건), `dangerouslySetInnerHTML` 은 React 내부에만, 외부 URL 호출 없음(번들의 URL 은 XML 네임스페이스·React 문서 문자열), CSRF/멱등키/재시도 규칙 TC-VF-001~022, 로그아웃은 서버 성공 시에만 상태 변경, PIN·토큰 console 비출력(TC-VF-038).
- 발견된 결함
  1. DEF-VF-005(작업 404, 프런트 완화), 백엔드 DEF-VF-B01(High)·B02(Low)
  2. 변이로 드러난 시험 공백 5곳(위), 변이 점검 자체의 오류 — 1회전 M49 가짜 검출
- 조치: 시험 보강, DEF-VF-005 수정. → v2

## 한계 (정직한 기록)
- 같은 모델 계열이 구현 노트 작성 세션과 다른 세션에서 심사했지만, 완전히 다른 팀의 독립 검증은 아니다. 변이 점검과 실서버·실브라우저 점검으로 시험의 실효성을 보강했다.
- 병렬로 다른 에이전트가 CPU 를 쓰는 동안 변이 점검을 돌려 일부 시험이 부하로 실패하는 **가짜 검출**이 있었다. 모든 최종 killer 를 검토하고 의심 건은 개별 실행으로 재확인했지만, 개별 확인하지 않은 나머지 killer 는 이름이 변이 내용과 일치함을 눈으로 확인한 것이다.
- `git` 금지로 "이전 커밋 추출 후 같은 시험 실행" 방식의 수정 전 FAIL 증명은 하지 못했다(변이 되돌림으로 대체).
- 실서버는 PostgreSQL 16·Python 3.13 임시 환경이며 운영 이미지(PG 17, Python 3.12, nginx)와 다르다.
- 스크린리더·Edge·실기기·Windows Docker Desktop 은 환경이 없어 PASS 로 세지 않았다.
