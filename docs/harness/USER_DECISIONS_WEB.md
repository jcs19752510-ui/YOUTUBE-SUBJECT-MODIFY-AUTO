- 목적: 여러 문서에 흩어진 "사용자만 정할 수 있는 것"을 한 장에 모았습니다. **한 번에 답하면 같은 대화를 두 번 하지 않습니다.**

> 지금 당장 개발이 멈춰 있는 것은 아닙니다. 나머지 60개는 "그 단계에 가기 전에" 필요하며, 지금 안 정해도 M1 화면 확인에는 영향이 없습니다. 다만 한 번에 정해 두면 이후 질문이 줄어듭니다.

**"모두 추천안대로"라고 답하면 이렇게 진행됩니다.**
1. 에이전트가 각 항목의 추천안을 "사용자 응답"으로 결정 로그(`docs/harness/decisions.md`)에 DEC 번호로 기록하고, 아래 "반영할 문서" 목록의 문서를 고칩니다. 근거가 필요하면 이 문서의 출처 칸으로 되짚을 수 있습니다.
2. `[보수적 제안 — 문서에 권고 없음]` 표시 항목은 문서의 권고가 아니라 에이전트가 안전한 쪽으로 고른 값입니다. "추천대로"라고 하시면 그 값이 채택되지만, 결정 로그에 "에이전트 제안을 사용자가 수용"으로 구분 기록하고 언제든 바꿀 수 있게(규칙 F) 둡니다.
3. **"추천대로"로 답할 수 없는 것**: Q-1~Q-4와 ⑤(Q-51~Q-55)는 사용자 PC에서 실제로 해 보고 결과를 알려 주셔야 합니다(부록 A 절차서). Q-20(M2 착수)과 Q-33(M3 착수·첫 실제 반영)은 **승인 자체**라서 일괄 "추천대로"에 포함되지 않습니다 — 각각 따로 "승인"이라고 답하셔야 합니다(규칙 E, DEC-037).
4. ⑥ 위험 수용에서 "추천대로"는 "수용"을 뜻합니다. 단 위험도 **High/Critical 위협은 사용자가 수용할 수 없어서**(threat_model.md W6) 이 질문서에 수용 항목으로 넣지 않았고, 고치거나 M3 전까지 해결해야 하는 것으로 아래에 따로 적었습니다.
5. 추천안이 "나중에 다시 묻기(재평가)"인 항목(Q-29, Q-31 등)은 지금은 현행 유지로 확정하고, 해당 단계 설계 때 에이전트가 다시 묻습니다.

## 부록 A. 사용자 PC 조작 절차서

> 모든 명령은 Windows **PowerShell** 에서 실행합니다. 저장소 폴더 예시는 `C:\big21\vibe-coding\YOUTUBE-SUBJECT-MODIFY-AUTO` 입니다(다르면 실제 위치로). **비밀번호·토큰·`client_secret` 파일 내용은 채팅이나 저장소에 붙여 넣지 마세요.** 막히면 오류 문구만 그대로 알려 주세요. 화면 문구는 Windows·Docker 버전마다 다를 수 있어 `[확인 필요]`입니다.

### A-1. Q-1~Q-4: Docker Desktop과 첫 시작
1. 시작 메뉴 → Docker Desktop 실행 → 고래 아이콘이 멈추고 "Engine running" 비슷한 상태가 될 때까지 1~2분 대기. 아이콘 오른쪽 클릭 메뉴에 "Switch to Windows containers..." 가 보이면 정상(지금 Linux 모드), "Switch to Linux containers..." 가 보이면 눌러서 바꿉니다.
2. WSL2 확인: PowerShell에서 `wsl --status`. 오류가 나면 `wsl --update` 후 PC 재시작.
3. PowerShell 버전 확인: `$PSVersionTable.PSVersion` (5.1이면 Windows 기본, 7이면 별도 설치).
4. 포트 확인(선택): `Get-NetTCPConnection -LocalPort 8080 -State Listen` — 결과가 나오면 다른 프로그램이 쓰는 중입니다.
5. 시작:
   ```powershell
   cd C:\big21\vibe-coding\YOUTUBE-SUBJECT-MODIFY-AUTO
   Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
   .\web\scripts\start.ps1 -OpenBrowser
   ```
   첫 실행은 5~15분. 끝나면 "준비 완료! 브라우저에서 열기: http://127.0.0.1:8080" 가 나옵니다.
6. 첫 화면 성공 기준: 위쪽에 노란 띠 "데모 모드 — 유튜브에 아무것도 전송되지 않습니다"와 "서버 연결됨" → 홈에서 [데모 영상 불러오기]를 눌러 영상 200개가 생기면 완료. 상태 점검: `.\web\scripts\status.ps1`(마지막 줄 "점검 결과: 문제 없음").
7. 알려 줄 것: Windows 버전, Docker Desktop 실행 여부, PowerShell 버전, 화면이 열렸는지, 오류 문구, Docker 라이선스 확인 결과(Q-4).
- 데이터 삭제 주의: `docker compose down -v`, `docker system prune --volumes`, Docker Desktop의 "Clean / Purge data"는 데이터를 영구 삭제하니 쓰지 마세요.

### A-2. Q-51: 8080이 내 PC에서만 열리는지
1. `.\web\scripts\status.ps1 -Detail` 실행 → `[위험]` 표시가 없고 "이 PC 의 포트 8080 리스너는 루프백뿐" 이 나와야 합니다.
2. 같은 와이파이의 휴대폰 브라우저에서 `http://<내 PC의 IP>:8080` 을 열어 봅니다. **열리지 않아야 정상**입니다. (내 PC IP는 PowerShell `ipconfig` 의 IPv4 주소)
3. 알려 줄 것: 1번 결과 문구, 2번에서 열렸는지 여부. 열리면 즉시 `stop.ps1`로 끄고 알려 주세요.

### A-3. Q-52: 쿠키·CSP 확인
1. 크롬 또는 Edge에서 `http://127.0.0.1:8080` 이 열린 상태에서 **F12** 키 → "콘솔(Console)" 탭에 "Content Security Policy" 오류 문구가 없는지 봅니다. 있으면 그 문구를 복사해 전달.
2. (선택) 같은 개발자 도구에서 "Application(애플리케이션)" 탭 → Cookies 에 `ytw_session` 이 있고 HttpOnly 표시가 있는지 `[확인 필요: 메뉴 이름은 브라우저 버전마다 다름]`. 화면이 정상 동작하면 쿠키는 동작하는 것입니다.

### A-4. Q-53: 백업·복원·재시작
1. `.\web\scripts\backup.ps1` → 백업 파일 생성 확인(`web\backups`).
2. `.\web\scripts\restore.ps1 -Latest` → 확인 문구 `복원합니다` 입력 → 성공하고 행 수가 일치하는지 확인.
3. `.\web\scripts\stop.ps1` 후 `.\web\scripts\start.ps1` 해도 데이터가 남아 있는지, PC 재부팅 후에도 Docker Desktop 실행 + `start.ps1` 로 복구되는지 확인.
4. (개발 담당용, 선택) `docker compose -f web/compose.yaml exec api ls -l /run/secrets` 결과 전달.
5. `web\secrets` 폴더는 지우거나 남에게 보내지 마세요.

### A-5. Q-54: 구글 클라우드 OAuth 클라이언트(웹 유형)
`03_manual_setup.md` 2~5장이 기준입니다(그 문서는 CLI 때 만든 "데스크톱 앱" 기준이라, 웹 전환 후에는 5장의 유형만 아래처럼 바뀝니다. 화면 이름은 구글 정책 변경으로 달라질 수 있어 `[확인 필요]`).
1. 구글 클라우드 콘솔에 채널 소유 계정으로 로그인 → 프로젝트 생성(이름 예: `senior-title-helper`, "YouTube" 단어는 앱 이름에서 제외 권장).
2. "API 및 서비스 → 라이브러리"에서 **YouTube Data API v3**, **YouTube Analytics API** 사용 설정.
3. "OAuth 동의 화면"(또는 Google Auth Platform): 사용자 유형 **외부**, 앱 이름 입력, **테스트 사용자에 본인 구글 계정 추가**, 게시 상태 **테스트**(Q-21 추천). 데이터 액세스(범위)는 **읽기 2개만** 등록: `.../auth/youtube.readonly`, `.../auth/yt-analytics.readonly`. 쓰기 범위는 지금 추가하지 않습니다(M3 직전에 에이전트가 안내).
4. "사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID" → 애플리케이션 유형 **웹 애플리케이션**. 이름 예: `senior-title-helper-web`.
5. "승인된 리디렉션 URI" 칸에 `http://127.0.0.1:8080` 으로 시작하는 주소가 **입력·저장되는지**만 확인합니다(정확한 콜백 경로는 M2 설계 확정 후 에이전트가 알려 드립니다. 저장이 거부되면 거부 문구를 알려 주세요 → `localhost` → 데스크톱 유형 순으로 대안).
6. (참고) 콘솔의 "할당량" 화면에서 YouTube Data API의 하루 할당량 수치를 확인해 알려 주시면 문서의 `[확인 필요]`(기본 10,000단위 가정)를 해소합니다.
7. 받은 JSON(`client_secret`)은 PC에만 보관하고 **저장소·채팅에 올리지 마세요**(`.gitignore` 처리된 `secrets` 폴더, 저장 위치는 M2 때 안내). 알려 줄 것: 유형 생성 가능 여부, 리디렉션 주소 저장 가능 여부.

### A-6. Q-55: Studio CSV 샘플
YouTube Studio의 분석(Analytics) 화면에서 영상별 지표를 내보낸 CSV 1개를 준비합니다. 정확한 메뉴 이름은 문서에 없어 `[확인 필요]`이며 필요한 열은 에이전트가 M2 전에 안내합니다. 개인정보가 있으면 가리고 보냅니다.
