# 내부 검증 로그 — 3·4단계 산출물

대상: `docs/yt/DESIGN.md`(설계서), `docs/yt/threat_model.md`(위협 모델), `docs/yt/04_ux_design.md`(UX 설계서), `docs/harness/traceability.md`(스크립트 생성)
적용 Tier: Standard (최소 2회, 결함 0건까지) / 버전: v0 → v1 → v2 → v3 → v4(최종)
도구: `scratchpad/gen_trace2.py` — 4개 문서와 `decisions.md`를 파싱해 ID 정의·참조·매핑·수치 일치를 점검하고 추적표를 생성한다.

## 1차 검증 (작성자 관점)
- 방법: 작성 직후 UX 7장의 설계서 정합성 체크 + 스크립트 + 위협 모델의 SEC 커버리지 점검
- 발견된 결함 (5건)
  1. 위협 모델 작성 중: **하루 적용 건수 상한이 없어** 실수·스크립트 반복으로 여러 영상이 한꺼번에 바뀔 수 있음 → SEC-020 신규, 설정 `max_live_changes_per_day` 추가
  2. UX 정합성: 공통 출력 모듈 `ui.py`가 WU-0 소유 파일에 없음
  3. UX 정합성: 전역 옵션 `--plain`/`--color`가 설계서에 없음
  4. 03 가이드의 `.env` 예시가 설계(설정 계층, 토큰 저장 위치)와 불일치
  5. 스크립트: SEC-004(교체 제한)를 다루는 위협이 없음 → T-16에 연결
- 조치: 5건 수정 → v1 (DEC-023 기록)

## 2차 검증 (독립 심사자 관점 — "이 설계서로 구현할 개발자")
- 방법: DESIGN.md를 처음부터 끝까지 다시 읽음
- 발견된 결함 (11건)
  1. DEC 범위(013~022)가 023까지로 늘었고, "12장"이 승인 요청 절(13장)을 잘못 가리킴
  2. 구성도의 공통 기반 목록에 `ui` 누락
  3. 상태 머신 그림(`filtered → blocked`)이 본문(검증 시점에 승격)과 모순
  4. `plan`이 `title_changes`에 쓰는지 모호(`apply`에서도 `planned` 행을 만들어 중복)
  5. **설계 공백**: `plan`이 기준으로 삼는 snippet과 `plan_hash` 계산 방법, 승인 이후 영상이 바뀐 경우의 처리가 없음
  6. 게이트 순서가 "값싼 로컬 검사 → 네트워크" 원칙에 맞지 않음
  7. 게이트 순서를 바꾼 뒤 6장의 단계 번호 참조(SEC-001/002/009)가 어긋남
  8. SEC-019/020 표 순서 어긋남(경미)
  9. 중단 기준에 "쿼터 80% 초과"가 있어 NFR-003(80% 경고, 100% 중단)과 모순
  10. 승인 파일 유효 시간(24시간)과 Shorts 판별 기준이 설정 파일에 없음
  11. **WU-0 완료 기준이 "`--help`에 서브커맨드 9개 표시"인데 WU-0은 `purge`만 소유** — 그 시점에 충족 불가
- 조치: 11건 수정 → v2. 5-2 게이트 14단계를 재배열하고 `plan_hash` 정의를 추가했다.

## 3차 검증
- 방법: 스크립트 재실행 + UX/위협 모델 상호 참조 점검
- 발견된 결함 (1건)
  1. SCR-010(데이터 정리 화면)을 사용하는 사용자 흐름이 없음 → UX-009 추가
- 오탐 2건(결함 아님): ①`EVT-001` 안의 `T-001` 문자열을 위협 ID로 오인한 검사 ②굵은 글씨 `**상**`을 못 읽은 위험도 집계(실제 상 3·중 11·하 2)
- 조치: 흐름 UX-009 추가 → v3

## 4차 검증 (결함 0건 확인)
- 스크립트 결과: ID 정의 FR 20·NFR 11·POL 4·SEC 20·EVT 19·UX 9·SCR 10·ADR 10·RISK 17, 본문이 참조하는 미정의 ID 0, PRD 요구 중 설계 매핑 없는 것 0, 작업단위 미배정 0, 위협 모델의 SEC 참조 미정의 0, 명령 9개의 소유 단위 확인, UX가 참조한 EVT 미정의 0, ADR→DEC 상호 참조 0 누락, 설정 수치(72h/3회/1,000회/6,000) PRD와 일치, 게이트가 참조한 SEC 미정의 0 — **ALL OK**
- 발견된 결함: 0건

## 최종 판정
- [x] **PASS** (결함 0건, 4회 검증: 5 → 11 → 1 → 0). 설계서·위협 모델·UX 설계서 모두 해당.

## 한계 (정직한 기록)
- 같은 모델이 역할만 바꿔 검증했다. 특히 보안 설계는 실제 보안 담당자의 검토가 필요하다.
- **Windows 고유 동작은 이 환경에서 검증할 수 없다**(DESIGN §8-2). 구현 후에도 "미수행(Windows 필요)"로 남는 항목이 있다.
- 설계서는 아직 코드로 구현되지 않았으므로 구현 가능성은 5단계에서 실증된다.
