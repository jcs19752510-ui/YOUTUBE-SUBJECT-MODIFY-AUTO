## 1차 검증 — 작성자 관점 자가 재검토
- 방법: 노트 AC 6건·D-01~D-14 를 시험에 1:1 연결, 설계 의도에서 기대값 도출(구현자 시험 미복사), 정적 → 일회용 컨테이너 → 실가동 스택 순으로 실행해 기대·실제 비교
- 발견된 결함/문제:
  1. **시험 자신의 오류 12건**(내 잘못된 기대): 디렉터리 설정(`YTWEB_SECRETS_DIR`)을 비밀로 오판, nginx 잘못된 Host 의 400 을 444 로 기대, 속도 제한 시험이 앞선 시험의 burst 를 소비, bool 컬럼 문자열 형식, 세션 시간대 기대, 바인드 경로 `/home` 접두사 금지, 무효 GRANT/REVOKE 를 오류로 기대, `pg_terminate_backend` 오용, trace 모드 종료코드·인자 따옴표, 중복 프로브 해시, 헬스 대기 누락, 노트의 api "exit 0" 가정 → 모두 시험을 고쳐 해결(제품 결함 아님)
  2. **제품 결함 후보 발견**: web 의 egress·db 도달(DEF-VI-001), `alembic_version` 쓰기 가능(DEF-VI-002), 오류 로그의 쿼리 문자열(DEF-VI-003), nginx 시작 경고(DEF-VI-004)
- 조치: DEF-VI-004 는 소유 파일 안에서 1줄 수정(동작 불변) + 회귀 시험·변이 + 이미지 재빌드 후 경고 소멸 실측. DEF-VI-001~003 은 설계 변경·사용자 결정·타 단위 소유라 고치지 않고 xfail(strict) 시험으로 고정하여 보고 → v1

## 2차 검증 — 독립 심사자 관점 재검토(변이 점검 + 보안 읽기)
- 방법: 안전 로직 113곳을 격리 사본에서 일부러 망가뜨려 시험이 실패하는지 확인(노트 자체 변이 9건과 방식이 다른 100여 곳). 회전: 1회전 106곳 유효 중 **4곳 생존**(M26 로그 크기 상한, M97 복원 전 목차 검사, M105 SHA 비교 반전, M109 Windows 컨테이너 모드 검사 반전) → 시험 보강 → 2회전 110/110 → 3회전 110/110 → 최종 회전 113곳 중 112곳(생존 1 = 주석 추가 대조군). 별도로 정적 단계를 건너뛰고 **행동 시험(실제 컨테이너)만으로** 돌린 회전에서 11곳이 생존해(CSP 지시자 정확성, 소켓 인증, PUBLIC 권한 열림, 경로 탈출, 느린 본문, 접두사 Host, 쿼리 로그) 시험 8건을 보강, 최종 5곳 남음 = 동치 2(M60, M66)·재현 불가 1(M76)·런타임 무효 1(M113)·대조군 1(M114)
- 의심한 점과 확인: (a) 변이 회전 사이에 한 번 "M63/M64 가 047 로 잡힘"으로 보인 것은 시험의 타이밍 흔들림(false kill)이 의심돼 047 을 4회 반복 실행해 안정(4/4)함을 확인하고 변이별 첫 실패 시험을 사람이 대조 (b) 코드 읽기 점검: 입력 검증(백업 파일명 이중 정규식, 서비스명 ValidateSet, Prefix 패턴), 비밀 비노출(화면·로그·이미지·inspect 바이트 검색), SQL 바인딩(psql 변수 `:'pw'`), 실패 시 안전(약한 비밀번호 초기화 실패, 마이그레이션 실패 시 up 실패, 비밀 없고 볼륨 있으면 start 거부, 잘린 덤프 복원 롤백), 멱등성(재실행 시 비밀 덮어쓰지 않음)
- 발견된 결함: 위 변이 생존 4+11건은 모두 **시험의 구멍**이었고 보강으로 해소. 제품 결함은 1차의 4건 외 신규 없음
- 조치: 시험 보강(결과서 부록 A)

## 3차 검증 — 결함 0건 확인 대신 "남은 것 확인"
- 방법: 소스 확정 후 전체 재실행. 최종 공식 연속 실행 `204 passed, 1 skipped, 3 xfailed`(208항목) — 건너뜀은 TC-VI-136(Docker Hub 조회 의존) 하나이며 단독 재실행 `1 passed`. 구현자 시험 `test_compose_security.py` 36 passed. 정적 검사: pyflakes(시험 파일), hadolint(Dockerfile 3), shellcheck -S style(셸 2), yamllint(compose 2), `bash -n`, pwsh 파서(9개 ps1 오류 0) 전부 무결함

## 한계 (정직한 기록)
- 같은 모델이 작성자·심사자 역할을 번갈아 수행했다. 변이 점검과 실제 컨테이너 시험으로 실효성을 보강했지만 독립된 사람의 검토는 아니다.
- Linux 엔진·pwsh 7 실측만 했다. Windows Docker Desktop·PowerShell 5.1·Windows ACL·브라우저 CSP 는 **미수행**이며 PASS 로 세지 않았다.
- 빌드는 프록시 CA 를 주입한 Dockerfile 사본으로 했다(저장소 Dockerfile 직접 빌드는 이 클라우드의 TLS 제약으로 불가). 지시문은 CA 두 줄을 제외하고 동일.
- PowerShell 줄 커버리지는 `Set-PSDebug` 추적 기반 근사치다. `01-roles.sh` 는 줄 추적 없이 분기 열거로 대체.
- TC-VI-136 은 외부 레지스트리에 의존해 연속 실행에서 건너뛸 수 있다.
