## 원인 (로그 근거)
수정 전 서버 로그 101회: `sqlalchemy.exc.TimeoutError: QueuePool limit of size 5 overflow 5 reached, connection timed out, timeout 30.00` (`GET /api/v1/videos` 등 → HTTP 500, "unhandled error"). 코드: db/session.py 풀 5+5=10, anyio 스레드풀 기본 40 스레드. 운영 compose 의 DB max_connections=50.
**주의: 이 시험에서 500 이 재현된 지점은 동시 50 이 아니라 동시 100(영상 목록 연타) 이었다.** 동시 50 은 실서버(uvicorn)에서 오류 0 이다. 직전 C 구획의 동시 50 오류는 ASGI 인-프로세스 전송(스레드·이벤트 루프 공유) 조건이라 서버 설정 문제만으로 보기 어렵다.
"왜 풀 대기가 30초까지 가는가"의 메커니즘(연결을 쥔 요청이 guard.py 의 응답 전 commit 용 스레드를 못 얻는 스레드풀 교착)은 **가설이며 확정하지 못했다**: 수정 후에도 같은 QueuePool 오류가 나므로 가설만으로는 설명이 안 된다. 확정된 것은 "풀 고갈 → 30초 대기 → 500" 까지다.
