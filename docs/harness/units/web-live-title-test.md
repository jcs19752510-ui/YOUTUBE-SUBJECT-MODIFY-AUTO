## 2. 테스트 범위 및 제외 범위

**범위**: ①실제(youtube) 영상 제안 생성 경로(모의/규칙 기반/Gemini 선택, 길이, 반복 요청) ②Gemini 어댑터(요청 구성·응답 해석·오류·키 비노출) ③영상 불러오기 갱신 규칙 ④반영 후 검증(`verify_snippet`)과 실패 항목 표시 ⑤제안 점수 표시·정렬 ⑥검증기 권장 길이 40→60자 영향.

**제외(미수행과 사유)**
- 선생님 PC(Windows·Docker)에서의 수정본 실행: 제 환경에서 접근 불가.
- 실제 유튜브 `videos.update` 호출: 선생님 승인 없이는 하지 않으며 이 환경에서 불가. 반영 후 검증 실패의 **실제 원인 항목은 미확인**(수정은 흔한 원인을 막고, 못 막으면 항목 이름이 화면에 나오게 했다).
- 이미지 취약점 스캔, 부하 시험, 브라우저 화면 캡처 자동 시험(이번 변경은 화면 문구·정렬 위주이며 프런트 단위 시험으로만 확인).
- 변이 점검 중 `verify_snippet` 정규화 로직(`_canon`, `_same_field`, `describe_verify`)에 대한 변이 점검: **미수행**(시간 상한). 대신 경계 시험 8개를 직접 작성했다(4절).

## 7. 테스트 환경 정리(Teardown) 확인 — 규칙 K
- 임시 PostgreSQL(`.harness-tmp/pgx`) 중지·삭제, 가상환경(`.harness-tmp/be`, `.harness-tmp/pt`), 격리 사본(`.harness-tmp/qa1`), `web/frontend/node_modules`, 임시 시험 결과(`/tmp/g`, `/tmp/h`) 삭제. 마지막 실행의 가상환경은 이 결과서 커밋 직후 삭제(삭제함).
- 저장소에 비밀·키·`data/`·`.harness-tmp/` 는 올리지 않았다. `web/secrets/` 와 `google_client*.json`, `client_secret*.json` 은 `.gitignore` 로 제외.
- 실제 구글 키로 한 시험은 없다(제 환경은 프록시가 키를 주입하며 키 값은 저에게 보이지 않는다).

## 8. 리스크 및 잔존 이슈
1. **반영 후 검증 실패의 실제 원인 미확인(DEF-LIVE-004)**: 수정이 원인을 못 막으면 다음 실제 변경에서도 "실패"가 나온다. 이제 화면에 항목이 나오므로 한 번 더 시도하면 확정된다.
2. DEF-LIVE-005 는 조치했으나 선생님 PC 에서의 동작은 미확인(`live_off` 안내 문구 확인 필요).
3. Gemini 모델 이름 `gemini-flash-latest` 는 별칭이라 구글이 가리키는 모델이 바뀔 수 있다(`YTWEB_GEMINI_MODEL` 로 고정 가능). 제안 제목은 법률·광고 규정 검토가 아니다.
4. A/B 테스트 중인지 프로그램은 알 수 없다(API 에 없음). 선생님이 Studio 에서 확인해야 한다.
