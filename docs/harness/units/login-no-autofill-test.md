## 1. 개요
| 항목 | 내용 |
|---|---|
| 요청 | 선생님: "로그인 화면의 아이디·비밀번호가 새로고침해도 계속 기록(표시)되어 있다. 새로고침·로그아웃 시 화면에 보이지 않게, 쿠키에 저장되어 있어도 무조건 입력하게. 보안상 심각" (캡처: 아이디 `jcs…` 5글자와 비밀번호 점 10개가 채워져 있고 안내문은 "아이디를 입력해 주세요.") |
| 원인(코드로 확인) | 앱은 입력값을 쿠키·localStorage·sessionStorage 어디에도 저장하지 않는다(소스 검색 0건, 값은 React 상태에만 존재). 캡처의 안내문이 "아이디를 입력해 주세요."인 것은 앱 상태는 비어 있고 **브라우저(Chrome 비밀번호 관리자)가 화면에만 채운 것**이라는 증거다. 기존 코드가 `autocomplete="username"`/`"current-password"`로 브라우저에 자동 채움을 **요청**하고 있었다 |
| 판정 | **조건부 합격** — 코드·헤드리스 Chromium 시험은 통과, **실제 Chrome 비밀번호 관리자에서의 효과는 선생님 PC에서만 확인 가능**(9절) |

## 2. 범위 및 제외
**범위**: `web/frontend/src/app/LoginForm.tsx` 의 입력칸 속성과 비움 동작, 시험.
**제외(미수행과 사유)**: ①실제 Chrome 비밀번호 관리자(헤드리스에는 없음) ②선생님 PC에 이미 저장된 비밀번호 삭제(제가 닿을 수 없음, 따라 하기 가이드로 안내) ③실제 한글 IME·모바일·스크린리더 낭독 ④실제 백엔드 연동(가짜 응답 사용) ⑤"새로고침하면 로그인이 풀리게" 하는 세션 방식 변경(요청 문구가 모호해 **하지 않음**, 선생님께 확인 질문). 말하지 않은 기능(2단계 인증 등)은 만들지 않았다.

## 3. 환경
Linux 컨테이너, Node 22, Chromium 1194(playwright-core, 헤드리스), vitest 5.0.3(jsdom), 임시 가상환경(인프라·보안 정적 시험).

## 4. 수정 내용
1. `<form autocomplete="off">`, 아이디 `autocomplete="off"`·name `admin-login-id`, 비밀번호 `autocomplete="new-password"`·name `admin-login-secret`(흔한 이름 username/password 제거).
2. 사용자가 칸을 누르기(포커스·포인터) 전에는 `readOnly`(브라우저 자동 채움은 읽기 전용 칸을 채우지 못한다).
3. 화면이 열릴 때 화면 값을 비우고, **처음 30초 동안 0.4초마다**(사람이 입력하기 전이면) 칸을 다시 비운다. 사람의 입력은 `keydown`·`paste`·`beforeinput`·`compositionstart`로 판별(브라우저 자동 채움은 이 이벤트가 없다).
4. 뒤로 가기·앞으로 가기로 이전 화면이 복원될 때(`pageshow` persisted) 비우고 읽기 전용으로 되돌린다. 로그아웃 뒤 로그인 화면은 새로 그려져 비어 있다.

## 5. 테스트 케이스 및 결과
### 5-1. 단위(vitest, jsdom) — `loginForm.noautofill.test.tsx` 9개 + `adminLogin.test.tsx`
- **수정 전 코드로 새 시험을 돌린 첫 실행(보존): 7개 중 4개 실패, 3개 통과** — 실패: 자동 채움 속성, 읽기 전용, 브라우저가 몰래 채운 값 비우기, 뒤로 가기 복원. 통과(원래도 안전했던 것): 사람 입력 유지, 로그아웃 뒤 새 화면 비어 있음, 값이 쿠키·저장소·URL에 남지 않음.
- 수정 후 7개 통과, **보강 후 9개 통과**(음성·가상 키보드·한글 조합 입력 보존, 20초 뒤 늦은 채움 비우기 추가). 두 파일 합계 31 통과.
- **기존 시험 1곳의 기대값을 바꿨다**: `adminLogin.test.tsx` "접근성: …autocomplete…" 가 `autocomplete=username`, `name=username`, `autocomplete=current-password`를 기대했다. 선생님 보안 지시(저장된 값을 채우지 않는다)가 이 속성 자체를 바꾸므로 기대값을 `off`·`admin-login-id`·`new-password`로 갱신했고 원래 값은 위에 보존한다. 접근성 쟁점: 웹 접근성 지침은 로그인 칸에 autocomplete 표기를 권장하지만 선생님 지시가 우선이며 axe 위반은 0건이다.

## 8. 리스크
1. 실제 Chrome 에서 효과가 부족하면 선생님 PC에서 **저장된 비밀번호 삭제와 저장 제안 끄기**가 필요하다(웹이 못 하는 영역).
2. 읽기 전용→해제 방식은 일부 스크린리더가 "읽기 전용"으로 읽을 수 있다(코드 검토, 실제 낭독 미확인).
3. 처음 30초 동안 사람이 입력하지 않으면 값을 계속 비우므로, 칸에 값을 두고 기다리는 사용은 불가능하다(요청 의도와 같음).

## 9. 결론
브라우저가 저장된 아이디·비밀번호를 칸에 채우는 경로(속성으로 요청, 읽기 전용 없이 채움, 화면 복원, 로그아웃 뒤 재표시)를 코드·헤드리스 Chromium에서 차단했다. 앱은 입력값을 저장하지 않으며 이를 시험으로 확인했다. **실제 Chrome 비밀번호 관리자에서의 동작은 확인하지 못했다.** 선생님 PC에서 아래 순서로 확인한다.
