# unit-1 구현 노트 — WU-1 OAuth 인증 (5단계)

- 작업 단위: **WU-1** (feature F-A 인증·조회) / **속도 트랙: L5** / Tier: Standard / 선행: WU-0(완료)
- 실행: 단독 실행. 파일 범위: `src/ytitle/auth.py`, `src/ytitle/commands/auth.py`, `tests/test_auth.py` (범위 밖 수정 없음, 의존성은 WU-0이 선언)

## 1. 구현 범위
설치형 앱 OAuth 로그인(읽기/쓰기 분리), 토큰 로컬 저장(사용자 프로필 폴더, 권한 제한 시도), 만료 시 갱신과 재로그인 안내, 로컬 토큰 삭제(`--revoke`), 로그인 상태 표시(토큰 값은 읽지 않음).

## 2. 설계서 대비 편차
| # | 편차 | 사유 |
|---|---|---|
| 1 | `auth`를 옵션 없이 실행하면 로그인 상태를 보여 준다 | UX-001/UX-008(초보자가 현재 상태를 확인). 설계의 `--read/--write/--revoke`는 그대로. |
| 2 | `auth --write`는 '쓰기권한'을 직접 입력해야 진행 | SEC-015·SEC-001 정신(쓰기 권한은 의식적으로). |
| 3 | 읽기 범위 = `youtube.readonly` + `yt-analytics.readonly`, 쓰기 범위 = `youtube.force-ssl` | 03 가이드 4-2와 동일. **쓰기 범위가 `videos.update`에 충분한 최소 범위인지는 원문 미확인 → 12단계 전 확정 [확인 필요, DEC-016]**. 상수 한 곳(`WRITE_SCOPES`)만 바꾸면 됨. |
| 4 | `--revoke`는 로컬 삭제와 구글 계정 설정 안내만 수행(구글 서버에 철회 요청은 보내지 않음) | 네트워크 호출을 이 단위에 넣지 않기 위해. 설계의 "계정 회수 절차"는 안내로 충족. |

## 3. 인수 조건 (AC)
| AC | 인수 조건 | 연결 요구 |
|---|---|---|
| AC-01 | `auth --read`가 읽기 범위로 로그인하고 읽기 토큰 파일만 저장한다 | FR-016, SEC-015 |
| AC-02 | `auth --write`는 쓰기 범위로 별도 파일에 저장하고 읽기 토큰을 건드리지 않으며, 직접 입력 확인 없이는 진행하지 않는다 | SEC-015, SEC-001 |
| AC-03 | 토큰 파일은 프로젝트 밖(사용자 프로필)에 저장되고 권한이 제한되며 임시 파일이 남지 않는다 | SEC-008, ADR-004 |
| AC-04 | 사용자가 권한을 일부만 허용하면 저장하지 않고 안내한다. 클라이언트 비밀 파일이 없으면 03 가이드를 안내한다 | FR-016, NFR-007 |
| AC-05 | 토큰 읽기: 유효하면 사용, 없으면 다음 명령 안내(읽기/쓰기 구분), 손상·범위 부족은 재로그인 안내 | FR-016, NFR-007 |
| AC-06 | 만료 토큰은 갱신해 다시 저장하고, 갱신 실패(7일 만료·철회)는 재로그인 안내(RISK-012) | FR-016 |
| AC-07 | 로그인·갱신 실패 메시지, 화면, 로그 어디에도 토큰·키 값이 나오지 않는다 | SEC-008 |
| AC-08 | 읽기 토큰을 읽을 때 쓰기 토큰 파일은 열지 않는다. `--revoke`는 둘 다 지우고 반복 실행해도 안전하다 | SEC-015 |
| AC-09 | 옵션 없이 실행하면 상태만 보여 주고, 동시에 두 옵션을 주면 거부한다 | EVT-001 |

## 4. 수동 확인이 필요한 부분
- **실제 브라우저 로그인은 사용자가 수행**한다(03 가이드 8장). 이 환경에서는 모의 흐름 객체로만 검증했다. 실제 구글 서버와의 토큰 발급·갱신·7일 만료 동작은 미검증.
- Windows `icacls` 권한 제한은 WU-0 TC-054와 같은 이유로 미수행.
