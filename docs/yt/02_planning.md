# 02 기획서 (PRD) — 유튜브 제목 수정 자동화

- 입력: `docs/yt/01_policy_research.md`(CONDITIONAL PASS, 공식 원문 재확인 대기), v1 프롬프트, 저장소 스캔(하네스 파일만 있고 소스 코드 없음)
- 작성: 오케스트레이터(2단계 역할 직접 수행, DEC-011)
- 업무 유형: 신규 개발 / Tier: Standard / 병렬 P1 / 법규: 대한민국 + YouTube·Google 약관
- 규칙: 사용자에게 추가 요청을 하지 않고 완성한다. 결정 불가 항목은 11장의 질문으로 분리하되, 모두 보수적 기본값으로 진행한다.

## 1. 서비스/기능 개요 및 목적
**"시니어 생활팁" 유튜브 채널의 기존 영상 제목을 안전하게 개선하는 로컬 Python CLI 프로그램.** 채널 소유자(사용자)가 별도로 만든 제목 후보를 파일로 입력하면, 프로그램이 (1)시니어 시청자 특화 규칙으로 후보를 검증·차단하고, (2)사람 승인 후에만 `videos.update`로 제목만 바꾸며, (3)모든 변경을 기록하고 한 번에 롤백할 수 있게 하고, (4)변경 전후 성과 지표를 수집·비교한다.

**목적**: 계정 제재 위험을 최소화하면서 제목 개선 과정을 자동화하고 기록한다(v1 §3). 제목을 "더 자극적으로"가 아니라 **"더 정확하고 안전하게"** 만드는 것이 목적이다.

## 6. 제약 조건
- **예산**: 추가 비용 0원(개인 도구, 무료 API 쿼터 내 사용). **인력**: 사용자 1인 + AI 개발 보조. **일정**: 미정(Q-2-2, 11장). 기본값은 단위별 PASS 순서대로 진행.
- **환경**: Windows + PowerShell, Python 3.12+venv, SQLite(DEC-003).
- **외부 제약**: YouTube API 쿼터(기본 10,000 units/일, [확인 필요]), OAuth 정책(1단계 d).

## 8. 가정(Assumptions) 목록
스스로 판단해 채운 부분이다. 3단계 이후 담당자가 검증한다.
1. YT-00 질문 9개는 v1 기본값으로 진행(DEC-003).
2. `videos.update` 쿼터 비용 50 units, 조회 1 unit은 **가정**이며 설정값으로 둔다(1단계 c).
3. OAuth 운영 방식(Testing 7일 재인증 vs Production 전환)은 사용자 선택이며, 설계는 둘 다 동작하게 한다.
4. 영상당 변경 횟수 상한 3회, 최소 노출 1,000회, 로그 보관 365일, 성능 5초, 커버리지 90%는 **임의 기본값**이고 모두 설정값이다.
5. 공식 A/B 테스트는 API로 제어할 수 없다고 가정한다(근거 없음 ≠ 불가 증명).
6. 후보 제목은 사용자가 이 프로그램 밖에서 만든다. 후보 JSON의 `summary`는 사용자가 쓴다.
7. 대상은 사용자 소유 채널 1개이며 영상 수는 수십~수백 개 수준이다(규모 가정).
8. 1단계는 공식 원문 미열람(CONDITIONAL PASS)이므로 사실 항목이 바뀔 수 있다. 바뀌면 규칙 F로 재산정한다.
9. 규칙 I은 보수적으로 적용하고 법률 자문은 사용자 몫이다(DEC-012).
10. 후보 파일에는 영상 설명이 없을 수 있다. 이 경우 일치율은 `summary` 기반으로만 계산하며 정확도가 낮아질 수 있다(리포트에 표기).
11. 변경 전 지표 스냅샷이 없는 영상도 사용자가 확인하면 적용할 수 있지만, 이후 성과 비교의 신뢰도는 낮아진다.
