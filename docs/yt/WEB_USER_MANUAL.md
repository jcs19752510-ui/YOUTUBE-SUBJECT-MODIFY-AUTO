## 1. 이 프로그램은 무엇인가요?

영상 제목을 더 알기 쉽게 고치도록 **AI가 제목 후보를 제안**하고, **선생님이 직접 보고 승인한 것만** 모아서 한 번에 바꾸는(일괄 반영) 도우미 프로그램입니다. 사람이 승인하지 않으면 아무것도 바뀌지 않습니다.

쉬운 말 풀이

| 낯선 말 | 뜻 |
|---|---|
| 데모 모드 | 가짜 영상·가짜 AI로 연습만 하는 상태. 바깥(유튜브·AI)으로 아무것도 안 나갑니다 |
| 제안 | AI가 만든 새 제목 후보 하나 |
| 검증 | 프로그램이 제안을 점검해 **통과 / 경고 / 차단**으로 판정하는 것 |
| 엄격 모드 | 건강·금융처럼 민감한 주제는 "경고"도 "차단"으로 취급하는 안전 규칙 |
| 승인 | "이 제목으로 바꿔도 좋다"고 선생님이 허락하는 것. 24시간 안에, 한 번만 쓸 수 있습니다 |
| 배치(일괄 반영) | 승인한 제안을 한 묶음으로 모아 한꺼번에 바꾸는 작업 |
| 사전 점검(미리보기) | 묶음을 실행하기 전에 "이렇게 바뀔 예정입니다"를 보여 주는 단계. 이 단계에서는 **아무것도 바뀌지 않습니다** |
| 롤백 | 바뀐 제목을 이전 제목으로 되돌리는 것 |
| 쿼터(API 사용량) | 구글이 하루에 허락하는 사용 한도. 화면에는 "남은 API 사용량"으로 나옵니다 |
| PIN | 숫자 4~12자리 비밀번호. 선택 사항이며 처음에는 꺼져 있습니다 |

사용 환경: **이 PC에서만** 열립니다(주소 `http://127.0.0.1:8080`). 최신 Chrome 또는 Edge, 화면 폭 1024px 이상, 마우스와 키보드 사용을 기준으로 만들어졌습니다(설계 목표이며 선생님 PC에서 확인되지 않았습니다). 휴대폰·태블릿은 지원하지 않습니다.

## 2. 하지 말아야 할 일 (실수 방지)

1. **PowerShell에서 `docker compose down -v` 를 직접 치지 마세요.** 저장된 모든 데이터가 영구 삭제됩니다. (`stop.ps1` 로 끄는 것은 안전합니다.)
2. Docker Desktop에서 "Clean / Purge data"를 누르거나 `docker system prune --volumes` 를 실행하지 마세요. 같은 이유로 데이터가 지워집니다.
3. `web\secrets` 폴더를 지우거나 다른 곳에 올리지 마세요. 프로그램 내부 비밀번호가 들어 있습니다. (이 폴더를 지우면 저장된 데이터에 접속하지 못할 수 있습니다.)
4. `web\backups` 폴더(백업 파일)를 다른 사람에게 주지 마세요. 암호화되어 있지 않습니다.
5. 같은 와이파이의 다른 기기나 인터넷에서 열려고 하지 마세요. 설계상 이 PC에서만 열립니다.
6. 경고(▲) 사유를 읽지 않고 체크만 하지 마세요. 사유를 읽고 제목이 사실과 맞는지 직접 판단하세요.
7. **"데모에서 해 봤으니 실제도 같겠지" 하고 넘어가지 마세요.** 실제 연동이 생기면 그때 다시 이 문서를 확인하고, 처음에는 반드시 테스트 영상 1개로 시험해야 합니다.
8. **사전 점검(초안)을 만들었다면 실행하거나 [초안 버리기]로 정리하세요.** 초안에 담긴 제안은 그 초안이 남아 있는 동안 다른 배치에 쓸 수 없습니다(4-4 참고).

## 3. 시작하기 (처음 한 번만 따라 하세요)

설치는 `WEB_INSTALL.md` 를 먼저 끝내 주세요. 이미 설치되어 있다면:

1. **Docker Desktop을 실행**합니다. 작업 표시줄 고래 아이콘이 "실행 중"으로 바뀔 때까지 1~2분 기다립니다.
2. PowerShell을 열고 아래를 차례로 입력합니다. (폴더 위치는 `web/README.md` 의 예시 경로입니다. 선생님 PC에서 다르면 맞게 바꾸세요.)
   ```powershell
   cd C:\big21\vibe-coding\YOUTUBE-SUBJECT-MODIFY-AUTO
   Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
   .\web\scripts\start.ps1 -OpenBrowser
   ```
3. 처음에는 5~15분 걸릴 수 있습니다(이 시간은 문서 값이며 내 PC에서 측정되지 않았습니다). "준비 완료!" 글자와 주소가 나오면 브라우저가 열립니다.
4. 화면 위쪽에 **"데모 모드 — 유튜브에 아무것도 전송되지 않습니다"** 띠가 보이면 정상입니다. 이 띠는 상태에 따라 세 가지로 바뀝니다(4장 앞부분).
5. PIN을 설정해 둔 경우에는 "PIN 을 입력해 주세요" 화면이 먼저 나옵니다. PIN을 입력하고 [확인]을 누릅니다. PIN이 꺼져 있으면 이 화면 없이 바로 홈이 열립니다.
6. 연결은 **마지막으로 사용한 뒤 30분**이 지나면 만료됩니다(처음 연결로부터 최대 12시간). PIN이 꺼져 있으면 화면이 알아서 다시 연결하고, PIN이 켜져 있으면 "세션이 만료되었습니다" 창에서 PIN을 다시 입력하면 이어서 쓸 수 있습니다.

**첫 과업: 연습용 영상 200개 불러오기**
1. 왼쪽 메뉴 **홈**의 "오늘 할 일" 카드에 "아직 영상이 없습니다. 데모 영상 200개를 불러와 시작하세요." 와 함께 **[데모 영상 불러오기]** 버튼이 있습니다. **이 버튼은 영상이 하나도 없을 때만 보입니다.** 영상이 생기면 홈에서 사라집니다.
2. 누르면 "데모 영상 불러오기를 시작했습니다." 안내와 진행 막대("N / M 처리됨")가 나옵니다. 끝나면 "영상 현황"의 "전체 영상"이 200, "제외된 영상"이 37이 됩니다 (클라우드 임시 서버에서 확인한 숫자).
3. 처음 상태로 되돌려 다시 불러오고 싶으면 `WEB_RUNBOOK.md` 6장(데이터 초기화)을 보세요.

### 4-1. 홈
오늘 할 일과 남은 사용량을 한눈에 봅니다.
- **오늘 할 일**: 상황에 맞게 한 줄씩 안내합니다. 예) "검토할 AI 제안이 N개 영상에 있습니다" → [검토하러 가기], "승인된 제안 N건을 배치로 묶어 반영할 수 있습니다" → [배치 만들기], "반영 대기 중인 항목이 N건 있습니다" → [진행 상황 보기]. 할 일이 없으면 "지금 처리할 일이 없습니다. 영상 목록에서 새 제안을 만들어 보세요."
- **오늘 반영 건수** `a / 상한건`: 하루에 바꿀 수 있는 최대 건수(기본 10건)와 오늘 바꾼 건수. 하루는 **한국 시간** 기준입니다.
- **남은 API 사용량**: "N 단위 남음", "사용 / 한도 단위 사용", "기준일 (태평양 시간)". 80% 이상 쓰면 노란 안내 "사용량이 80%를 넘었습니다. 오늘은 반영을 줄이는 것이 안전합니다." (기준일 옆에 "미국 태평양 시간 기준 — 한국 시간 오후 4~5시에 하루가 바뀝니다"라고 함께 안내됩니다. 프로그램 기본 하루 한도는 6,000단위입니다(설정 파일 값).)
- **반영 대기열**: "대기 N건"과 "다음 실행일", 없으면 "예약된 항목이 없습니다."
- **연결 상태**: 세 줄이 나옵니다. ① "구글 연결: 데모 모드(실제 유튜브와 연결되지 않음)" 또는 "구글 연결됨" ② "구글 연결 안 됨" 또는 "구글 연결됨" ③ "실제 반영(라이브): 꺼짐" 또는 "켜짐". ③은 실제 수정 3가지 조건이 모두 맞을 때만 "켜짐"입니다.
  - 구글 연결 파일만 넣고 아직 로그인하지 않았다면 ①줄은 "구글 연결 안 됨"으로 나옵니다(코드 확인). 화면 맨 위 띠도 실제 상태를 따라 바뀝니다 — 4장 첫머리.
- **구글(유튜브) 연결 카드**: 구글 로그인, 내 영상 불러오기, 제목 수정 권한 연결, 연결 해제 버튼이 있는 카드입니다(9장).
- **영상 현황**: 전체 영상 / 제외된 영상 / 제안 있음 / 승인됨 / 반영 대기 / 반영 완료. 이름을 누르면 그 조건의 영상 목록으로 갑니다. (영상 하나가 여러 제안을 가지면 영상마다 상태를 하나만 셉니다. 우선순위는 반영 대기 > 승인됨 > 반영 완료·되돌림 > 제안 있음 > 제안 없음입니다.)

### 4-2. 영상 목록
제목을 고칠 영상을 고르는 화면입니다.
1. 위쪽 검색칸("제목 또는 영상 ID 검색")에 글자를 쓰고 **[검색]** (또는 Enter)을 누릅니다. 글자만 쓰고 누르지 않으면 반영되지 않습니다.
2. "진행 상태"(제안 없음/제안 있음/승인됨/반영 대기/반영 완료/되돌림), "제외 여부"(전체/제외된 영상만/제외되지 않은 영상만)는 바꾸는 즉시 적용됩니다. 조건을 바꾸면 1쪽으로 돌아갑니다. 조건이 있으면 **[필터 초기화]** 가 나타납니다.
3. 표 머리글(제목·길이·조회수·최근 변경)을 누르면 정렬됩니다. 처음 누르면 오름차순이고, 같은 머리글을 다시 누르면 오름/내림차순이 바뀝니다.
4. 영상 앞 네모를 눌러 고릅니다. 머리글 네모는 "이 페이지 전체 선택"입니다. **쪽을 넘겨도 선택은 유지**됩니다. 단, 화면을 새로고침하면 선택은 사라집니다.
5. **제외** 표시가 있는 영상은 고를 수 없습니다. 제외 사유는 화면에 영상마다 이렇게 표시됩니다: "비공개 영상", "아동용 영상", "예약 라이브·프리미어 또는 라이브 중", "Shorts 가능성(180초 이하)". ("일부 공개" 영상은 제외 대상이 아닙니다.)
6. 하나라도 고르면 화면 아래에 "N개 선택됨" 줄이 생기고 **[선택 모두 해제]**, **[선택 영상 AI 제안 생성]** 이 나옵니다. **한 번에 최대 200개**까지입니다. 누르면 진행 창이 열리고 "N / M 처리됨"이 표시됩니다. 끝날 때까지는 [닫기]가 눌리지 않고 Esc로도 닫히지 않습니다.
7. 영상 제목을 누르면 **영상 상세**로 갑니다. 한 번에 보는 개수(25·50·100개)는 표 아래 "한 번에 보기"에서 바꿉니다.

### 4-3. 영상 상세 — AI 제안 만들기·확인·승인
1. 맨 위에 **현재 제목**과 공개 상태·길이·조회수·최근 변경·설명 앞부분이 나옵니다.
2. **변경 한도 상태** 카드: "지금 이 영상의 제목을 바꿀 수 있습니다." 또는 "지금은 이 영상의 제목을 바꿀 수 없습니다(한도 초과)." 와 사유, "다시 바꿀 수 있는 시각"이 나옵니다.
   - 같은 영상은 **직전 변경 후 72시간**이 지나야 다시 바꿀 수 있습니다.
   - 같은 영상은 **최대 3회**까지만 바꿀 수 있습니다. 3회에 도달하면 시간이 지나도 풀리지 않습니다. 이때 사유 문장은 "더 바꾸려면 설정 파일(config/settings.yaml)의 영상당 변경 횟수 상한을 늘려야 합니다"라는 쉬운 말로 안내하며(괄호 안에 설정 이름이 한 번 나옵니다), 이 화면에서는 바꿀 수 없는 설정이므로 신경 쓰지 않아도 됩니다.
   - **롤백(되돌리기)도 "변경 1회"로 세어지고 72시간 간격이 새로 시작됩니다.**
   - 하루 반영 상한에 걸리면 사유에 하루 상한 문장이 나옵니다. 그 문장에는 "태평양 시간 기준"이라고 적혀 있지만, 이 프로그램이 실제로 세는 하루는 **한국 시간** 하루입니다(문구 오류, 알려진 제한).
   - 데모에서는 "변경 후 노출수 1,000회 이상" 조건을 **적용하지 않습니다**(데모에는 변경 후 지표가 없기 때문). 그래서 데모에서 같은 영상을 다시 바꾸는 시연은 72시간이 지나야 가능합니다.
3. **[AI 제안 만들기]** 를 누르면 제안 카드가 생깁니다. 한 번에 만드는 개수는 설정의 "영상당 제안 개수"(기본 3, 1~5)입니다. 같은 제목은 새로 만들지 않고 기존 카드를 다시 보여 줍니다.
4. 제안 카드에서 확인할 것
   - **검증 배지**: ✓ 통과 / ▲ 경고 / ✕ 차단. 색만이 아니라 기호와 글자로도 표시됩니다.
   - **상태 배지**: 검토 대기 / 승인됨 / 반려됨 / 반영 대기 / 반영 완료 / 승인 만료 / 차단됨 / 되돌림. 그리고 "AI 제안", "주제: 생활·건강·금융 등". (제목을 직접 고쳐도 배지는 "AI 제안" 그대로입니다 — 고친 제안에 "직접 수정" 배지가 붙는 경우는 지금 만들어지지 않습니다. 알려진 제한)
   - **안내 문구**: 모든 제안 카드에 "AI가 생성한 제안입니다…"와 "AI 제안은 사실과 법령 적합성을 보장하지 않습니다. 건강·금융 내용은 표시·광고 관련 규정을 직접 확인하세요."가 보입니다. 제안 목록 위에는 "'통과'는 길이·금칙어·내용 일치 같은 형식 점검을 넘었다는 뜻일 뿐입니다."도 있습니다.
   - **변경 전/후 비교**: 지워진 글자는 취소선, 새로 생긴 글자는 밑줄입니다. "글자 수 a자 → b자 (+n)"도 표시됩니다.
   - **영상 내용 일치율**: "영상 내용 일치율 N%". 새 제목이 영상 설명과 얼마나 맞는지. 낮으면 영상과 상관없는 제목일 수 있습니다.
   - **검증 사유**: [차단 사유] / [경고] / [참고] 와 이유 문장.
   - **엄격 모드** 배지: 건강·금융 등 민감 주제라는 뜻입니다. 경고도 차단으로 처리됩니다. 이 카드에는 노란 상자로 "건강·금융 제목입니다. 병이 낫는다거나 원금·수익이 보장된다는 식으로 읽힐 수 있는 표현이 없는지 직접 읽고 확인하세요. '통과'는 법령에 맞는다는 뜻이 아닙니다." 안내가 함께 나옵니다.
   - 이 데모의 가짜 AI는 **일부러 문제 있는 제목(느낌표 남발, 너무 긴 제목, "완치"·"원금 보장" 같은 단정 표현, "무조건 100%", "큰일 납니다", 영상과 무관한 제목 등)을 섞어서** 냅니다. 검증 기능이 어떻게 막는지 보여 주기 위해서입니다.
5. 카드의 버튼 (상태에 따라 보이는 것이 다릅니다)
   - **[제목 수정]**: 새 제목(1~100자)을 직접 씁니다. 저장하면 **검증을 다시 하고, 이미 받은 승인은 무효**가 됩니다. "검토 대기·승인 만료·승인됨·차단됨" 카드에 보입니다.
   - **[승인]**: "검토 대기·승인 만료·차단됨" 카드에 보입니다(차단됨이면 눌리지 않습니다). 누르면 승인 창이 열리고 변경 전/후 비교, AI 안내와 면책 문구, 승인자 이름(필수, 40자까지) 입력칸이 나옵니다. 경고(▲)라면 사유가 보이고 "경고 사유를 모두 읽고 확인했습니다." 를 체크해야 승인됩니다. **엄격 모드에서 경고(▲)가 있으면 카드에 ✕ 차단으로 표시되고 [승인] 버튼이 눌리지 않습니다.** 이때는 [제목 수정]으로 고치거나 [반려]하세요.
   - **[반려]**: "이 제안은 쓰지 않겠다"는 뜻입니다. "검토 대기·승인 만료·승인됨·차단됨" 카드에 보입니다. 반려한 제안은 배치에 넣을 수 없고, 새 제안은 다시 만들 수 있습니다.
6. **차단(✕) 판정을 받은 제안**: 상태 칸에 "차단됨"이 보입니다. [승인]은 눌리지 않고, 카드 아래에 **"승인할 수 없는 이유"** 상자가 나와 차단 사유와 "[제목 수정]으로 고쳐 다시 검증하거나 [반려]할 수 있습니다." 안내를 보여 줍니다. [제목 수정]으로 고쳐 저장하면 다시 검증하고, 통과하면 검토 대기가 되어 승인할 수 있습니다. 쓰지 않을 제안은 [반려]하세요.
7. 승인하면 "승인자 이름 승인 · 만료 시각"이 표시됩니다. **24시간 안에, 한 번만** 쓸 수 있습니다. 만료되면 "승인 만료"가 되고, 다시 승인하면 됩니다. 이미 배치로 실행이 확정된 승인은 실행 확정 시각 기준으로 판단됩니다.
8. 제외 영상에서는 [AI 제안 만들기]와 카드 버튼이 눌리지 않습니다.
9. 맨 아래 "변경 이력"에는 그 영상의 반영·롤백 기록이 나옵니다.

### 4-3-1. 일괄 승인 — 여러 제안을 한 번에 승인하기 (3차 대조에서 추가)
영상을 하나씩 열지 않고 여러 제안을 한꺼번에 승인하는 화면입니다. **승인만 하며 제목은 바뀌지 않습니다.** 화면에 가려면 배치 화면의 "여러 제안을 한 번에 승인하려면 일괄 승인" 링크를 누릅니다(왼쪽 메뉴에도 있는지는 확인 필요). 한 번에 **최대 50건**까지 승인할 수 있습니다.
- **방법 A. 목록에서 고르기**: "승인 가능한 제안 N건" 목록에서 체크합니다. 목록이 길면 **"목록 줄여 보기"** 를 씁니다.
  - 검색칸에 **영상 ID 의 일부나 제목의 일부**를 쓰면 그 영상만 남습니다. 비우면 전체가 다시 보입니다.
  - "판정으로 줄여 보기"에서 **전체 / 통과 / 경고 / 차단** 중 하나를 고릅니다.
  - **최근에 만든 제안이 위에 나옵니다.** 그래서 방금 만든 제안은 목록 맨 위에서 찾으면 됩니다. 영상 ID 일부를 검색하면 더 빨리 찾습니다.
  - 글자와 맞는 제안이 없으면 "입력한 글자와 맞는 제안이 없습니다" 가 나옵니다. 글자를 줄이거나 비우세요.
- **방법 B. 영상 ID 붙여넣기**: 영상 ID(11자)를 붙여넣고 찾습니다. 한 번에 최대 50개입니다.
- **한 영상에 후보가 3개씩 있을 때**: 영상마다 후보 중 **하나만** 고릅니다. 고르지 않은 영상은 "후보를 고르지 않은 영상이 N개 있습니다"라고 나오며, 고르지 않으면 승인 대기 목록에 들어가지 않습니다.
- **[확인 창 열기]** → 승인자 이름을 쓰고 **[N건 승인]** 을 누릅니다. **경고 판정 건**은 확인 창에서 건별로 **"경고를 읽었음"** 확인란을 선택해야 승인됩니다. 차단 판정 건은 승인되지 않고 "제외 N건"으로 사유와 함께 나옵니다.
- **승인 유효시간은 24시간입니다**(코드 확인: 프로그램 정책 설정 `approval.ttl_hours` = 24, 이 값이 실제로 쓰입니다). **그런데 이 화면의 안내문은 "기본 1시간"이라고 적혀 있어 실제와 다릅니다. 확인 필요(개발 확인 항목: 안내문 수정).** 시간이 지나면 다시 승인해야 하므로, 안전하게는 승인한 뒤 바로 배치를 만들어 실행하세요.
- 위 24시간 값은 코드와 설정 파일을 읽어 확인한 것이며, 화면에서 만료 시각이 정말 24시간 뒤로 표시되는지는 이 문서 작성 중 실행해 보지 않았습니다.

### 4-4. 배치(일괄 반영) — 묶어서 바꾸기
**① 승인 항목 고르기** (메뉴 "배치(일괄 반영)")
1. "반영할 승인 항목 고르기" 표에서 묶을 제안을 체크합니다(표 머리글의 네모가 "전체 선택"). 표에는 승인된 제안이 최대 200개까지 보입니다. **한 배치에는 최대 50건**입니다. 넘으면 "한 배치에는 최대 50건까지입니다. 선택을 줄여 주세요." 가 나오고 버튼이 막힙니다.
2. 같은 영상의 제안을 여러 개 고르면 한 영상에 하나만 담기고 나머지는 "제외된 항목"으로 빠집니다.
3. 필요하면 메모(200자까지)를 쓰고 **[사전 점검 만들기]** 를 누릅니다. 아직 **아무것도 바뀌지 않습니다.**
4. **초안과 [초안 버리기]:** 사전 점검을 만들면 담긴 제안들은 그 "초안"에 묶입니다. 초안이 남아 있는 동안은 같은 제안으로 새 사전 점검을 만들 수 없고, 승인 목록에 "초안 배치 #번호에 있음 — 버리거나 실행하세요"와 [초안 배치 #번호 열기] 링크가 나옵니다. 쓰지 않을 초안은 배치 상세 위쪽 또는 "지난 배치" 목록의 **[초안 버리기]** → 확인 창의 **[버리기]** 로 버립니다(초안에는 반영된 변경이 없어 제목은 그대로이고, 담겨 있던 제안은 다른 배치에 다시 담을 수 있습니다). 버려진 초안은 상태가 "버려진 초안"으로 보입니다. 지난 배치 목록에서 아직 실행하지 않은 초안은 "초안"으로 보입니다.

**② 사전 점검 확인** (배치 상세, 초안 상태)
| 항목 | 뜻 |
|---|---|
| 반영 대상 | 실제로 바뀔 건수 |
| 예상 사용량 | 1건당 52단위(제목 수정 50 + 확인용 조회 2) × 건수 |
| 하루 반영 상한 | 기본 10건 |
| 남은 API 한도 | 오늘 남은 사용량 |
| 날짜별 일정 | 하루 상한을 넘는 것은 **다음 날로 자동 예약**. 날짜는 한국 시간 기준 |
| 경고 | 항상 "Studio에서 해당 영상의 제목 A/B 테스트가 진행 중이 아닌지 확인하세요." 가 들어 있습니다. 상한 도달, 쿼터 부족, 경고 판정 제안 포함 안내가 더 붙을 수 있습니다. 실제 수정 모드에서는 맨 앞에 "실제 모드입니다. 실행하면 허용된 영상 N개의 제목이 실제 유튜브에서 바뀝니다…" 경고가 붙습니다 |
| 제외된 항목 | 영상 제목(누르면 영상 상세) 옆에 "(제안 번호): 이유" 형식으로 빠진 제안과 이유 |

표 아래에는 "AI 제안은 사실과 법령 적합성을 보장하지 않습니다…"와 면책 문장이 보입니다.

**③ 실행**
1. "실행 확인" 카드의 노란 상자에서 **"선택한 영상 모두 YouTube Studio에서 제목 A/B 테스트 중이 아님을 확인했습니다."** 확인란을 직접 선택합니다. 이 프로그램은 어떤 영상이 A/B 테스트 중인지 알 수 없으니 Studio에서 직접 확인하고, 테스트 중인 영상은 배치에서 빼야 합니다. 선택하지 않으면 "위 확인란을 선택해야 실행할 수 있습니다."가 나오고 [실행]이 눌리지 않습니다. (이 확인란은 화면 단계이며, 서버가 확인 여부를 따로 저장하거나 검사하지는 않습니다.)
2. "확인 문구 입력:" 옆에 보이는 문구를 **그대로 직접 입력**합니다. 형식은 `실행 N건` 입니다. 예) 3건이면 `실행 3건`. 띄어쓰기도 같아야 하고 앞뒤 공백도 틀린 것으로 봅니다. 실제 수정 모드에서는 `실제 실행 N건` 입니다(9-5).
3. 확인란을 선택하고 "✓ 문구가 일치합니다."가 나오면 빨간 **[실행]** 버튼이 눌립니다. (안내문: 데모 모드에서는 "실행하면 데모 데이터의 제목이 바뀝니다. 계속하려면 아래 문구를 그대로 입력하세요.", 실제 수정 모드에서는 "실제 수정 모드입니다. 실행하면 허용된 영상의 제목이 실제 유튜브에서 바뀝니다. 계속하려면 아래 문구를 그대로 입력하세요."가 나옵니다. 실제 수정 모드에서는 입력할 문구도 `실제 실행 N건` 으로 다릅니다. 코드 확인, 화면 캡처 확인은 아님.)
4. 실행 순간에 승인·제외·한도를 **한 번 더 점검**합니다. 하나라도 어긋나면 **전체가 거부**됩니다(오류 코드 `precheck_stale`). 그러면 그 초안을 [초안 버리기]로 버리고 새로 사전 점검을 만드세요.
5. 같은 요청을 두 번 눌러도(또는 새로고침해도) 한 번만 처리됩니다.

**④ 진행 보기와 중지**
- "진행 상황"이 2초마다 자동으로 새로 고쳐집니다. 건수 표시: 대기 / 진행 중 / 성공 / 실패 / 건너뜀 / 취소됨. 새로고침해도 서버 상태를 다시 읽어 옵니다.
- 배치 상태는 한글로 나옵니다: 초안 / 실행 대기 / 실행 중 / 완료 / 중지됨 / 실패 (일시 중지 문구도 있으나 실제로 쓰이지는 않습니다). 한 번도 실행하지 않고 버린 초안은 "버려진 초안"으로 나옵니다. 오늘 몫은 처리됐지만 내일 이후 몫이 남아 있으면 상태가 계속 **"실행 대기"** 이고 화면은 계속 2초마다 새로 고쳐집니다. 정상입니다.
- 오늘 몫(하루 상한 안)만 오늘 처리하고, 나머지는 **예정일에 프로그램이 알아서** 처리합니다(워커가 2초마다 확인). 프로그램이 꺼져 있다 켜져도 **놓친 날짜 분을 한꺼번에 몰아서 실행하지 않습니다.** PC가 꺼져 있으면 그 시간 동안은 반영이 일어나지 않습니다.
- **[중지]** → "중지하기" 를 누르면 남은 항목은 취소되고, 이미 처리 중인 항목은 끝까지 처리됩니다. 취소된 제안은 승인 시간이 남았으면 "승인됨", 지났으면 "승인 만료"로 돌아옵니다. [중지]는 실행이 확정된 배치(실행 대기·실행 중)에만 보입니다.
- 항목이 **건너뜀**이 되면 아무것도 바뀌지 않은 것입니다. 이유는 `[코드] 사유` 로 상태 옆에 표시됩니다 (뜻은 `WEB_FAQ.md`). 하루 상한에만 걸린 항목은 건너뜀이 아니라 "다음 날로 이월"됩니다.

### 4-5. 이력·롤백 — 바뀐 기록 보기와 되돌리기
1. "이력·롤백"에는 시각, 영상, 구분(반영/롤백)과 모드, 이전→새 제목, 결과, 승인자, 조치가 나옵니다. 모드 칸은 데모 기록이면 "데모"이고, 실제 수정 모드로 반영한 기록은 "실제"로 보입니다. 영상 ID나 결과로 찾을 수 있습니다. 표 위에는 "이 기록은 사람이 승인해 반영한 제목의 변화입니다."와 AI 안내가 있습니다.
2. 결과 칸 글자: **성공 / 실패 / 예정 / 중단됨**. 실패 기록에는 "오류 코드 …"가 붙습니다. "중단됨"은 반영 도중 멈춰서 **제목이 바뀌지 않은** 기록입니다.
3. "결과" 찾기 목록은 **전체 / 예정 / 성공 / 실패 / 중단됨** 입니다. (예전에 있던 "검증 완료·검증 필요·되돌려짐" 선택지는 오류가 나서 목록에서 뺐습니다.)
4. 되돌릴 수 있는 기록에는 **[롤백]** 이 있습니다. 누르면 "현재 제목 → 되돌릴 제목"이 나옵니다.
5. 확인을 위해 **영상 ID를 직접 입력**("복사하지 않고 직접 입력해 주세요")하고 승인자 이름을 쓴 뒤 **[롤백 실행]** 을 누릅니다.
6. 되돌리기가 **안 되는** 경우: 그 뒤에 같은 영상이 또 바뀌었거나(롤백 자체도 "바뀜"입니다), 이미 원래 제목이거나, 처리 중인 변경이 있을 때. 이때는 "되돌릴 수 없음"으로 표시됩니다. 롤백한 뒤에는 그 롤백을 다시 롤백할 수 없습니다. **실제 수정 모드에서는 한 가지가 더 있습니다.** 반영한 뒤 유튜브(Studio 등)에서 그 영상의 제목·설명·태그 등을 선생님이 고쳤다면, 되돌리기가 옛 내용으로 덮어써 그 수정이 사라질 수 있으므로 프로그램이 **되돌리지 않고 거부**합니다("반영한 뒤 유튜브에서 영상이 바뀌어 자동으로 되돌리지 않았습니다", 코드 `live_changed_since_apply`). 이때는 Studio 에서 직접 확인해 고치세요. 그 밖의 거부 사유는 9-7을 보세요.
7. 자동 되돌리기는 없습니다. 되돌릴지는 항상 선생님이 정합니다. 되돌린 뒤에는 그 되돌리기를 취소할 수 없습니다. 롤백에는 72시간·3회 같은 한도가 적용되지 않지만, 쿼터(사용량)는 씁니다.
8. 결과가 "예정"으로 남아 있으면 반영 결과가 불확실하다는 뜻입니다. 데모에서는 흔치 않으며, 보이면 `WEB_FAQ.md` 를 보세요. (화면 문구에 "검증 필요"라는 말이 있으나 서버가 그런 결과를 만들지 않습니다.)
9. 롤백한 제안은 영상 상세 카드의 상태 칸에 "되돌림"으로 보입니다.

### 4-6. 성과 리포트
- 제목을 바꾸기 **전/후 숫자(노출, 클릭률, 조회수, 시청 시간)** 를 나란히 보여 줍니다.
- 맨 위의 노란 박스 **"읽기 전에 꼭 확인하세요"** 를 먼저 읽으세요. 숫자가 달라졌어도 **제목 때문이라고 단정할 수 없고**, 데이터가 부족하면 결론을 내지 않으며, **데모의 성과 숫자는 가짜 데이터**라는 내용이고, 법률 자문이 아니라는 면책 문장과 "이 숫자는 참고용입니다. CSV 파일로 내려받아 다른 곳에 전달할 때도 같은 안내가 적용됩니다."가 함께 있습니다.
- 영상별 상태: "비교 가능" / "데이터 부족"(이유 표시, "변경 후 지표 수집 예정일: 날짜") / "변경 기록 없음". 리포트에는 성공한 제목 변경이 있는 영상만 나옵니다(최대 200개).
- **데모에는 "변경 후" 성과 숫자를 만들어 내는 부분이 없습니다**(코드 확인). 그래서 제목을 바꾼 영상의 리포트는 항상 "데이터 부족"(이유: "변경 후 지표가 아직 없습니다.")으로 나오고, "비교 가능"은 데모에서 볼 수 없습니다. 클라우드 임시 서버에서 반영 후 확인했습니다. 예정일은 반영일로부터 약 14일 뒤로 표시됩니다.
- **[CSV 내보내기]** 로 `youtube-title-report.csv` 파일을 내려받을 수 있습니다. 파일 맨 앞에 엑셀용 표시(BOM)가 들어 있어 보통 한글이 깨지지 않습니다. 깨지면 엑셀의 "데이터 가져오기"에서 UTF-8을 선택하세요.

### 4-7. 설정
위쪽 탭 4개: **안전 설정 / PIN / 세션·연결 / 감사 로그**. (탭은 마우스나 좌우 방향키로 옮깁니다.)
- **안전 설정**: 하루 반영 건수 상한(1~20, 기본 10, 낮을수록 안전), 영상당 제안 개수(1~5, 기본 3), 제목 말투(쉼표로 구분, 최대 5개, 각 20자). 값을 바꾸면 [저장]이 눌립니다. 아래의 **"이 화면에서는 켤 수 없는 설정"** (실제 반영(라이브), 라이브 허용 영상)은 화면에서 바꿀 수 없습니다. 이 구역은 정책 설정 파일의 값을 보여 줄 뿐 9장의 `web\.env` 스위치와 연결되어 있지 않아, **실제 수정 모드가 켜져 있어도 "꺼짐"·"허용된 영상이 없습니다"로 보일 수 있습니다.** 실제 수정 상태는 맨 위 띠와 홈의 "구글(유튜브) 연결" 카드로 확인하세요(알려진 표시 제한).
- **PIN**: 설정/변경/해제(숫자 4~12자리). PIN이 이미 있으면 변경·해제 때 현재 PIN을 입력해야 합니다. PIN을 해제하면 이 PC에서 주소를 여는 누구나 화면을 쓸 수 있게 됩니다. PIN을 연속 5번 틀리면 5분 잠기고, 잠금이 풀린 뒤 또 5번 틀리면 10분, 20분, 40분으로 길어져 **최대 1시간**입니다(올바른 PIN을 입력하면 처음으로 돌아갑니다). PIN을 바꾸거나 해제하면 다른 접속(세션)은 모두 끊깁니다. **PIN을 잊었을 때의 복구 방법은 문서화되어 있지 않습니다** [확인 필요 — 운영 담당에게 문의].
- **세션·연결**: 서버 연결, 구글 연결(서버가 알려 주는 안내 문장), 실행 모드, [로그아웃]. "실행 모드" 칸은 서버의 실제 상태를 따라 "데모 모드(유튜브에 아무것도 전송되지 않음)" 또는 "실제 수정 모드(허용된 영상의 제목이 실제 유튜브에서 바뀝니다)"로 나옵니다. 로그아웃하면 "로그아웃되었습니다" 화면에서 [다시 연결]을 누릅니다.
- **감사 로그**: 누가 언제 무엇을 했는지의 읽기 전용 기록(시각·행위자·동작·대상). 행위자는 "소유자"(내가 화면에서 한 일), "웹 화면", "작업 처리기"(자동 처리)로, 동작은 "제안 승인"·"배치 실행"·"제목 반영"·"롤백" 같은 한글로 보이고 원래 이름(`suggestion.approve` 등)이 작은 글씨로 함께 나옵니다. 구글 연결 관련 동작(`google.connected` 등)은 아직 한글 이름이 없어 영어 그대로 보입니다. 맨 위 "기록 무결성 확인됨"이면 정상, "기록이 변조되었을 수 있습니다"가 나오면 `WEB_RUNBOOK.md` 의 안내에 따라 운영 담당에게 알리세요. 이 기록은 지울 수 없습니다.

### 4-8. 일괄 승인 — 여러 제안을 한 번에 승인 (2026-10-13 추가)
> 이 절은 코드(`BulkApprovePage.tsx`, `ko.ts`)와 계약서·시험 결과서 기준입니다. 데모 모드에서 자동 시험으로 확인했고, 선생님 PC에서 직접 눌러 확인한 것은 아닙니다 — **내 PC에서 확인 필요**.

**언제 쓰나요?** 영상마다 [승인]을 따로 누르는 대신, **여러 영상의 제목 제안을 한 번에 승인**하고 싶을 때 씁니다. 한 번에 **최대 50건**입니다.

**가장 중요한 것 — 이 화면은 승인만 합니다.** 화면 맨 위에 "여러 제안을 한 번에 승인합니다. 이 화면은 승인만 합니다. 제목은 바뀌지 않습니다." 라고 적혀 있습니다. 승인이 끝나도 **제목은 아직 바뀌지 않습니다.** 제목이 바뀌려면 그다음에 **배치를 만들어 실행**해야 합니다(4-4). 승인이 끝나면 결과 화면에 "승인만 했습니다. 제목은 아직 바뀌지 않았습니다. 바꾸려면 배치를 만들어 실행하세요." 가 나오고, **[배치 만들기로 이동]** 을 누르면 배치 화면으로 갑니다. 실제 수정 모드에서는 배치를 실행할 때 `실제 실행 N건` 을 입력해야 합니다(4-4 ③, 9-5).

**승인에는 시간 제한이 있습니다.** 확인 창에 "승인은 일정 시간(기본 1시간) 안에 배치를 만들어 실행해야 합니다. 시간이 지나면 다시 승인해야 합니다." 라고 나옵니다. 지나면 그 제안은 "승인 만료"가 되니 다시 승인하세요.

**메뉴 위치:** 왼쪽 메뉴의 **"일괄 승인"** (홈, 영상 목록 다음). 배치 화면에서도 "여러 제안을 한 번에 승인하려면 일괄 승인" 링크로 올 수 있습니다.

**사용 순서**
1. 방법 A 또는 방법 B로 승인할 제안을 고릅니다. 두 방법을 섞어도 되며, 고른 것은 하나의 **"승인 대기 목록"** 에 모입니다. 같은 영상은 한 번만 담기고 겹친 것은 "같은 영상은 한 번만 담습니다. 겹친 N건은 뺐습니다." 로 알려 줍니다. 목록이 비어 있으면 "아직 고른 제안이 없습니다. 방법 A 또는 방법 B 로 고르세요." 가 보이고 **[확인 창 열기]** 는 눌리지 않습니다.
2. **[확인 창 열기]** 를 눌러 확인 창에서 내용을 읽고 승인합니다.
3. 결과 화면에서 승인된 것과 제외된 것을 확인합니다. 제목을 바꾸려면 **[배치 만들기로 이동]**.

**방법 A. 목록에서 고르기**
1. "방법 A. 목록에서 고르기" 아래 표 위에 "승인 가능한 제안 N건" 이 보입니다. 표 칸은 선택 / 영상 ID / 새 제목 / 판정 / 글자 수 / 승인할 수 없는 이유 입니다.
2. 승인할 줄의 선택 칸을 체크합니다. 맨 위 "현재 목록 전체 선택" 으로 한꺼번에 고를 수도 있습니다. 위쪽에 "선택 N/50건" 으로 몇 건 골랐는지 보입니다.
3. 50건을 넘기려 하면 "최대 50건까지만 고를 수 있습니다. 더 고르려면 다른 선택을 먼저 해제하세요." 가 나옵니다. 하나를 해제한 뒤 고르세요.
4. **승인할 수 없는 제안은 목록에 회색(체크 못 함)으로 보이고, 맨 오른쪽 "승인할 수 없는 이유" 칸에 이유가 적혀 있습니다.** 예: "차단 판정이라 승인할 수 없습니다." / "엄격 모드(건강·금융 등)에서는 통과 판정만 승인할 수 있습니다." / "이미 승인된 제안입니다."
5. 승인할 제안이 하나도 없으면 "승인할 수 있는 제안이 없습니다." 가 보입니다. 먼저 영상 목록에서 AI 제안을 만드세요.

**방법 B. 영상 ID 붙여넣기**
영상 ID를 이미 따로 적어 두었을 때 편합니다.
1. "방법 B. 영상 ID 붙여넣기" 입력칸("영상 ID (줄바꿈, 쉼표, 공백으로 구분)")에 영상 ID를 붙여 넣습니다. 안내: "영상 ID 는 11자입니다. 한 번에 최대 50개까지 찾을 수 있습니다."
2. **[찾기]** 를 누릅니다(누르면 "찾는 중"). 비어 있으면 "찾기를 누르려면 영상 ID 를 한 개 이상 입력하세요.", 50개를 넘으면 "영상 ID 가 N개입니다. 50개 이하로 줄여 주세요." 가 나옵니다. 11자 형식이 아닌 ID는 찾지 않고 "형식이 맞지 않아 찾지 않은 ID: …" 로 알려 줍니다.
3. "찾은 결과 N개 영상" 표에서 영상마다 **상태**를 읽습니다.
   - "없음 (이 영상은 목록에 없습니다)" — 이 프로그램에 없는 ID입니다. ID를 다시 확인하세요(승인 대상 아님).
   - "제외 대상: 사유" — 제외 영상(비공개·아동용·예약 게시·쇼츠 등)이라 승인할 수 없습니다.
   - "후보 제안 없음 (먼저 영상 목록에서 제안을 만드세요)" — 승인할 제안이 아직 없습니다.
4. **후보 제안이 1개**이면 "후보가 1개라 미리 선택했습니다. 확인 창에서 다시 보여 드립니다." 라고 나오며 미리 골라집니다.
5. **후보 제안이 2개 이상이면 직접 하나를 골라야 합니다.** 상태 칸에 "선택 필요" 가 보이고 "(영상 ID) 의 후보 제안 중 하나 고르기" 아래 동그라미(라디오)로 하나를 고릅니다. 고르기 전에는 승인 대기 목록에 들어가지 않으며 "후보를 고르지 않은 영상이 N개 있습니다. 고르지 않으면 승인 대기 목록에 들어가지 않습니다." 라고 알려 줍니다. 프로그램이 대신 골라 주지 않습니다.

**확인 창 ("N건 승인 확인")**
1. 위쪽 파란 상자에 "이 단계는 승인만 합니다. 제목은 아직 바뀌지 않습니다. 바꾸려면 배치를 만들어 실행하세요." 와 승인 유효 시간 안내가 나옵니다.
2. **"승인자 이름"** 을 입력합니다(누가 승인했는지 기록에 남습니다). 비우면 "승인자 이름을 입력해 주세요." 가 나옵니다.
3. "승인 대기 N건" 표에서 영상 ID, 현재 제목, 새 제목을 마지막으로 읽어 봅니다. 현재 제목을 못 불러오면 "(제목을 불러오지 못함)" 이 보이고, 영상 ID로 어떤 영상인지 확인한 뒤 승인하라는 안내가 나옵니다(승인은 할 수 있습니다).
4. **경고(▲)가 있는 제안은 건별로 확인 체크가 필요합니다.** 그 줄 "경고를 읽었음" 칸의 "이 제안의 경고 내용을 읽었고 승인합니다: …" 를 직접 체크하세요. 전체를 한 번에 체크하는 버튼은 없습니다.
5. 조건이 모자라면 **[N건 승인]** 이 눌리지 않고, "아직 필요한 것" 칸에 무엇이 모자란지 글로 적혀 있습니다(예: "경고가 있는 N건은 건별로 확인란을 선택해야 합니다."). 조건을 채운 뒤 **[N건 승인]** 을 누릅니다. 취소는 **[닫기]**.

**결과 화면 읽는 법 ("승인 결과")**
맨 위에 "승인 N건 / 제외 M건" 이 나옵니다. "승인된 N건" 표는 승인 성공이고, **"제외된 N건과 사유"** 표의 "제외 사유" 칸이 승인되지 않은 이유입니다. 제외된 것은 **아무것도 바뀐 것이 없습니다.** 화면에 나오는 사유와 해결 방법:

## 6. 접근성(보기 편한 사용법)

- **키보드만으로** 모든 기능을 쓸 수 있도록 만들어졌습니다(설계·소스 확인, 내 PC 실사용 확인 전). Tab으로 이동, Enter/Space로 누르기, 창(대화상자)에서는 Esc로 닫기가 됩니다. 창이 열리면 첫 입력칸으로 커서가 가고, 닫으면 원래 버튼으로 돌아옵니다. 닫을 수 없는 창(AI 제안 생성 진행 창이 끝나기 전, PIN 재입력 창)은 Esc가 듣지 않습니다.
- 설정의 탭은 좌우 방향키와 Home/End 키로 옮길 수 있습니다.
- 페이지 맨 위에서 첫 Tab을 누르면 **"본문으로 건너뛰기"** 가 나옵니다.
- 화면을 옮기면 커서가 그 화면 제목으로 이동해 화면 낭독 프로그램이 제목을 읽습니다.
- 상태는 **색만이 아니라 기호와 글자**로도 표시합니다 (✓ 통과, ▲ 경고, ✕ 차단).
- 글자 크기: 기본 16px 이상, 누르는 영역 44px을 목표로 만들었습니다. 브라우저 확대(Ctrl + 마우스 휠 또는 Ctrl과 + 키)는 200%까지를 목표로 하며, 400%에서는 화면이 깨질 수 있습니다. 화면 폭 1024px 미만은 지원하지 않습니다.
- 어두운 화면은 **Windows의 설정을 자동으로 따라갑니다** (프로그램 안에서 켜고 끄는 버튼은 없습니다).
- 알려진 한계: 브라우저 탭 제목이 모든 화면에서 같습니다. 실제 화면 낭독 프로그램(NVDA 등)은 사람이 직접 확인하지 못했습니다 [확인 필요]. 색 대비는 개발 중 자동 점검 도구로 측정했다고 기록돼 있으나 이 문서 작성자가 다시 확인하지는 않았습니다.

> **정직한 상태 안내**: 이 장의 기능은 프로그램으로는 만들어졌고 가짜 구글로 자동 시험했습니다. **실제 구글에 접속해 본 적은 없습니다.** 실제 제목이 바뀐 적도 없습니다. 아래 화면 문구와 순서는 코드에서 확인한 것이며, 실제 구글 로그인 화면과 이어지는 부분은 **내 PC에서 확인 필요**입니다.

### 9-1. 시작하기 전에
- 구글 쪽 준비(클라이언트 ID 만들기)와 `web\secrets\google_client.json` 저장, `start.ps1` 다시 실행은 `WEB_INSTALL.md` 8장을 먼저 끝내세요. 클라이언트 유형은 **데스크톱 앱**입니다.
- 준비가 안 되면 홈의 "구글(유튜브) 연결" 카드에 "데모 모드입니다. 구글 연결 파일(google_client.json)이 없어 실제 유튜브에는 연결할 수 없습니다…"와 "실제 유튜브에 연결하려면 web\secrets\google_client.json 을 저장한 뒤 .\web\scripts\start.ps1 을 다시 실행하세요."가 보이고 연결 버튼은 없습니다. 이때는 계속 데모 모드입니다. 파일이 준비되면 "구글 연결 준비가 됐습니다. [구글 계정 연결]을 눌러 로그인하세요. 읽기 전용이라 영상 제목은 바뀌지 않습니다."로 바뀝니다.

### 9-2. 1단계 — 읽기 전용으로 연결하고 내 영상 불러오기
1. 홈 화면의 **"구글(유튜브) 연결"** 카드에서 **[구글 계정 연결]** 을 누릅니다. 구글 로그인 화면으로 이동합니다.
2. 구글에서 **본인 계정으로 로그인**하고 요청한 권한(영상 정보 **읽기**)을 허용합니다. 이 단계의 권한은 읽기뿐이라 **제목이 바뀌지 않습니다.**
3. 홈으로 돌아오면 카드에 "구글(유튜브)에 읽기 전용으로 연결돼 있습니다. 영상 제목은 바뀌지 않습니다."가 보이고 맨 위 띠가 "구글 연결됨(읽기) — 제목은 바뀌지 않습니다"로 바뀝니다. 구글이 오류를 돌려주면 카드에 "구글 연결에 문제가 있습니다"와 이유가 한 번 표시됩니다(로그인 취소 포함). 다시 [구글 계정 연결]을 누르면 됩니다.
4. **[내 영상 불러오기]** 를 누르면 내 채널의 영상 목록을 읽어 와 "영상 목록"에 보여 줍니다(최대 2,000개까지, 읽기만 합니다). 데모 영상은 이때 실제 영상으로 바뀝니다.
   - 이미 데모 영상으로 승인·반영·되돌리기 등의 **기록을 만들어 둔 상태**면 "데모 기록이 있어 불러올 수 없습니다"가 나옵니다. 데모 기록을 지우고 오려면 운영 담당 또는 `WEB_INSTALL.md` 8-3 의 `reset-demo.ps1` 안내를 따르세요(데이터가 지워지니 먼저 백업).
   - 불러온 영상이 처음부터 제외 대상(Shorts·비공개·아동용 등)이면 일반 규칙대로 제외 표시됩니다.
5. 구글을 연결해도 **AI 제안은 여전히 가짜(모의) AI** 입니다. 제안을 만들 때 영상 정보가 외부 AI로 나가는 일은 아직 없습니다.

### 9-3. 2단계 — [제목 수정 권한 연결]이 무엇인가요?
- 읽기 연결만으로는 제목을 바꿀 수 없습니다. 제목을 바꾸려면 구글에서 **"제목 수정" 권한을 따로 한 번 더 허용**해야 합니다. 카드의 **"제목 수정 권한"** 구역에서 **[제목 수정 권한 연결]** 을 누르면 구글 로그인 화면으로 이동해 그 권한을 요청합니다. 읽기 권한과 수정 권한은 **서로 다른 로그인 정보로 따로 보관**됩니다.
- **이 권한을 허용했다고 제목이 바뀌지 않습니다.** 실제로 바뀌려면 아래 3가지가 모두 필요합니다(`WEB_INSTALL.md` 8-4).
  1. 서버 설정 "실제 수정 켜기"(`YTWEB_LIVE_WRITE=1`)
  2. 제목 수정 권한 연결
  3. 서버 설정 "수정 허용 영상"(`YTWEB_LIVE_ALLOWED_VIDEOS`)에 영상이 1개 이상
- 서버 설정 두 가지는 `web\.env` 파일에 적고 `start.ps1` 을 다시 실행하면 전달됩니다(순서와 방법은 `WEB_INSTALL.md` 8-4). 화면 안내 문구에도 "web\.env 파일의 YTWEB_LIVE_WRITE 를 1 로 바꾸고 start.ps1 을 다시 실행하세요." 같은 안내가 나옵니다. 이 방법은 코드와 설정 파일로 확인했고, 내 PC(Windows)에서 실제로 해 본 적은 없습니다 — 내 PC에서 확인 필요.

### 9-4. 카드에 보이는 상태별 뜻
| 카드에 보이는 문장 | 뜻 | 제목이 바뀌나요? |
|---|---|---|
| "읽기 전용입니다. 이 프로그램은 구글에서 영상 정보를 읽기만 하고, 영상 제목을 바꾸지 않습니다." | 읽기 연결만 됨 | 아니오 |
| "제목 수정 권한이 연결돼 있습니다." + "실제 수정은 아직 꺼져 있습니다(수정 허용 영상 N개)." 뒤에 부족한 것 안내("web\.env 파일의 YTWEB_LIVE_WRITE 를 1 로 바꾸고…" 또는 "수정을 허용할 영상이 없습니다. web\.env 파일의 YTWEB_LIVE_ALLOWED_VIDEOS 에…") | 권한은 있으나 서버 설정이 꺼져 있거나 허용 영상이 0개 | 아니오 (가짜 방식으로만 동작) |
| **"실제 수정 모드가 켜져 있습니다"** (경고 상자) | 3가지가 모두 맞음. 허용 영상 N개는 **진짜 유튜브 제목이 바뀝니다** | **예 — 허용 영상만** |
- 이전 문서의 "아직 꺼져 있음 안내가 무엇이 부족한지 구분하지 못함" 문제는 고쳐졌습니다(위 표처럼 부족한 것을 알려 줍니다). 읽기 로그인만 풀리고 쓰기 정보가 남은 드문 경우에도 "제목 수정 권한" 구역이 보이도록 고쳐졌습니다(코드 확인). 그래도 헷갈리면 맨 위 띠가 "실제 수정 모드"인지 먼저 보고, 확실하지 않으면 **실제 수정이 켜져 있다고 생각하고** 조심하세요.

### 9-5. 실제 모드에서 달라지는 점 (실제로 바뀌는 상태에서만)
- **확인 문구가 다릅니다.** 데모에서는 배치를 실행할 때 `실행 N건` 을 입력했지만, 실제 모드에서는 **`실제 실행 N건`** 을 입력해야 합니다. 이 문구는 일부러 다르게 만들어, 데모인 줄 알고 실제로 바꾸는 사고를 막습니다. 사전 점검(초안) 화면에도 경고가 추가됩니다. 문구는 화면이 알려 주는 그대로 입력하세요.
- **허용 영상이 아니면 바뀌지 않습니다.** 허용 목록에 없는 영상은 초안 단계, 실행 직전, 되돌리기에서 모두 막히고 "실제 수정 허용 영상이 아닙니다" 안내가 나옵니다(오류 코드 `live_not_allowed`).
- **이력의 구분**: 변경 기록에 실제(live)인지 데모인지 구분되어 저장됩니다(이력 화면의 모드 칸에 "실제" 또는 "데모").
- **모드를 도중에 바꾸면 거부됩니다.** 배치를 실행 확정한 때와 실제 수정 모드 설정이 달라지면 그 항목은 반영되지 않고 건너뜀(`live_mode_changed`: "…이 배치를 취소하고 새로 만들어 확정하세요.")이 됩니다. 반영한 때와 모드가 다른 상태에서 롤백하면 `live_mode_mismatch` 로 거부됩니다(9-7).
- 맨 위 띠가 "실제 수정 모드 — 허용된 영상의 제목이 실제 유튜브에서 바뀝니다"로 바뀝니다.
- **쿼터**: 제목 한 건을 바꾸는 요청(`videos.update`) 1회가 API 사용량 **50단위**이고, 반영 1건 전체로는 확인용 조회 2회(1단위씩)를 더해 **52단위**를 씁니다(프로그램 설정값 기준, 구글 공식 값은 확인 필요). 홈의 "남은 API 사용량"과 하루 반영 한도를 확인하세요.

### 9-6. 처음에는 테스트 영상 1개로만
1. 공개되어도 괜찮은 영상 **1개**를 테스트용으로 정하고 허용 목록에도 그 영상만 넣게 요청하세요(`WEB_INSTALL.md` 8-5).
2. 그 영상 하나로 제안 → 승인 → 배치 사전 점검 → `실제 실행 1건` 입력 → 반영까지 해 봅니다.
3. 유튜브 Studio 에서 제목이 실제로 바뀌었는지 직접 확인합니다.
4. 이력·롤백 화면에서 같은 영상을 **되돌려** 원래 제목으로 돌아오는지 확인합니다.
5. 모두 이상 없을 때만 허용 영상을 늘리도록 요청하세요.

### 9-7. 되돌리기(롤백)와 한계
- 이력·롤백 화면(4-5)에서 바뀐 영상을 선택해 이전 제목으로 되돌릴 수 있습니다. 롤백도 이력에 남습니다. 허용 목록에서 빠진 영상은 되돌릴 수 없고(`live_not_allowed`), 이때는 **유튜브 Studio 에서 직접** 고치거나 허용 목록에 다시 넣어야 합니다.
- **실제 수정 모드의 롤백은 보수적으로 동작합니다.** 반영한 뒤 유튜브에서 제목·설명·태그·카테고리·언어가 바뀌었으면 백업으로 덮어쓰지 않고 `live_changed_since_apply`("반영한 뒤 유튜브에서 영상이 바뀌어 자동으로 되돌리지 않았습니다.")로 거부합니다. 이때는 유튜브 Studio 에서 직접 확인해 고치세요. (반영 중 보존 항목이 손상된 변경(`verify_failed`)은 예외로 통째 복원합니다.)
- 반영할 때와 실제 수정 모드 설정이 다르면 `live_mode_mismatch`("이 변경을 반영한 때와 실제 수정 모드 설정이 달라 되돌리지 않았습니다.")로 거부합니다. 같은 모드로 맞추거나 Studio 에서 직접 되돌리세요.
- 유튜브가 되돌리기를 거부하거나 응답이 불분명하면 직접 고쳐야 할 수 있습니다(카드 경고 문구와 같습니다).
- **"반영됐는지 알 수 없음" 상태**: 구글 응답이 끊기거나 새 제목을 확인할 수 없으면 프로그램이 실패로 단정하지 않고 "반영 여부를 확인해야 합니다"라고 안내합니다. 이때는 **다시 실행하기 전에 유튜브 Studio 에서 현재 제목을 먼저 확인**하세요(이중 반영 방지).

### 9-8. 연결 해제
- 카드의 **[연결 해제]** 를 누르고 한 번 더 **[해제]** 로 확인하면 저장된 로그인 정보(읽기·쓰기 모두)가 지워지고 실제 수정이 멈춥니다. 이미 불러온 영상 목록과 변경 이력은 지워지지 않습니다.
- [연결 해제]는 이 프로그램이 저장한 로그인 정보만 지웁니다. 코드에 구글 쪽 권한을 취소하는 요청이 없는 것을 확인했으므로, **구글 계정 쪽의 권한까지 없애려면 구글 계정 설정의 "타사 앱 및 서비스 액세스"(메뉴 이름은 구글 화면에서 확인 필요)에서 직접 삭제**해야 합니다.
