# 유튜브 제목 웹 자주 묻는 질문(FAQ) — 막혔을 때 보는 곳

> **먼저 알아 두세요: 지금은 데모 모드입니다.** 영상 200개는 가짜 연습용이고, 유튜브와 AI 서비스에는 아무것도 전송되지 않으며, **실제 유튜브 제목은 절대 바뀌지 않습니다.** (2026-10-11 정정: 구글 연결·제목 수정 프로그램은 만들어졌지만 **실제 구글 접속·실제 제목 변경은 한 번도 해 보지 않았고**, 구글 연결 파일을 넣고 서버 설정을 켜기 전에는 위 문장이 그대로 맞습니다. 자세한 것은 아래 4-1장.) 실제 AI 연결은 이후 단계에서 별도 승인 후 추가됩니다. `[확인 필요]` 는 아직 직접 확인하지 못했다는 뜻입니다.

기준: 오류 코드 표는 실제 백엔드 코드(`ProblemError`·`StepFailure` 호출)와 `docs/yt/API.md` 를 2026-10-11에 대조했고, 일부는 클라우드 임시 서버(가짜 데이터)에서 직접 일으켜 확인했습니다. 화면 문구는 `ko.ts` 와 화면 소스 기준입니다. "내 PC에서 확인 필요"는 선생님 PC(Windows)에서만 확인할 수 있다는 뜻입니다. 쓰는 법은 `WEB_USER_MANUAL.md`, 설치는 `WEB_INSTALL.md`, 운영은 `WEB_RUNBOOK.md` 입니다.

**오류가 나면 이렇게 하세요**
1. 화면 빨간(또는 노란) 상자의 **제목, 상세, "다음에 할 일", "오류 코드"** 를 읽습니다.
2. 아래 3장에서 오류 코드를 찾습니다. 코드는 영어 소문자와 밑줄(`_`)로 되어 있습니다.
3. 그래도 모르겠으면 코드와 상황을 메모해 운영 담당(문의처 **미정**)에게 전하세요. 비밀번호·PIN은 알리지 마세요.

## 1. "왜 안 바뀌나요?" 모음

**Q1. 제목을 바꿨는데 유튜브(진짜 내 채널)에서는 그대로예요.**
정상입니다. 지금은 데모 모드라 가짜 영상의 제목만 바뀝니다. 유튜브에는 아무것도 전송되지 않습니다.

**Q2. [승인] 버튼이 눌리지 않아요.**
- 검증이 **차단(✕)** 이면 승인할 수 없습니다.
- 승인자 이름을 비워 두면 안 됩니다.
- 영상이 **제외** 대상(비공개·아동용·예약 게시·쇼츠)이면 안 됩니다.
- 상태가 이미 "승인됨/반영 대기/반영 완료/반려됨"이면 승인 버튼이 없습니다.
- 검증이 **차단(✕)** 이고 상태 칸에 "차단됨"이 보이는 카드는 [승인]이 눌리지 않고, 카드 아래 "승인할 수 없는 이유" 상자에 사유가 나옵니다. [제목 수정]으로 고치거나 [반려]할 수 있습니다(아래 Q17).
- 경고(▲)인 경우 "경고 사유를 모두 읽고 확인했습니다." 를 체크해야 눌립니다.
- 건강·금융 주제(엄격 모드)는 경고만 있어도 차단으로 처리되어 승인되지 않습니다.

**Q3. 영상 앞 체크 네모가 눌리지 않아요.**
제외된 영상입니다("제외" 표시와 사유가 있음). 제외 영상은 제안·승인·배치·반영 모두에서 막힙니다.

**Q4. [AI 제안 만들기]가 눌리지 않거나 오류가 나요.**
제외 영상이면 눌리지 않습니다(`video_excluded`). 같은 제목이 이미 있으면 새로 만들지 않고 기존 제안을 보여 줍니다. 제안 개수는 1~5개만 가능합니다(`count_invalid`).

**Q5. 배치에서 [사전 점검 만들기]가 눌리지 않아요.**
선택이 0개이거나 51건 이상이면 눌리지 않습니다(한 배치 최대 50건). 승인된 제안만 목록에 나옵니다. 목록이 비어 있으면 영상 상세에서 먼저 승인하세요.

**Q6. [실행] 버튼이 안 눌려요.**
두 가지가 모두 필요합니다. ① 노란 상자의 **"선택한 영상 모두 YouTube Studio에서 제목 A/B 테스트 중이 아님을 확인했습니다."** 확인란 선택(안 하면 "위 확인란을 선택해야 실행할 수 있습니다."가 보입니다). ② "실행 확인" 칸에 화면에 보이는 문구(`실행 N건`, 실제 수정 모드는 `실제 실행 N건`)를 **글자 하나, 띄어쓰기 하나까지 똑같이** 입력. 앞뒤 공백도 틀린 것으로 봅니다. "문구가 일치합니다."가 뜨고 확인란이 선택되어 있으면 눌립니다.

**Q7. 실행했는데 어떤 항목은 "건너뜀"이에요.**
건너뜀은 **아무것도 바꾸지 않았다**는 뜻입니다. 사유 코드는 3-3 표를 보세요. 흔한 것은 승인 만료(24시간), 같은 영상 72시간 간격 제한, 영상당 3회 제한입니다. 하루 상한에만 걸린 항목은 건너뜀이 아니라 **다음 날로 넘어갑니다**(Q8).

**Q8. 오늘 10건만 바뀌고 나머지는 안 바뀌어요.**
정상입니다. 하루 반영 상한(기본 10건) 때문에 나머지는 **다음 날로 예약**됩니다. 날짜별 일정은 배치 상세에 나옵니다. 상한은 [설정 > 안전 설정]에서 1~20으로 바꿀 수 있습니다(낮을수록 안전).

**Q9. 어제 예약한 건이 오늘 한꺼번에 처리되지 않았어요.**
의도된 동작입니다. 프로그램(또는 PC)이 꺼져 있던 동안 놓친 날짜 분을 **몰아서 실행하지 않고**, 켜진 날의 하루 몫만 처리합니다. 예약 처리는 Docker Desktop과 프로그램이 켜져 있어야 합니다.

**Q10. 같은 영상을 다시 바꾸려는데 "한도 초과"라고 해요.**
같은 영상은 직전 변경 후 72시간(3일)이 지나야 다시 바꿀 수 있고, 영상당 최대 3회입니다. **롤백(되돌리기)도 1회로 세고 72시간이 새로 시작됩니다.** 영상 상세의 "변경 한도 상태"에 사유와 가능한 시각이 나옵니다. 3회에 도달하면 시간이 지나도 풀리지 않으며, 그때 사유에 나오는 "설정 cadence.max_changes_per_video를 바꿔야 합니다"는 개발자용 문장입니다(이 화면에서는 바꿀 수 없음). 데모에서는 "변경 후 노출수 1,000회" 기준을 적용하지 않으므로(변경 후 지표가 없기 때문) 막히는 이유는 72시간·3회·하루 상한뿐입니다. 하루 상한 문장에 "태평양 시간 기준"이라고 나오지만 실제 계산은 한국 시간 하루입니다(문구 오류, 알려진 제한).

**Q11. 승인했는데 "승인 만료"가 됐어요.**
승인은 24시간만 유효하고(일괄 승인 화면 안내문도 24시간) 한 번만 쓸 수 있습니다. 제목을 수정하거나 영상 정보가 바뀌어도 무효가 됩니다. 다시 [승인]하세요.

**Q12. 성과 리포트가 전부 "데이터 부족"이에요.**
- 변경 기록이 없으면 "변경 기록 없음".
- 데모에는 변경 **후** 성과 숫자를 만드는 부분이 없습니다(코드 확인). 그래서 제목을 바꾼 영상은 항상 "데이터 부족"(이유: "변경 후 지표가 아직 없습니다.")으로 나옵니다. 클라우드 임시 서버에서 반영 후 이 결과를 확인했습니다. 이 화면의 "비교 가능"은 데모에서 볼 수 없습니다.
- 데이터가 부족하면 일부러 결론을 내지 않습니다. 이유 목록과 "변경 후 지표 수집 예정일"을 보세요.
- 숫자가 나와도 데모의 성과는 **가짜 데이터**이고, 제목 때문이라고 단정할 수 없습니다.

**Q13. 화면에 영어가 보여요.**
예전에 영어로 보이던 `blocked`("차단됨"), `aborted`("중단됨"), `rolled_back`("되돌림")은 한글로 고쳐졌습니다. 이력 모드 칸의 실제 수정 기록은 "실제"로 한글 표기됩니다. 지금 영어로 남아 있는 것은 ① 감사 로그의 구글 연결 관련 동작 이름(`google.connected` 등) ② 오류 코드(`precheck_stale` 등, 일부러 영어)입니다. 동작에는 문제가 없습니다. 배치 상태는 한글(초안/실행 대기/실행 중/완료/중지됨/실패, 버린 초안은 "버려진 초안")로 나옵니다.

**Q14. 선택해 둔 영상, 적어 둔 승인자 이름이 새로고침하니 사라졌어요.**
영상 목록의 체크 선택, 승인자 이름, 진행 창은 새로고침하면 사라집니다. 검색 조건·정렬·쪽, 설정 탭, 서버에 저장된 모든 것(제안, 배치, 이력)은 그대로입니다.

**Q15. 롤백(되돌리기)이 안 돼요.**
같은 영상에 그 뒤 다른 변경(롤백 포함)이 있거나(`later_change_exists`), 이미 원래 제목이거나(`already_restored`), 처리 중인 변경이 있으면(`pending_change_exists`) 안 됩니다. 영상 ID는 **직접 똑같이** 입력해야 합니다(`typed_video_id_mismatch`).

**Q16. 실제 내 채널 영상을 불러오고 싶어요 / 진짜 AI로 제안받고 싶어요.**
- 실제 채널 영상 읽기: 프로그램은 만들어졌지만 **실제 구글에 접속해 본 적은 없습니다**. 준비 방법은 4-1장과 `WEB_INSTALL.md` 8장입니다.
- 진짜 AI 제안: **아직 만들어지지 않았습니다**(AI 서비스가 정해지지 않음). 선생님의 승인과 준비가 필요합니다.

**Q17. 차단(✕)된 제안은 어떻게 하나요?**
상태 칸에 "차단됨"이 보이고 [승인]은 눌리지 않습니다(승인도 배치 포함도 되지 않습니다). 카드 아래 "승인할 수 없는 이유" 상자의 사유를 읽고, [제목 수정]으로 고쳐 저장하면 다시 검증합니다. 통과하면 "검토 대기"가 되어 승인할 수 있습니다. 쓰지 않을 제안은 [반려]하세요. 후보를 더 받으려면 설정의 "영상당 제안 개수"를 늘린 뒤 [AI 제안 만들기]를 다시 누르세요.

**Q18. "다른 배치에 이미 담겨 있습니다"라고 하면서 [사전 점검 만들기]가 거절돼요.**
이전에 사전 점검(초안)을 만들고 실행하지 않았거나 실행이 `precheck_stale` 로 거부됐을 때 생깁니다. 초안에 담긴 제안은 그 초안에 묶여 있어 새 배치에 쓸 수 없습니다. 배치 화면의 승인 목록에 "초안 배치 #번호에 있음 — 버리거나 실행하세요"가 보이니, [초안 배치 #번호 열기]로 가서 실행하거나 **[초안 버리기]**(확인 창에서 [버리기])로 버리세요. 초안에는 반영된 변경이 없어 제목은 그대로이고, 버리면 제안을 다시 담을 수 있습니다.

## 2. 시작·접속 문제

| 증상 | 원인과 조치 |
|---|---|
| "Docker 엔진에 연결할 수 없습니다" | Docker Desktop을 먼저 실행하고 고래 아이콘이 안정될 때까지 1~2분 기다린 뒤 다시 `start.ps1` |
| "포트 8080 를 다른 프로그램이 이미 사용 중입니다." | 다른 프로그램이 8080을 쓰는 중. `WEB_INSTALL.md` 의 확인 방법 참고 |
| "스크립트를 실행할 수 없습니다" | 같은 PowerShell 창에서 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned` 를 먼저 실행 |
| "Docker 가 Windows 컨테이너 모드입니다." | 고래 아이콘 오른쪽 클릭 → Switch to Linux containers... |
| 브라우저에서 아예 안 열림 | 주소가 정확히 `http://127.0.0.1:8080` 인지 확인. 다른 주소(내 PC의 IP, 다른 포트)로는 열리지 않으며, 이때 오류 상자 없이 브라우저가 "연결할 수 없음"(응답 없음)으로 보이는 것이 정상입니다(서버가 연결을 바로 끊음). `localhost:8080` 은 허용됩니다 |
| 화면이 하얗게 나옴 | F12 → 콘솔에 "Content Security Policy" 오류가 있는지 보고 운영 담당에게 전달 [확인 필요: 실제 브라우저 확인 안 됨] |
| "서버 연결이 끊겼습니다" 배너 | 프로그램(api)이 꺼졌거나 Docker가 멈춘 것. Docker Desktop 확인 후 `status.ps1`, 그다음 [다시 연결]. 작성 중이던 내용은 저장되지 않았을 수 있습니다 |
| "세션이 만료되었습니다" | 마지막으로 쓴 뒤 30분이 지났거나(처음 연결 후 최대 12시간) 다른 곳에서 PIN을 바꿨습니다. **PIN이 꺼져 있으면** 화면이 알아서 조용히 다시 연결합니다. **PIN이 켜져 있으면** "세션이 만료되었습니다" 창이 뜨고 PIN을 다시 입력하면 이어서 쓸 수 있습니다(이 창은 Esc로 닫히지 않습니다). [다시 연결] 버튼은 "로그아웃되었습니다" 화면과 "서버 연결이 끊겼습니다" 안내에 있습니다 |
| "PIN 이 맞지 않습니다" / `pin_locked` | 5회 연속 틀리면 5분 잠기고, 반복하면 2배씩(최대 1시간) 늘어납니다. 기다린 뒤 다시 입력. PIN 분실 시 복구 절차는 문서화되지 않았습니다 [확인 필요] |
| 컨테이너가 계속 재시작 | `.\web\scripts\logs.ps1 -Service api` (또는 db/worker/migrate)로 원인 확인 — `WEB_RUNBOOK.md` 참고 |
| PC를 껐다 켰더니 안 열림 | Docker Desktop을 실행하고 `start.ps1` 을 다시 실행. Docker Desktop은 기본적으로 로그인 때 자동 시작되지 않습니다 |

## 3. 오류 코드별 해결표

화면의 "오류 코드"와 같은 글자를 찾으세요. 이 표는 `API.md` 의 코드표를 쉬운 말로 풀었습니다. "HTTP"는 참고용 숫자이니 몰라도 됩니다.

### 3-1. 접속·보안 관련

| 오류 코드 | HTTP | 뜻 | 해결 |
|---|---|---|---|
| `host_not_allowed` | 403 | 허용되지 않은 접속 주소. 보통은 앞단(nginx)이 연결을 바로 끊어 이 코드가 화면에 나오지 않고 "연결할 수 없음"으로 보입니다 | 주소를 `http://127.0.0.1:8080` 로 열기 |

## 4. 데이터·백업 관련

**Q. 데이터가 사라졌어요.** 가장 흔한 원인은 `docker compose down -v`, Docker Desktop "Clean / Purge data", `docker system prune --volumes`, 또는 `reset-demo.ps1` 입니다. `web\backups` 에 백업이 있으면 `WEB_RUNBOOK.md` 의 복원 절차를 따르세요. 백업을 만든 적이 없다면 되살릴 방법이 없습니다.

**Q. 백업은 어떻게 하나요?** `.\web\scripts\backup.ps1` (자동 백업은 없습니다). 백업 파일은 암호화되지 않았으니 남에게 주지 마세요.

**Q. 감사 로그에 "기록이 변조되었을 수 있습니다"가 떠요.** 기록이 중간에서 바뀌거나 지워진 신호입니다. 예전 안내에는 "새 PC로 옮겨 복원하면 나올 수 있다"고 되어 있었으나, 코드를 확인한 결과 감사 기록은 키 없는 해시 연결이라 복원만으로는 어긋나지 않는 것이 설계입니다(복원 후 실제 표시는 내 PC에서 확인 필요). 새 PC로 복원할 때 실제로 생기는 일은 **기존 승인이 모두 무효가 되어 다시 승인해야 한다**는 것입니다. 직접 고치려 하지 말고 `WEB_RUNBOOK.md` 의 점검 절차를 따르거나 운영 담당에게 알리세요.

## 4-1. 구글 연결·실제 수정 관련 (2026-10-11 추가)

> 이 장은 코드와 가짜 구글 시험 결과에 근거합니다. 실제 구글에서 확인하지 못한 부분은 [확인 필요]로 적었습니다.

**Q. 구글에 연결하면 제목이 바뀌나요?**
아니요. [구글 계정 연결]은 **읽기 전용**이라 영상 정보를 읽어 오기만 합니다. 제목이 실제로 바뀌려면 (1) [제목 수정 권한 연결], (2) 서버 설정 "실제 수정 켜기", (3) "수정 허용 영상" 1개 이상, **세 가지가 모두** 필요합니다. 홈의 "구글(유튜브) 연결" 카드에 **"실제 수정 모드가 켜져 있습니다"** 경고가 보일 때만 허용 영상의 제목이 실제로 바뀝니다. (참고: 맨 위 띠는 상태를 따라 "데모 모드 / 구글 연결됨(읽기) / 실제 수정 모드"로 바뀝니다. 홈 "연결 상태" 첫 줄은 구글 연결 파일만 있어도 "구글 연결됨"으로 나올 수 있으니 로그인 여부는 둘째 줄과 카드로 확인하세요.)

**Q. 쓰기(제목 수정) 권한은 왜 따로 연결하나요?**
실수로 바뀌는 것을 막기 위한 안전장치입니다. 읽기 연결로는 목록만 읽을 수 있고, 제목 수정 권한은 구글에서 **한 번 더 따로 허용**해야 하며 로그인 정보도 **별도 파일**에 보관됩니다. 수정 권한을 안 주면 읽기 연결을 해도 제목을 바꿀 방법이 없습니다.

**Q. "허용 영상"이 뭔가요?**
실제로 제목을 바꿔도 되는 영상 ID 목록입니다. 서버 설정(`YTWEB_LIVE_ALLOWED_VIDEOS`)에 쉼표로 구분해 넣으며, **목록에 없는 영상은 승인을 받았어도 바뀌지 않습니다.** 목록이 비어 있으면 실제로는 아무것도 바뀌지 않습니다. 처음에는 테스트 영상 **1개만** 넣는 것을 권합니다(`WEB_INSTALL.md` 8-5). 이 목록은 화면 설정에서 바꿀 수 없고(`setting_not_allowed`), 서버 설정에서만 바꿉니다. 서버 설정은 `web\.env` 파일에 적고 `start.ps1` 을 다시 실행하면 전달됩니다(`WEB_INSTALL.md` 8-4, 내 PC에서 확인 필요).

**Q. 실제 모드를 끄려면 어떻게 하나요?**
가장 빠른 방법은 홈 카드의 **[연결 해제]** → [해제]입니다(쓰기 로그인 정보까지 지워져 실제 수정이 즉시 멈춥니다). 서버 설정으로 끄려면 `web\.env` 에서 `YTWEB_LIVE_WRITE=0` 으로 고치거나 `YTWEB_LIVE_ALLOWED_VIDEOS` 를 비운 뒤 `start.ps1` 을 다시 실행하세요. 끈 뒤에도 이미 바뀐 제목은 저절로 돌아오지 않으므로 이력에서 되돌려야 합니다(허용 목록에서 이미 뺀 영상은 되돌리기도 막히니, **먼저 되돌리고 나서 허용 목록에서 빼세요**).

**Q. 실제 모드에서는 확인 문구가 왜 다른가요?**
데모와 구분하기 위해 일부러 `실제 실행 N건` 으로 다르게 합니다. 화면에 표시된 문구를 그대로 입력하세요. 데모 때처럼 `실행 N건` 을 입력하면 [실행]이 눌리지 않거나(문구 불일치 표시), 서버가 `confirm_text_mismatch` 로 거부하며 아무것도 바뀌지 않습니다.

**Q. 구글을 연결했는데 상단에는 계속 "데모 모드 — 유튜브에 아무것도 전송되지 않습니다"라고 나와요.**

## 4-2. 일괄 승인·여러 영상 반영 관련 (3차 대조에서 추가)

**Q. 방금 만든 제안을 일괄 승인 목록에서 어떻게 찾나요?**
목록은 **최근에 만든 제안이 위에** 나옵니다. 길면 "목록 줄여 보기" 검색칸에 영상 ID 의 일부나 제목의 일부를 쓰고, "판정으로 줄여 보기"에서 전체/통과/경고/차단을 고르세요. 비우면 전체가 다시 보입니다.

**Q. 한 영상에 후보가 3개씩 있는데 하나만 고르려면요?**
일괄 승인에서 영상마다 후보 중 하나만 체크합니다. 고르지 않은 영상은 "후보를 고르지 않은 영상이 N개 있습니다"라고 나오며 승인 대기 목록에 들어가지 않습니다.

**Q. 경고 판정인 건이 승인되지 않아요.**
확인 창에서 그 건의 **"경고를 읽었음"** 확인란을 선택해야 합니다. 경고 건이 여러 개면 건별로 모두 선택해야 합니다. 차단 판정 건은 승인되지 않습니다(제목을 고쳐 다시 검증).

**Q. 승인한 뒤 얼마 안에 배치를 실행해야 하나요?**
코드와 설정 파일 기준으로 승인 유효시간은 **24시간**입니다(1회용). 일괄 승인 화면의 안내문도 "기본 24시간"으로 같습니다(예전의 "1시간" 안내문은 수정됨). 헷갈리면 승인 후 바로 배치를 만들어 실행하세요. 시간이 지나 `approval_expired` 가 나오면 다시 승인하면 됩니다.

**Q. 영상 ID 는 어디서 보나요?**
영상 목록에서 각 영상 제목 아래에 11자로 표시됩니다(화면 확인은 하지 않았고 안내 문구 기준이라 확인 필요).

**Q. 여러 영상을 실제로 바꾸려면 허용 영상 목록에 어떻게 넣나요?**
`web\.env` 파일의 `YTWEB_LIVE_ALLOWED_VIDEOS=` 뒤에 영상 ID 를 **쉼표로 이어서** 적습니다. 예: `YTWEB_LIVE_ALLOWED_VIDEOS=영상ID11자,영상ID11자` (실제 ID 로 바꾸세요). 적은 뒤 `.\web\scripts\start.ps1` 을 다시 실행해야 적용됩니다. 쉼표 앞뒤 공백이 허용되는지는 확인하지 못했으니 공백 없이 쓰세요. 실제 수정은 `YTWEB_LIVE_WRITE=1` 과 [제목 수정 권한 연결]도 함께 필요합니다. 처음에는 1개로 시험하세요. (`web\.env.example` 과 `web\compose.online.yaml` 의 항목 이름을 읽어 확인했고, 쉼표 구분 설명은 `.env.example` 문구 기준입니다.)

**Q. 쇼츠도 바꾸려면요?**
위 "쇼츠(3분 이하) 영상도 제목을 바꿀 수 있나요?" 항목을 보세요: `web\.env` 에 `YTWEB_INCLUDE_SHORTS=1` → `start.ps1` 다시 실행 → 홈 [내 영상 불러오기]. 실제 모드에서는 쇼츠 영상 ID 도 허용 영상 목록에 넣어야 바뀝니다. (`.env.example`·`compose.online.yaml` 과 일치함을 확인했습니다. 단 `.env.example` 은 "Shorts(3분 이하)는 제외되어 바꿀 수 없다"는 옛 문구도 한 줄 있어 서로 어긋납니다. 확인 필요.)

## 4-2. 일괄 승인 관련 (2026-10-13 추가)

> 사용법은 `WEB_USER_MANUAL.md` 4-8장입니다. 데모 모드에서 자동 시험으로 확인했으며 선생님 PC에서 직접 확인한 것은 아닙니다(내 PC에서 확인 필요).

**Q. 일괄 승인을 했는데 제목이 안 바뀌었어요.**
정상입니다. 일괄 승인은 **승인만** 합니다. 화면에도 "승인만 했습니다. 제목은 아직 바뀌지 않았습니다. 바꾸려면 배치를 만들어 실행하세요." 라고 나옵니다. **[배치 만들기로 이동]** → 승인 항목 고르기 → [사전 점검 만들기] → 확인란과 확인 문구 입력 후 [실행]까지 해야 제목이 바뀝니다(실제 수정 모드는 `실제 실행 N건` 입력).

**Q. 목록에서 체크가 안 눌려요(회색이에요).**
그 줄 맨 오른쪽 "승인할 수 없는 이유" 칸을 읽어 보세요. "차단 판정이라 승인할 수 없습니다." / "엄격 모드(건강·금융 등)에서는 통과 판정만 승인할 수 있습니다." / "이미 승인된 제안입니다." 중 하나입니다. 차단이면 영상 상세에서 [제목 수정]으로 고치거나 [반려]하세요. 이미 50건을 골랐다면 "최대 50건까지만 고를 수 있습니다…" 가 나오며, 하나를 해제하면 다른 것을 고를 수 있습니다.

**Q. 영상 ID를 넣고 [찾기]를 눌렀더니 "없음 (이 영상은 목록에 없습니다)"이라고 나와요.**
이 프로그램에 없는 영상 ID입니다. ID는 11자입니다. 글자 하나 틀렸거나, 아직 영상을 불러오지 않았거나, 다른 채널 영상일 수 있습니다. 영상 목록에서 ID를 복사해 다시 붙여 넣으세요. 11자 형식이 아니면 "형식이 맞지 않아 찾지 않은 ID: …" 가 나옵니다.

**Q. 후보 제안이 여러 개라고 해요. 어느 걸 골라야 하나요?**
같은 영상에 AI 제안이 여러 개 있으면 프로그램이 대신 고르지 않습니다. 상태 칸의 "선택 필요" 아래에서 마음에 드는 새 제목 하나를 동그라미로 고르세요. 고르지 않으면 승인 대기 목록에 들어가지 않습니다. 한 영상은 한 번에 제안 1개만 승인됩니다.

**Q. 승인했는데 배치에서 안 보여요 / "승인 만료"가 됐어요.**
승인은 일정 시간(기본 24시간) 안에 배치를 만들어 실행해야 하며, 지나면 만료됩니다. 영상 상세나 이 화면에서 다시 승인하세요. 이미 다른 초안 배치에 담긴 제안은 배치 화면에 "초안 배치 #번호에 있음" 으로 표시됩니다(`WEB_USER_MANUAL.md` 4-4). 제외 사유에 "지금 상태에서는 승인할 수 없습니다(이미 승인됨, 만료, 반려, 배치에 담김 등)…" 가 나왔다면 상태를 확인하세요.

**Q. [N건 승인] 버튼이 안 눌려요.**
버튼 아래 "아직 필요한 것" 칸을 보세요. 보통 ① "승인자 이름을 입력해 주세요." ② "경고가 있는 N건은 건별로 확인란을 선택해야 합니다." 입니다. 경고 건은 줄마다 "이 제안의 경고 내용을 읽었고 승인합니다: …" 를 직접 체크해야 하며 전체 체크는 없습니다.

**Q. 결과에 "제외된 N건"이 있어요. 잘못된 건가요?**
아닙니다. 제외된 건은 아무것도 바뀌지 않았고, 나머지는 정상 승인됐습니다. "제외 사유" 칸 문구의 뜻은 `WEB_USER_MANUAL.md` 4-8장 표를 보세요. 예: "경고 확인 체크가 없어 승인하지 않았습니다." → 다시 고르고 체크. "같은 영상의 다른 제안이 먼저 처리되었습니다." → 한 번에 영상당 1개만 처리되니 나머지는 다시 승인.

**Q. 한 번에 몇 건까지 되나요?**
최대 50건입니다(배치 한 번에 50건과 같은 숫자). 영상 ID 찾기도 한 번에 50개까지입니다.

기본은 바꾸지 않습니다(쇼츠는 제목보다 영상·설명으로 노출되고, 길이로만 판별해 오분류될 수 있어서입니다). 바꾸려면 `web\.env` 파일에 `YTWEB_INCLUDE_SHORTS=1` 줄을 넣고(없으면 `.env.example` 참고), `.\web\scripts\start.ps1` 을 다시 실행한 뒤, 홈의 **[내 영상 불러오기]** 를 한 번 눌러 영상 목록을 새로 고치세요. 쇼츠의 "제외" 표시가 풀립니다. 비공개·어린이용·예약 라이브 영상은 계속 제외됩니다. 실제 모드에서는 쇼츠도 수정 허용 영상 목록(`YTWEB_LIVE_ALLOWED_VIDEOS`)에 있어야 바뀝니다. 끄려면 값을 `0` 으로 바꾸고 같은 방법으로 다시 시작하세요.
