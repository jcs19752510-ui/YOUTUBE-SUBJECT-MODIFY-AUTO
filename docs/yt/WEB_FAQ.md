# 유튜브 제목 웹 자주 묻는 질문(FAQ) — 막혔을 때 보는 곳

> **먼저 알아 두세요: 지금은 데모 모드입니다.** 영상 200개는 가짜 연습용이고, 유튜브와 AI 서비스에는 아무것도 전송되지 않으며, **실제 유튜브 제목은 절대 바뀌지 않습니다.** 실제 구글·AI 연결은 이후 단계에서 별도 승인 후 추가됩니다. `[확인 필요]` 는 아직 직접 확인하지 못했다는 뜻입니다.

기준: 오류 코드 표는 실제 백엔드 코드(`ProblemError`·`StepFailure` 호출)와 `docs/yt/API.md` 를 2026-10-11에 대조했고, 일부는 클라우드 임시 서버(가짜 데이터)에서 직접 일으켜 확인했습니다. 화면 문구는 `ko.ts` 와 화면 소스 기준입니다. "내 PC에서 확인 필요"는 선생님 PC(Windows)에서만 확인할 수 있다는 뜻입니다. 쓰는 법은 `WEB_USER_MANUAL.md`, 설치는 `WEB_INSTALL.md`, 운영은 `WEB_RUNBOOK.md` 입니다.

**오류가 나면 이렇게 하세요**
1. 화면 빨간(또는 노란) 상자의 **제목, 상세, "다음에 할 일", "오류 코드"** 를 읽습니다.
2. 아래 3장에서 오류 코드를 찾습니다. 코드는 영어 소문자와 밑줄(`_`)로 되어 있습니다.
3. 그래도 모르겠으면 코드와 상황을 메모해 운영 담당(문의처 **미정**)에게 전하세요. 비밀번호·PIN은 알리지 마세요.

## 1. "왜 안 바뀌나요?" 모음

**Q1. 제목을 바꿨는데 유튜브(진짜 내 채널)에서는 그대로예요.**
정상입니다. 지금은 데모 모드라 가짜 영상의 제목만 바뀝니다. 유튜브에는 아무것도 전송되지 않습니다.

**Q2. [승인] 버튼이 눌리지 않아요.**
- 검증이 **차단(✕)** 이면 승인할 수 없습니다.
- 승인자 이름을 비워 두면 안 됩니다.
- 영상이 **제외** 대상(비공개·아동용·예약 게시·쇼츠)이면 안 됩니다.
- 상태가 이미 "승인됨/반영 대기/반영 완료/반려됨"이면 승인 버튼이 없습니다.
- 검증이 **차단(✕)** 이면서 상태 칸에 영어 `blocked` 가 보이는 카드는 [제목 수정]·[승인]·[반려] 버튼이 **아예 나타나지 않습니다**(화면의 알려진 한계, 아래 Q17).
- 경고(▲)인 경우 "경고 사유를 모두 읽고 확인했습니다." 를 체크해야 눌립니다.
- 건강·금융 주제(엄격 모드)는 경고만 있어도 차단으로 처리되어 승인되지 않습니다.

**Q3. 영상 앞 체크 네모가 눌리지 않아요.**
제외된 영상입니다("제외" 표시와 사유가 있음). 제외 영상은 제안·승인·배치·반영 모두에서 막힙니다.

**Q4. [AI 제안 만들기]가 눌리지 않거나 오류가 나요.**
제외 영상이면 눌리지 않습니다(`video_excluded`). 같은 제목이 이미 있으면 새로 만들지 않고 기존 제안을 보여 줍니다. 제안 개수는 1~5개만 가능합니다(`count_invalid`).

**Q5. 배치에서 [사전 점검 만들기]가 눌리지 않아요.**
선택이 0개이거나 51건 이상이면 눌리지 않습니다(한 배치 최대 50건). 승인된 제안만 목록에 나옵니다. 목록이 비어 있으면 영상 상세에서 먼저 승인하세요.

**Q6. [실행] 버튼이 안 눌려요.**
"실행 확인" 칸에 화면의 빨간 박스 문구(`실행 N건`)를 **글자 하나, 띄어쓰기 하나까지 똑같이** 입력해야 합니다. 앞뒤 공백도 틀린 것으로 봅니다. "문구가 일치합니다."가 뜨면 눌립니다.

**Q7. 실행했는데 어떤 항목은 "건너뜀"이에요.**
건너뜀은 **아무것도 바꾸지 않았다**는 뜻입니다. 사유 코드는 3-3 표를 보세요. 흔한 것은 승인 만료(24시간), 같은 영상 72시간 간격 제한, 영상당 3회 제한입니다. 하루 상한에만 걸린 항목은 건너뜀이 아니라 **다음 날로 넘어갑니다**(Q8).

**Q8. 오늘 10건만 바뀌고 나머지는 안 바뀌어요.**
정상입니다. 하루 반영 상한(기본 10건) 때문에 나머지는 **다음 날로 예약**됩니다. 날짜별 일정은 배치 상세에 나옵니다. 상한은 [설정 > 안전 설정]에서 1~20으로 바꿀 수 있습니다(낮을수록 안전).

**Q9. 어제 예약한 건이 오늘 한꺼번에 처리되지 않았어요.**
의도된 동작입니다. 프로그램(또는 PC)이 꺼져 있던 동안 놓친 날짜 분을 **몰아서 실행하지 않고**, 켜진 날의 하루 몫만 처리합니다. 예약 처리는 Docker Desktop과 프로그램이 켜져 있어야 합니다.

**Q10. 같은 영상을 다시 바꾸려는데 "한도 초과"라고 해요.**
같은 영상은 직전 변경 후 72시간(3일)이 지나야 다시 바꿀 수 있고, 영상당 최대 3회입니다. **롤백(되돌리기)도 1회로 세고 72시간이 새로 시작됩니다.** 영상 상세의 "변경 한도 상태"에 사유와 가능한 시각이 나옵니다. 3회에 도달하면 시간이 지나도 풀리지 않으며, 그때 사유에 나오는 "설정 cadence.max_changes_per_video를 바꿔야 합니다"는 개발자용 문장입니다(이 화면에서는 바꿀 수 없음). 데모에서는 "변경 후 노출수 1,000회" 기준을 적용하지 않으므로(변경 후 지표가 없기 때문) 막히는 이유는 72시간·3회·하루 상한뿐입니다. 하루 상한 문장에 "태평양 시간 기준"이라고 나오지만 실제 계산은 한국 시간 하루입니다(문구 오류, 알려진 제한).

**Q11. 승인했는데 "승인 만료"가 됐어요.**
승인은 24시간만 유효하고 한 번만 쓸 수 있습니다. 제목을 수정하거나 영상 정보가 바뀌어도 무효가 됩니다. 다시 [승인]하세요.

**Q12. 성과 리포트가 전부 "데이터 부족"이에요.**
- 변경 기록이 없으면 "변경 기록 없음".
- 데모에는 변경 **후** 성과 숫자를 만드는 부분이 없습니다(코드 확인). 그래서 제목을 바꾼 영상은 항상 "데이터 부족"(이유: "변경 후 지표가 아직 없습니다.")으로 나옵니다. 클라우드 임시 서버에서 반영 후 이 결과를 확인했습니다. 이 화면의 "비교 가능"은 데모에서 볼 수 없습니다.
- 데이터가 부족하면 일부러 결론을 내지 않습니다. 이유 목록과 "변경 후 지표 수집 예정일"을 보세요.
- 숫자가 나와도 데모의 성과는 **가짜 데이터**이고, 제목 때문이라고 단정할 수 없습니다.

**Q13. 화면에 `blocked`, `aborted`, `rolled_back` 같은 영어가 보여요.**
문구가 빠진 알려진 제한이며 동작에는 문제가 없습니다. 뜻: `blocked` = 검증에서 차단된 제안(Q17), `aborted` = 반영 도중 멈춰서 **제목은 바뀌지 않은** 기록(이력의 결과 칸), `rolled_back` = 롤백된 제안(영상 상세 카드의 상태 칸). 배치 상태는 한글(초안/실행 대기/실행 중/완료/중지됨/실패)로 나옵니다.

**Q14. 선택해 둔 영상, 적어 둔 승인자 이름이 새로고침하니 사라졌어요.**
영상 목록의 체크 선택, 승인자 이름, 진행 창은 새로고침하면 사라집니다. 검색 조건·정렬·쪽, 설정 탭, 서버에 저장된 모든 것(제안, 배치, 이력)은 그대로입니다.

**Q15. 롤백(되돌리기)이 안 돼요.**
같은 영상에 그 뒤 다른 변경(롤백 포함)이 있거나(`later_change_exists`), 이미 원래 제목이거나(`already_restored`), 처리 중인 변경이 있으면(`pending_change_exists`) 안 됩니다. 영상 ID는 **직접 똑같이** 입력해야 합니다(`typed_video_id_mismatch`).

**Q16. 실제 내 채널 영상을 불러오고 싶어요 / 진짜 AI로 제안받고 싶어요.**
아직 만들어지지 않았습니다. 구글 연결(읽기)과 AI·실제 반영은 이후 단계이며, 그 전에 선생님의 승인과 준비(구글 로그인용 설정, AI 서비스 선택 등)가 필요합니다.

**Q17. 차단(✕)된 제안에 버튼이 하나도 없어요.**
검증에서 "차단"이 나온 제안은 상태 칸에 영어 `blocked` 가 보이고 [제목 수정]·[승인]·[반려] 버튼이 나타나지 않습니다. 지금 화면의 알려진 한계입니다(고쳐야 하는 항목으로 개발 담당에게 전달됨). 그 제안은 쓰지 않으면 됩니다 — 승인도 배치 포함도 되지 않습니다. 다른 후보를 쓰거나, 설정의 "영상당 제안 개수"를 늘린 뒤 [AI 제안 만들기]를 다시 눌러 후보를 더 받으세요.

**Q18. "다른 배치에 이미 담겨 있습니다"라고 하면서 [사전 점검 만들기]가 거절돼요.**
이전에 사전 점검(초안)을 만들고 실행하지 않았거나 실행이 `precheck_stale` 로 거부됐을 때 생깁니다. 초안에 담긴 제안은 그 초안에 묶여 있어 새 배치에 쓸 수 없는데, 지금 화면에는 초안을 버리는 버튼이 없습니다(알려진 한계). 해결: 개발 담당에게 "초안 배치 #번호 취소"를 요청하세요(서버에는 초안 취소 기능이 있습니다). 가능하면 사전 점검을 만든 뒤 바로 실행해 이런 초안을 남기지 마세요.

## 2. 시작·접속 문제

| 증상 | 원인과 조치 |
|---|---|
| "Docker 엔진에 연결할 수 없습니다" | Docker Desktop을 먼저 실행하고 고래 아이콘이 안정될 때까지 1~2분 기다린 뒤 다시 `start.ps1` |
| "포트 8080 를 다른 프로그램이 이미 사용 중입니다." | 다른 프로그램이 8080을 쓰는 중. `WEB_INSTALL.md` 의 확인 방법 참고 |
| "스크립트를 실행할 수 없습니다" | 같은 PowerShell 창에서 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned` 를 먼저 실행 |
| "Docker 가 Windows 컨테이너 모드입니다." | 고래 아이콘 오른쪽 클릭 → Switch to Linux containers... |
| 브라우저에서 아예 안 열림 | 주소가 정확히 `http://127.0.0.1:8080` 인지 확인. 다른 주소(내 PC의 IP, 다른 포트)로는 열리지 않으며, 이때 오류 상자 없이 브라우저가 "연결할 수 없음"(응답 없음)으로 보이는 것이 정상입니다(서버가 연결을 바로 끊음). `localhost:8080` 은 허용됩니다 |
| 화면이 하얗게 나옴 | F12 → 콘솔에 "Content Security Policy" 오류가 있는지 보고 운영 담당에게 전달 [확인 필요: 실제 브라우저 확인 안 됨] |
| "서버 연결이 끊겼습니다" 배너 | 프로그램(api)이 꺼졌거나 Docker가 멈춘 것. Docker Desktop 확인 후 `status.ps1`, 그다음 [다시 연결]. 작성 중이던 내용은 저장되지 않았을 수 있습니다 |
| "세션이 만료되었습니다" | 12시간이 지났거나 다른 곳에서 PIN을 바꿨습니다. **PIN이 꺼져 있으면** 화면이 알아서 조용히 다시 연결합니다. **PIN이 켜져 있으면** "세션이 만료되었습니다" 창이 뜨고 PIN을 다시 입력하면 이어서 쓸 수 있습니다(이 창은 Esc로 닫히지 않습니다). [다시 연결] 버튼은 "로그아웃되었습니다" 화면과 "서버 연결이 끊겼습니다" 안내에 있습니다 |
| "PIN 이 맞지 않습니다" / `pin_locked` | 5회 연속 틀리면 5분 잠기고, 반복하면 2배씩(최대 1시간) 늘어납니다. 기다린 뒤 다시 입력. PIN 분실 시 복구 절차는 문서화되지 않았습니다 [확인 필요] |
| 컨테이너가 계속 재시작 | `.\web\scripts\logs.ps1 -Service api` (또는 db/worker/migrate)로 원인 확인 — `WEB_RUNBOOK.md` 참고 |
| PC를 껐다 켰더니 안 열림 | Docker Desktop을 실행하고 `start.ps1` 을 다시 실행. Docker Desktop은 기본적으로 로그인 때 자동 시작되지 않습니다 |

## 3. 오류 코드별 해결표

화면의 "오류 코드"와 같은 글자를 찾으세요. 이 표는 `API.md` 의 코드표를 쉬운 말로 풀었습니다. "HTTP"는 참고용 숫자이니 몰라도 됩니다.

### 3-1. 접속·보안 관련

| 오류 코드 | HTTP | 뜻 | 해결 |
|---|---|---|---|
| `host_not_allowed` | 403 | 허용되지 않은 접속 주소. 보통은 앞단(nginx)이 연결을 바로 끊어 이 코드가 화면에 나오지 않고 "연결할 수 없음"으로 보입니다 | 주소를 `http://127.0.0.1:8080` 로 열기 |
| `origin_not_allowed`, `cross_site_request` | 403 | 허용되지 않은 출처의 요청 | 다른 사이트에서 연 링크가 아닌, 위 주소를 직접 입력해 열고 새로고침 |
| `csrf_invalid`, `session_required` | 403/401 | 화면의 보안 확인값이 맞지 않음/세션 없음 | 화면 새로고침(F5). 계속되면 [로그아웃] 후 [다시 연결] |
| `pin_invalid` | 401/422 | PIN이 틀렸거나 형식이 틀림(숫자 4~12자리) | PIN 다시 확인 |
| `pin_locked` | 429 | PIN 5회 연속 실패로 잠김 | 안내된 시간(몇 분~최대 1시간) 후 재시도 |
| `pin_not_set` | 409 | PIN이 없는데 해제하려 함 | 해제할 필요 없음 |
| `rate_limited` | 429 | 요청이 너무 많음(앞단 nginx는 초당 30건, 세션 발급은 분당 10건, 프로그램 안에서는 전체 분당 600건·쓰기 분당 120건 제한) | 안내된 초만큼 기다린 뒤 한 번만 다시. 같은 버튼을 연타하지 마세요 |
| `payload_too_large` | 413 | 보내는 내용이 너무 큼(1MB 초과) | 메모·제목을 줄이기 |
| `bad_content_length` | 400 | 요청 크기 표시가 잘못됨(사람이 화면에서 일으키기 어려움) | 화면 새로고침. 계속되면 운영 담당에게 코드 전달 |
| `not_found`, `method_not_allowed` | 404/405 | 없는 주소/허용되지 않는 방식 | 화면의 메뉴로 이동. 계속되면 코드 전달 |
| `internal_error` | 500 | 서버 내부 오류(자세한 내용은 로그에만 남음) | 잠시 후 한 번 다시. 계속되면 `logs.ps1 -Service api` 결과와 함께 운영 담당에게 전달 |
| `setting_not_allowed` | 400 | 화면에서 바꿀 수 없는 설정 | 의도된 제한입니다. 실제 반영(라이브)·허용 영상은 화면에서 바꿀 수 없습니다 |
| `validation_error` | 422 | 입력 형식·범위가 맞지 않음 | 안내된 범위(예: 하루 상한 1~20)로 입력 |
| `idempotency_key_required`, `idempotency_key_invalid`, `idempotency_key_reuse`, `idempotency_in_progress` | 400/422/409 | 중복 요청 방지 값 문제 | 화면 새로고침 후 다시 시도. `idempotency_in_progress` 는 처리 중이니 잠시 후 같은 동작을 한 번만 다시 |
| `network_error` / 503 "서버가 아직 준비 중" | - | 서버에 연결 못 함/시작 중 | 1~2분 후 [다시 시도], 계속되면 `status.ps1` |

## 4. 데이터·백업 관련

**Q. 데이터가 사라졌어요.** 가장 흔한 원인은 `docker compose down -v`, Docker Desktop "Clean / Purge data", `docker system prune --volumes`, 또는 `reset-demo.ps1` 입니다. `web\backups` 에 백업이 있으면 `WEB_RUNBOOK.md` 의 복원 절차를 따르세요. 백업을 만든 적이 없다면 되살릴 방법이 없습니다.

**Q. 백업은 어떻게 하나요?** `.\web\scripts\backup.ps1` (자동 백업은 없습니다). 백업 파일은 암호화되지 않았으니 남에게 주지 마세요.

**Q. 감사 로그에 "기록이 변조되었을 수 있습니다"가 떠요.** 기록이 중간에서 바뀌거나 지워진 신호입니다. 예전 안내에는 "새 PC로 옮겨 복원하면 나올 수 있다"고 되어 있었으나, 코드를 확인한 결과 감사 기록은 키 없는 해시 연결이라 복원만으로는 어긋나지 않는 것이 설계입니다(복원 후 실제 표시는 내 PC에서 확인 필요). 새 PC로 복원할 때 실제로 생기는 일은 **기존 승인이 모두 무효가 되어 다시 승인해야 한다**는 것입니다. 직접 고치려 하지 말고 `WEB_RUNBOOK.md` 의 점검 절차를 따르거나 운영 담당에게 알리세요.
