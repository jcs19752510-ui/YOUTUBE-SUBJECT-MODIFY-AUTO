2. 아래 3장에서 오류 코드를 찾습니다. 코드는 영어 소문자와 밑줄(`_`)로 되어 있습니다.
3. 그래도 모르겠으면 코드와 상황을 메모해 운영 담당(문의처 **미정**)에게 전하세요. 비밀번호·PIN은 알리지 마세요.

## 1. "왜 안 바뀌나요?" 모음

**Q1. 제목을 바꿨는데 유튜브(진짜 내 채널)에서는 그대로예요.**
정상입니다. 지금은 데모 모드라 가짜 영상의 제목만 바뀝니다. 유튜브에는 아무것도 전송되지 않습니다.

**Q2. [승인] 버튼이 눌리지 않아요.**
- 검증이 **차단(✕)** 이면 승인할 수 없습니다. [제목 수정]으로 고쳐 다시 검증하거나 [반려]하세요.
- 승인자 이름을 비워 두면 안 됩니다.
- 영상이 **제외** 대상(비공개·아동용·예약 게시·쇼츠)이면 안 됩니다.
- 상태가 이미 "승인됨/반영 대기/반영 완료/반려됨"이면 승인 버튼이 없습니다.
- 경고(▲)인 경우 "경고 사유를 모두 읽고 확인했습니다." 를 체크해야 눌립니다.
- 건강·금융 주제(엄격 모드)는 경고만 있어도 차단으로 처리되어 승인되지 않습니다.

**Q3. 영상 앞 체크 네모가 눌리지 않아요.**
제외된 영상입니다("제외" 표시와 사유가 있음). 제외 영상은 제안·승인·배치·반영 모두에서 막힙니다.

**Q4. [AI 제안 만들기]가 눌리지 않거나 오류가 나요.**
제외 영상이면 눌리지 않습니다(`video_excluded`). 같은 제목이 이미 있으면 새로 만들지 않고 기존 제안을 보여 줍니다. 제안 개수는 1~5개만 가능합니다(`count_invalid`).

**Q5. 배치에서 [사전 점검 만들기]가 눌리지 않아요.**
선택이 0개이거나 51건 이상이면 눌리지 않습니다(한 배치 최대 50건). 승인된 제안만 목록에 나옵니다. 목록이 비어 있으면 영상 상세에서 먼저 승인하세요.

**Q6. [실행] 버튼이 안 눌려요.**
"실행 확인" 칸에 화면의 빨간 박스 문구(`실행 N건`)를 **글자 하나, 띄어쓰기 하나까지 똑같이** 입력해야 합니다. 앞뒤 공백도 틀린 것으로 봅니다. "문구가 일치합니다."가 뜨면 눌립니다.

**Q7. 실행했는데 어떤 항목은 "건너뜀"이에요.**
건너뜀은 **아무것도 바꾸지 않았다**는 뜻입니다. 사유 코드는 3-3 표를 보세요. 가장 흔한 것은 하루 상한 도달, 승인 만료, 같은 영상 72시간 간격 제한입니다.

**Q8. 오늘 10건만 바뀌고 나머지는 안 바뀌어요.**
정상입니다. 하루 반영 상한(기본 10건) 때문에 나머지는 **다음 날로 예약**됩니다. 날짜별 일정은 배치 상세에 나옵니다. 상한은 [설정 > 안전 설정]에서 1~20으로 바꿀 수 있습니다(낮을수록 안전).

**Q9. 어제 예약한 건이 오늘 한꺼번에 처리되지 않았어요.**
의도된 동작입니다. 프로그램(또는 PC)이 꺼져 있던 동안 놓친 날짜 분을 **몰아서 실행하지 않고**, 켜진 날의 하루 몫만 처리합니다. 예약 처리는 Docker Desktop과 프로그램이 켜져 있어야 합니다.

**Q10. 같은 영상을 다시 바꾸려는데 "한도 초과"라고 해요.**
같은 영상은 72시간(3일)이 지나야 다시 바꿀 수 있고, 영상당 최대 3회이며, 노출수 최소 기준도 있습니다. 영상 상세의 "변경 한도 상태"에 사유와 가능한 시각이 나옵니다. 데모에서는 노출수 기준 때문에 재변경이 막혀 시연이 안 될 수 있습니다(알려진 제한, 고칠지는 결정 대기).

**Q11. 승인했는데 "승인 만료"가 됐어요.**
승인은 24시간만 유효하고 한 번만 쓸 수 있습니다. 제목을 수정하거나 영상 정보가 바뀌어도 무효가 됩니다. 다시 [승인]하세요.

**Q12. 성과 리포트가 전부 "데이터 부족"이에요.**
- 변경 기록이 없으면 "변경 기록 없음".
- 데모에서는 변경 **후** 성과 데이터를 만드는 부분이 코드에서 확인되지 않아, 바꾼 직후 리포트는 "데이터 부족"일 가능성이 높습니다 [확인 필요: 화면에서 직접 확인 못 함].
- 데이터가 부족하면 일부러 결론을 내지 않습니다. 이유 목록과 "변경 후 지표 수집 예정일"을 보세요.
- 숫자가 나와도 데모의 성과는 **가짜 데이터**이고, 제목 때문이라고 단정할 수 없습니다.

**Q13. 배치 상태에 `queued` 라는 영어가 보여요.**
"실행이 확정되어 대기 중"이라는 뜻입니다. 화면 문구가 빠진 알려진 제한이며 동작에는 문제가 없습니다.

**Q14. 선택해 둔 영상, 적어 둔 승인자 이름이 새로고침하니 사라졌어요.**
영상 목록의 체크 선택, 승인자 이름, 진행 창은 새로고침하면 사라집니다. 검색 조건·정렬·쪽, 설정 탭, 서버에 저장된 모든 것(제안, 배치, 이력)은 그대로입니다.

**Q15. 롤백(되돌리기)이 안 돼요.**
같은 영상에 그 뒤 다른 변경이 있거나(`later_change_exists`), 이미 원래 제목이거나(`already_restored`), 처리 중인 변경이 있으면(`pending_change_exists`) 안 됩니다. 영상 ID는 **직접 똑같이** 입력해야 합니다(`typed_video_id_mismatch`).

**Q16. 실제 내 채널 영상을 불러오고 싶어요 / 진짜 AI로 제안받고 싶어요.**
아직 만들어지지 않았습니다. 구글 연결(읽기)과 AI·실제 반영은 이후 단계이며, 그 전에 선생님의 승인과 준비(구글 로그인용 설정, AI 서비스 선택 등)가 필요합니다.

## 2. 시작·접속 문제

| 증상 | 원인과 조치 |
|---|---|
| "Docker 엔진에 연결할 수 없습니다" | Docker Desktop을 먼저 실행하고 고래 아이콘이 안정될 때까지 1~2분 기다린 뒤 다시 `start.ps1` |
| "포트 8080 사용 중" | 다른 프로그램이 8080을 쓰는 중. `WEB_INSTALL.md` 의 확인 방법 참고 |
| "스크립트를 실행할 수 없습니다" | 같은 PowerShell 창에서 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned` 를 먼저 실행 |
| "Windows 컨테이너 모드" 오류 | 고래 아이콘 오른쪽 클릭 → Switch to Linux containers |
| 브라우저에서 아예 안 열림 | 주소가 정확히 `http://127.0.0.1:8080` 인지 확인. 다른 주소(내 PC의 IP, 다른 포트)로는 열리지 않습니다. `localhost:8080` 은 허용됩니다 |
| 화면이 하얗게 나옴 | F12 → 콘솔에 "Content Security Policy" 오류가 있는지 보고 운영 담당에게 전달 [확인 필요: 실제 브라우저 확인 안 됨] |
| "서버 연결이 끊겼습니다" 배너 | 프로그램(api)이 꺼졌거나 Docker가 멈춘 것. Docker Desktop 확인 후 `status.ps1`, 그다음 [다시 연결]. 작성 중이던 내용은 저장되지 않았을 수 있습니다 |
| "세션이 만료되었습니다" | 12시간이 지났거나 다른 곳에서 PIN을 바꿨습니다. PIN을 다시 입력하거나 [다시 연결]을 누르세요 |
| "PIN 이 맞지 않습니다" / `pin_locked` | 5회 연속 틀리면 5분 잠기고, 반복하면 2배씩(최대 1시간) 늘어납니다. 기다린 뒤 다시 입력. PIN 분실 시 복구 절차는 문서화되지 않았습니다 [확인 필요] |
| 컨테이너가 계속 재시작 | `.\web\scripts\logs.ps1 -Service api` (또는 db/worker/migrate)로 원인 확인 — `WEB_RUNBOOK.md` 참고 |
| PC를 껐다 켰더니 안 열림 | Docker Desktop을 실행하고 `start.ps1` 을 다시 실행. Docker Desktop은 기본적으로 로그인 때 자동 시작되지 않습니다 |

## 3. 오류 코드별 해결표

화면의 "오류 코드"와 같은 글자를 찾으세요. 이 표는 `API.md` 의 코드표를 쉬운 말로 풀었습니다. "HTTP"는 참고용 숫자이니 몰라도 됩니다.

### 3-1. 접속·보안 관련

| 오류 코드 | HTTP | 뜻 | 해결 |
|---|---|---|---|
| `host_not_allowed` | 403 | 허용되지 않은 접속 주소 | 주소를 `http://127.0.0.1:8080` 로 열기 |
| `origin_not_allowed`, `cross_site_request` | 403 | 허용되지 않은 출처의 요청 | 다른 사이트에서 연 링크가 아닌, 위 주소를 직접 입력해 열고 새로고침 |
| `csrf_invalid`, `session_required` | 403/401 | 화면의 보안 확인값이 맞지 않음/세션 없음 | 화면 새로고침(F5). 계속되면 [로그아웃] 후 [다시 연결] |
| `pin_invalid` | 401/422 | PIN이 틀렸거나 형식이 틀림(숫자 4~12자리) | PIN 다시 확인 |
| `pin_locked` | 429 | PIN 5회 연속 실패로 잠김 | 안내된 시간(몇 분~최대 1시간) 후 재시도 |
| `pin_not_set` | 409 | PIN이 없는데 해제하려 함 | 해제할 필요 없음 |
| `rate_limited` | 429 | 요청이 너무 많음 | 안내된 초만큼 기다린 뒤 한 번만 다시. 같은 버튼을 연타하지 마세요 |
| `payload_too_large` | 413 | 보내는 내용이 너무 큼(1MB 초과) | 메모·제목을 줄이기 |
| `setting_not_allowed` | 400 | 화면에서 바꿀 수 없는 설정 | 의도된 제한입니다. 실제 반영(라이브)·허용 영상은 화면에서 바꿀 수 없습니다 |
| `validation_error` | 422 | 입력 형식·범위가 맞지 않음 | 안내된 범위(예: 하루 상한 1~20)로 입력 |
| `idempotency_key_required`, `idempotency_key_invalid`, `idempotency_key_reuse`, `idempotency_in_progress` | 400/422/409 | 중복 요청 방지 값 문제 | 화면 새로고침 후 다시 시도. `idempotency_in_progress` 는 처리 중이니 잠시 후 같은 동작을 한 번만 다시 |
| `network_error` / 503 "서버가 아직 준비 중" | - | 서버에 연결 못 함/시작 중 | 1~2분 후 [다시 시도], 계속되면 `status.ps1` |

### 3-2. 영상·제안·승인 관련

| 오류 코드 | 뜻 | 해결 |
|---|---|---|
| `video_not_found` | 그 영상이 없음 | 영상 목록에서 다시 선택. 영상을 아직 불러오지 않았다면 홈에서 [데모 영상 불러오기] |
| `video_excluded` | 제외 대상 영상(비공개·아동용·예약·쇼츠) | 다른 영상을 고르세요. 제외 영상은 바꿀 수 없습니다 |
| `video_inconsistent` | 저장된 영상 정보가 맞지 않음 | 홈에서 [데모 영상 불러오기]로 새로고침 후 다시 |
| `count_invalid` | 제안 개수가 1~5가 아님 | 1~5로 |
| `ai_unavailable`, `ai_no_candidates` | 제안기 장애/쓸 만한 후보 없음 | 잠시 후 다시. 데모의 모의 AI에서는 보통 나오지 않습니다 |
| `suggestion_not_found` | 제안이 없음 | 영상 상세를 새로고침 |
| `suggestion_blocked` | 차단 판정(또는 엄격 모드 경고)이라 승인 불가 | [제목 수정]으로 고쳐 다시 검증하거나 [반려] |
| `suggestion_state` | 지금 상태에서는 그 동작을 할 수 없음(예: 이미 배치에 담김, 이미 반영됨) | 상태를 새로고침해 확인. 배치에 담긴 제안은 배치를 먼저 중지해야 반려·수정됩니다 |
| `same_as_current` | 새 제목이 현재 제목과 같음 | 다른 제목으로 수정 |
| `duplicate_suggestion` | 같은 제목의 제안이 이미 있음/같은 제안을 두 번 선택 | 기존 제안을 사용 |
| `title_empty`, `title_too_long`, `title_invalid` | 제목이 비었음/너무 김(화면 한도 100자, 서버 300자)/쓸 수 없는 문자 | 제목 다듬기 |
| `approver_required`, `approver_invalid` | 승인자 이름이 비었음/형식 오류(1~40자, 제어문자 불가) | 이름을 정확히 입력 |

### 3-3. 배치·실행 관련

| 오류 코드 | 뜻 | 해결 |
|---|---|---|
| `batch_empty` | 담을 수 있는 제안이 하나도 없음 | 승인된 제안을 고르세요. 이미 다른 배치에 있거나 만료된 것은 제외됩니다 |
| `batch_too_large` | 50건 초과 | 선택을 줄이기 |
| `already_in_batch` | 방금 다른 배치가 먼저 담음 | 목록 새로고침 후 다시 |
| `schedule_overflow` | 예약 가능한 날짜 범위(400일) 초과 | 건수를 줄이기 |
| `batch_not_found` | 배치 번호가 없음 | 배치 목록에서 다시 열기 |
| `batch_not_draft` | 이미 실행했거나 취소된 배치 | 새 배치를 만드세요 |
| `batch_not_cancellable` | 이미 끝났거나 취소된 배치라 중지 불가 | 필요 없음 |
| `confirm_text_mismatch` | 확인 문구 불일치 | 화면에 표시된 `실행 N건` 을 그대로 입력 |
| `precheck_stale` | 사전 점검 이후 상태가 바뀜(승인 만료·한도·제외) | 배치를 중지(취소)하고 **새로 만들기** |
| `job_not_found`, `no_handler` | 작업을 찾을 수 없음/처리기 없음 | 새로고침. 계속되면 운영 담당에게 코드 전달 |

**배치 항목이 "건너뜀"일 때의 사유 코드** (`[코드] 사유` 형식으로 표시. 건너뜀 = 아무것도 안 바뀜)

| 코드 | 쉬운 뜻 |
|---|---|
| `approval_missing` / `approval_expired` / `approval_used` / `approval_tampered` | 승인이 없음 / 24시간이 지남 / 이미 사용함 / 승인 내용이 맞지 않음 → 다시 승인 |
| `plan_mismatch`, `title_changed`, `video_changed` | 승인 후 제목이나 영상 정보가 바뀜 → 다시 제안·승인 |
| `suggestion_state`, `suggestion_blocked`, `suggestion_missing` | 제안 상태가 맞지 않음/차단됨/없어짐 |
| `title_invalid`, `same_as_current` | 제목이 규칙에 맞지 않음/현재와 같음 |
| `video_excluded` | 제외 대상 영상 |
| `pending_change_exists` | 그 영상에 처리 중인 변경이 있음 |
| `limit_interval` / `limit_count` / `limit_impressions` / `limit_daily` | 72시간 간격 / 영상당 횟수 / 최소 노출수 / 하루 상한에 걸림 |
| `quota_exhausted` | 오늘 구글 사용량이 소진됨 (태평양 시간 자정에 초기화) |
| `batch_not_active`, `cancelled` | 배치가 더는 진행 중이 아님/사용자가 중지함 |

**배치 항목이 "실패"일 때** (시도했으나 실패)

| 코드 | 쉬운 뜻 | 조치 |
|---|---|---|
| `read_failed`, `video_not_found`, `snippet_invalid`, `body_invalid`, `update_failed`, `internal_error` | 읽기·변경 중 오류 | 이력에서 상태를 확인하고 필요하면 새로 배치 |
| `result_unknown` | **반영됐을 수도 있음** | 이력·영상 상세에서 현재 제목을 확인(실제 연동 시에는 Studio에서 확인) |
| `verify_failed` | 제목은 바뀌었지만 다른 항목 확인이 맞지 않음. 변경은 성공으로 남고 롤백 가능 | 이력에서 확인 후 필요하면 롤백 |
| `interrupted` | 프로그램이 중간에 멈춰 복구됨. 제목은 바뀌지 않음을 확인함 | 필요하면 다시 배치 |

### 3-4. 이력·롤백·리포트

| 오류 코드 | 뜻 | 해결 |
|---|---|---|
| `change_not_found` | 변경 기록이 없음 | 이력 새로고침 |
| `not_rollbackable` | 성공한 "반영"만 되돌릴 수 있음 | 해당 없음 |
| `later_change_exists` | 그 뒤에 같은 영상이 또 바뀜 | 가장 최근 변경부터 되돌려야 하는지 확인 |
| `already_restored` | 이미 원래 제목 | 필요 없음 |
| `backup_invalid` | 되돌릴 백업이 맞지 않음 | 운영 담당에게 코드 전달 |
| `typed_video_id_mismatch` | 입력한 영상 ID가 다름 | 영상 ID를 화면 그대로 다시 입력 |
| `quota_exhausted` (롤백 중) | 오늘 사용량 부족 | 미국 태평양 시간 자정 이후 다시 (한국 시간 환산은 [확인 필요]) |
| `gateway_error` | 재조회·갱신 실패 | 이력에서 결과 확인("예정"이 남을 수 있음) 후 운영 담당에게 문의 |

> 화면에 위 표에 없는 코드가 나오면 지어내서 해석하지 마시고 코드와 상황을 운영 담당에게 알려 주세요. 새 코드가 생겼을 수 있습니다.

## 4. 데이터·백업 관련

**Q. 데이터가 사라졌어요.** 가장 흔한 원인은 `docker compose down -v`, Docker Desktop "Clean / Purge data", `docker system prune --volumes`, 또는 `reset-demo.ps1` 입니다. `web\backups` 에 백업이 있으면 `WEB_RUNBOOK.md` 의 복원 절차를 따르세요. 백업을 만든 적이 없다면 되살릴 방법이 없습니다.

**Q. 백업은 어떻게 하나요?** `.\web\scripts\backup.ps1` (자동 백업은 없습니다). 백업 파일은 암호화되지 않았으니 남에게 주지 마세요.

**Q. 감사 로그에 "기록이 변조되었을 수 있습니다"가 떠요.** 기록이 중간에서 바뀌거나 지워진 신호입니다. 새 PC로 옮겨 복원한 경우에도 나올 수 있다고 안내되어 있습니다(알려진 제한). 직접 고치려 하지 말고 `WEB_RUNBOOK.md` 의 점검 절차를 따르거나 운영 담당에게 알리세요.
