# 04 UX 설계서 — CLI 사용 경험 + 웹 UI as-built (하네스 4단계)

- 입력: `02_planning.md`(v4), `DESIGN.md`(v0) / 웹 장(Part B)은 추가로 구현물 `web/frontend/src/**`, `docs/harness/units/web-WU-FE-note.md`, `웹프로그램으로수정요청.md` §6·§8, `docs/yt/WEB_DESIGN.md` §6, 백엔드 `web/backend/ytweb/**`(상태 값·문구 확인용, 읽기만)
- **문서 구성**: **Part A(§1~§7)는 CLI UX 원문을 보존**한다(추적표가 `04_ux 1`, `04_ux 2` 절 번호를 참조하므로 번호를 바꾸지 않았다). **Part B(§W1~§W12)는 웹 전환(DEC-032~038)의 UX를 구현 결과(as-built) 기준으로 새로 쓴 것**이며 ID는 충돌을 피하려고 `UX-1xx`/`SCR-1xx`를 쓴다. §8 변경 이력은 두 파트 공통이다. CLI는 DEC-034 Q-4에 따라 회귀·비상용으로 유지되므로 Part A는 폐기하지 않는다.
- (Part A) 이 프로그램은 **화면 UI가 없는 CLI**다. 하네스의 "화면(`SCR-xxx`)"은 **터미널 출력 한 덩어리**로 읽는다. 사용자는 초보 개발자 1인, 환경은 Windows + PowerShell이다.
- 원칙: ①쉬운 한국어 ②색에만 의존하지 않기 ③위험한 동작은 한 번 더 확인 ④오류는 "무엇이/왜/다음에 할 일" 순서 ⑤법률 자문 아님 문구(POL-002)

## W4. 데모 모드 상시 표시와 용어 규칙
1. **데모 모드 표시** [AB]: 앱 셸 모든 화면 상단바에 "● 데모 모드 — 유튜브에 아무것도 전송되지 않습니다"(노란 배경+굵은 테두리+● 기호+글자). 홈 "연결 상태", 설정 "세션·연결"에서도 반복한다. 한계: 고정 문구라 서버 `mode`와 연동되지 않음(§W11).
2. **dry-run → "미리보기"** [AB]: 화면에는 `dry-run`을 쓰지 않는다(정적 테스트가 `i18n` 파일에서 검사, TC-WF-084). 사용처: 배치 상세 카드 제목 "사전 점검(미리보기)". "모의 실행"은 CLI 용어이므로 웹에서는 쓰지 않는다(UI 이상 6건 중 "읽기·승인 명령이 모의 실행으로 표시"는 CLI 전용).
3. **용어표(현행)**: 제안(AI 제목 후보) / 검증(통과·경고·차단) / 엄격 모드 / 승인·반려 / 승인자 / **배치(일괄 반영)** / **사전 점검** / 반영(제목 변경 적용) / 롤백(되돌림) / 제외(영상) / 남은 API 사용량(쿼터) / 감사 로그. 개발 용어가 섞인 곳: "서버(api)가 꺼져 있거나…"(`ko.conn.offlineBody`), "PIN", 작업 유형 코드(V-07), 감사 동작 코드(V-09), `queued`(V-01). 톤 확정은 Q-UX-2.

## W5. 한국어 문구 관리 규칙 (`web/frontend/src/i18n/ko.ts`, F-08)
1. **화면에 보이는 모든 한국어 문구는 `ko.ts` 한 파일에 둔다.** 숫자·이름을 끼워 넣는 문구는 함수로 쓴다(예: `ko.home.todoReview(n)`). 상태 값 → 라벨은 객체 맵(`ko.workflow`, `ko.batchStatus` …)+`lib/labels.ts`의 조회 함수(**맵에 없으면 영문 코드가 그대로 노출**되므로 서버가 새 상태 값을 추가하면 맵도 같이 추가한다 — V-01이 그 사례).
2. **오류 문구 우선순위** [AB `ErrorPanel.tsx`]: 서버 problem+json의 `detail`/`hint`(한국어) → `ko.errors[code]` → `http_NNN` 기본 문구 → `ko.state.defaultHint`. 제목은 연결 끊김/세션 만료/한도 초과일 때 `ko.state.*` 고정 문구, 그 외는 서버 `title`. 오류 블록 모양은 항상 "제목 → 상세 → 다음에 할 일 → 오류 코드"(CLI SCR-009 형식 이식).
3. **금지**: 컴포넌트 안에 한글 리터럴 직접 쓰기(현재 예외 V-05), `dry-run` 표기, 외부 문자열(영상 제목·AI 응답)을 HTML로 삽입(텍스트로만 렌더링, `dangerouslySetInnerHTML` 금지·ESLint+정적 테스트).
4. **서식**: 숫자 `ko-KR` 천 단위 쉼표, 날짜 `YYYY-MM-DD`·시각 `YYYY-MM-DD HH:MM`(**한국 시간 고정**, `lib/format.ts`), API 사용량 기준일은 "(태평양 시간)" 병기, 영상 길이 `m:ss`, 글자 수는 코드포인트 기준.
5. **어조(현행)**: 존댓말, 짧은 문장, "~합니다/~해 주세요". 확정은 Q-UX-2.
6. **i18n 필요 여부**: **해당 없음(사유: 사용자 1인, 한국어 전용, 02 타깃 사용자 기준)**. 단 F-08 "이후 번역 가능하게 문구 한곳 관리"를 충족하려고 `ko.ts` 구조를 쓴다. 번역을 추가하게 되면 ①텍스트 길이 가변성(버튼은 `nowrap`, 배지 `nowrap`이라 긴 번역에서 가로 넘침 위험, 표는 가로 스크롤 래퍼 있음) ②날짜·통화 표기(현재 `ko-KR`+KST 고정)를 다시 설계해야 한다. 통화 표시는 이 제품에 없다.

### W9-1. 디자인 자산 관리
- **토큰↔코드 연결**: `web/frontend/src/styles/tokens.css`가 단일 원본, `styles/index.css`가 import 순서(tokens→base→components→layout). 디자인 도구 파일 없음(코드가 원본).
- **아이콘**: 이미지·아이콘 폰트 없음. 유니코드 기호(✓ ▲ ✕ ● ○ ⓘ ⊘ – ↕ ↓ ←)를 텍스트로 사용 → 별도 라이선스 없음. 기호가 일부 폰트에서 다른 모양으로 보일 수 있음(미확인).
- **폰트**: 사용자 OS의 시스템 글꼴만 사용(번들 없음, 원격 폰트·CDN 금지 F-04, 정적 테스트 TC-WF-083). 라이선스 해당 없음(사유: 파일 배포 없음).
- **이미지**: 영상 썸네일 없음(CDN 금지·데모 데이터에 없음). 파비콘 `public/favicon.svg`는 단색 도형만으로 된 자체 제작 SVG로 읽히나 제작자 확인 기록은 없다.
- **다크 모드**: 현재 OS 설정 자동 추종 구현됨. 필요/불필요 결정은 사용자 확인 대기 → Q-UX-1(근거: 사용자 1인, 사용 환경·시간대 미상).
- **사용성 확인 계획(8단계 UAT 연결)**: 5~8명 과업 테스트는 **불가**(사용자 1인). 대체: 채널 소유자 1인이 자기 PC에서 `web/scripts/start.ps1`로 기동한 뒤 아래 과업을 수행하고 **막힌 지점·걸린 시간·헷갈린 문구**를 기록한다(관찰자 없이 화면 녹화 또는 메모). ①데모 영상 불러오기 ②영상 3개 골라 제안 생성 ③경고 제안 승인(사유 확인) ④배치 사전 점검 확인 후 실행 ⑤롤백 ⑥리포트의 "데이터 부족" 이유 설명하기. 성공 기준: 과업 ①~⑤를 도움 없이 완료, ⑥을 자기 말로 설명. 한계: 1인 경험이라 일반화 불가, 시니어 시청자 관점의 검증이 아님. 이 시험은 사용자 PC에서만 가능한 조작이므로 일정은 사용자 확인 필요(Q-UX-9).
