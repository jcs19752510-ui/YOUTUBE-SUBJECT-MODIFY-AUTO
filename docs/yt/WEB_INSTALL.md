## 1. 준비물 체크

| 필요한 것 | 확인 방법 |
|---|---|
| Windows 10 또는 11 | 시작 > 설정 > 시스템 > 정보 |
| **Docker Desktop** (Linux 컨테이너 모드) | 시작 메뉴에서 "Docker Desktop" 실행 → 작업 표시줄 고래 아이콘이 "실행 중"이 될 때까지 대기 |
| **WSL2** (Docker Desktop 기본 방식) | PowerShell에서 `wsl --status`. 오류가 나면 `wsl --update` 후 PC 재시작 |
| PC 가상화 켜짐 | 작업 관리자 > 성능 > CPU > "가상화: 사용". "사용 안 함"이면 PC 제조사 안내에 따라 BIOS 설정 필요 (Windows 기능 "가상 머신 플랫폼"도 켜져 있어야 함) |

| 디스크 여유 약 3GB, 메모리 여유 약 2GB | Docker Desktop 설정 > Resources |
| 빈 포트 **8080** | 다른 프로그램이 쓰고 있으면 시작 때 알려 줍니다 |
| 최신 Chrome 또는 Edge, 화면 폭 1024px 이상 | - |
| 이 저장소 폴더 (예: `C:\big21\vibe-coding\YOUTUBE-SUBJECT-MODIFY-AUTO`) | 폴더 안에 `web` 폴더가 있어야 합니다 |

## 2. 설치·첫 실행 (순서대로)

### 단계 1. Docker Desktop 실행
1. 시작 메뉴 > Docker Desktop.
2. 고래 아이콘이 움직임을 멈추고 "실행 중"이 될 때까지 1~2분 기다립니다.
3. 성공 신호: Docker Desktop 창에 "Engine running" 같은 상태가 보입니다 [확인 필요: 실제 문구는 버전마다 다름].
4. 아이콘 오른쪽 클릭 메뉴에 "Switch to Windows containers..." 가 보이면 정상(= 지금 Linux 모드)일 것으로 보입니다 [확인 필요]. "Switch to Linux containers..." 가 보이면 그것을 눌러 바꿉니다.

### 단계 2. PowerShell 열고 폴더로 이동
```powershell
cd C:\big21\vibe-coding\YOUTUBE-SUBJECT-MODIFY-AUTO
```
폴더 위치가 다르면 실제 위치로 바꾸세요. 성공 신호: 프롬프트가 그 폴더 경로로 바뀝니다.

### 단계 3. 이 창에서만 스크립트 허용
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```
이 창을 닫으면 원래대로 돌아갑니다(컴퓨터 전체 설정은 바뀌지 않습니다). 새 창을 열 때마다 다시 입력합니다.

### 단계 4. 시작
```powershell
.\web\scripts\start.ps1 -OpenBrowser
```
스크립트가 알아서 하는 일: Docker 확인 → 비밀번호 파일 만들기(처음 한 번, 값은 화면에 안 나옴) → 포트 확인 → 이미지 빌드·시작 → 준비 대기 → 주소 안내. **첫 실행은 5~15분** 걸릴 수 있으니 창을 닫지 마세요.

진행 중 보이는 메시지(`[안내]` 글자): `1/5 Docker 확인` → `2/5 비밀 파일 확인` → `3/5 포트 확인` → `4/5 이미지 빌드 및 컨테이너 시작` → `5/5 준비될 때까지 대기`.

성공 신호:
```
준비 완료!  브라우저에서 열기:  http://127.0.0.1:8080
```
그리고 브라우저가 열립니다.

주의 메시지: 비밀 파일을 처음 만들 때 "web\secrets 폴더는 데이터베이스 비밀번호입니다. 지우거나 다른 곳에 올리지 마세요." 가 나옵니다. 정상입니다. 이 폴더는 지우지 말고, 값은 누구에게도 보여 주지 마세요.

### 단계 5. 첫 화면 확인
- 접속 주소: **<http://127.0.0.1:8080>** (이 PC에서만 열립니다. 같은 와이파이의 다른 기기에서는 열리지 않는 것이 정상입니다.)
- 화면 위쪽에 띠 **"데모 모드 — 유튜브에 아무것도 전송되지 않습니다"** 와 "서버 연결됨"이 보여야 합니다. 화면 맨 아래에는 "이 검증은 법률 자문이 아니며 최종 책임은 채널 소유자에게 있습니다." 안내가 항상 보입니다.
- 왼쪽 메뉴: 홈 / 영상 목록 / 배치(일괄 반영) / 이력·롤백 / 성과 리포트 / 설정.
- 홈에서 **[데모 영상 불러오기]** 를 눌러 영상 200개가 생기면 설치 완료입니다. 이어서 `WEB_USER_MANUAL.md` 를 따라가세요.

### 단계 6. 상태 점검 (권장)
```powershell
.\web\scripts\status.ps1
```
성공 신호: 모든 서비스가 "정상", `migrate` 는 "마이그레이션 완료", 호스트 포트는 `127.0.0.1:8080->8080/tcp` 하나뿐, 마지막 줄이 "점검 결과: 문제 없음". `[위험]` 표시가 있으면 `WEB_RUNBOOK.md` 의 장애 대응을 보세요.

### 단계 7. 끄기 / 다시 켜기
- 끄기: `.\web\scripts\stop.ps1` (데이터 보존)
- 다시 켜기: Docker Desktop 실행 후 `.\web\scripts\start.ps1` (코드를 바꾸지 않았다면 `-NoBuild` 를 붙이면 빠릅니다)
- PC를 껐다 켜면: Docker Desktop은 자동으로 시작되지 않으니 직접 실행한 뒤 `start.ps1`.

## 3. 설치 후 내 PC에서 꼭 확인할 것 (체크리스트)

클라우드(Linux)에서는 확인하지 못했고 **선생님 PC에서만 확인할 수 있는** 항목입니다 (`web/README.md` 8장). 결과를 운영 담당에게 알려 주세요.

- [ ] 1. `start.ps1` 이 끝까지 성공하고 <http://127.0.0.1:8080> 이 열린다.
- [ ] 2. `status.ps1 -Detail` 에 `[위험]` 표시가 없고, "이 PC 의 포트 8080 리스너는 루프백(127.0.0.1)뿐입니다." 가 나온다. 같은 와이파이의 다른 기기(휴대폰)에서 `http://<내 PC IP>:8080` 이 **열리지 않는다**.
- [ ] 3. 브라우저에서 F12 키 → "콘솔" 탭에 "Content Security Policy" 오류가 없다.
- [ ] 4. `backup.ps1` → `restore.ps1 -Latest` (확인 문구 `복원합니다`)가 성공하고 행 수가 일치한다.
- [ ] 5. `stop.ps1` 후 `start.ps1` 해도 데이터가 남아 있다. PC를 재부팅한 뒤에도 Docker Desktop 실행 + `start.ps1` 로 복구된다.
- [ ] 6. (개발 담당용) 컨테이너 안에서 비밀 파일이 읽힌다: `docker compose -f web/compose.yaml exec api ls -l /run/secrets` — Windows에서의 읽기 권한 동작은 확인되지 않았습니다.

## 4. 자주 나는 문제

| 증상 | 원인과 조치 |
|---|---|
| "Docker 가 설치되어 있지 않거나 PATH 에 없습니다" | Docker Desktop 설치 후 PowerShell을 **새로** 열고 다시 실행 |
| "Docker 엔진에 연결할 수 없습니다" | Docker Desktop을 먼저 실행하고 고래 아이콘이 안정될 때까지 1~2분 기다린 뒤 다시 |
| "Docker 가 Windows 컨테이너 모드입니다." | 고래 아이콘 오른쪽 클릭 > Switch to Linux containers... |
| "Docker Compose 버전이 너무 낮습니다" | 2.20 이상이 필요합니다. Docker Desktop을 최신으로 업데이트 |
| "포트 8080 를 다른 프로그램이 이미 사용 중입니다." | 다른 프로그램이 8080을 씁니다. `Get-NetTCPConnection -LocalPort 8080 -State Listen` 으로 `OwningProcess`(번호) 확인 → `Get-Process -Id 번호` 로 프로그램 이름 확인 → 그 프로그램 종료 후 다시 시작. (이 프로그램이 이미 켜져 있어서 나오는 경우는 없습니다) |
| WSL 관련 오류 | `wsl --update`, `wsl --shutdown` 후 Docker Desktop 재시작. 그래도 안 되면 PC 재시작. Windows 기능 "가상 머신 플랫폼"과 BIOS 가상화가 켜져 있어야 함 |
| "스크립트를 실행할 수 없습니다" | 단계 3의 `Set-ExecutionPolicy -Scope Process ...` 를 **같은 창**에서 먼저 실행 |
| 빌드 중 다운로드 실패 | 인터넷/사내 프록시 확인. 회사 네트워크가 암호화 통신을 가로채면 Docker Desktop에 인증서 설정이 필요할 수 있습니다 |
| 처음인데 오래 걸림 | 5~15분은 정상. 제한 시간(기본 300초) 안에 준비되지 않았다는 경고가 나오면 `.\web\scripts\logs.ps1` 로 확인하고 `start.ps1 -NoBuild -TimeoutSec 600` 처럼 대기 시간을 늘려 보세요 |
| "비밀 파일(db_…_password)이 없는데 데이터베이스 볼륨은 이미 있습니다." | `web\secrets` 를 지웠기 때문입니다. 새 비밀번호를 만들면 기존 DB에 접속할 수 없으니, 백업해 둔 `web\secrets` 폴더를 되돌려 놓으세요. 데이터를 버리고 처음부터 시작하려면 `reset-demo.ps1 -DeleteVolumes` (**모든 데이터 삭제**, 확인 문구 `모든 데이터 삭제`) |
| 컨테이너가 계속 재시작 | `.\web\scripts\logs.ps1 -Service api` (또는 db / worker / migrate) 로 원인 확인 |
| 화면이 하얗게 나옴 | F12 콘솔의 "Content Security Policy" 오류 문구를 운영 담당에게 전달 |
| 브라우저에서 "연결할 수 없음" | 주소를 정확히 `http://127.0.0.1:8080` 로. 다른 주소·다른 포트는 열리지 않습니다 |

## 5. 설치하면서 조심할 것

- 설치 과정에서 `docker compose down -v`, `docker system prune --volumes`, Docker Desktop의 "Clean / Purge data" 는 **데이터가 영구 삭제**되니 사용하지 마세요.
- `web\secrets` 폴더는 지우거나 남에게 보내지 마세요.
- 베이스 이미지 갱신(`pin-digests.ps1`)은 설치 때가 아니라 정기 점검 때 합니다 (`WEB_RUNBOOK.md`).
- 개발자용 정보(구성, PostgreSQL 17 선택 이유, 테스트용 환경변수, 정적 점검 `python -m pytest web/tests_infra`)는 `web/README.md` 7장에 있습니다. 정적 점검 명령(`python -m pytest web/tests_infra`)은 시험 추가에 따라 건수가 계속 늘어납니다. 가장 최근에 기록된 값은 클라우드 Linux에서 197 통과·331 건너뜀(실제 컨테이너 기동 등이 필요한 시험)·예상된 실패(xfail) 1이며, 이 문서를 대조하면서 다시 실행하지는 않았습니다 [확인 필요: 8단계에서 재측정]. Windows PC에서는 실행하지 않았고, 일반 사용자는 실행하지 않아도 됩니다.

## 7. 알려진 보안 사항 3가지와 선생님이 지금 할 일 (데모 모드 한정으로 그대로 두기로 한 항목)

9단계 보안 점검에서 나온 항목 중, **지금(데모 모드, 가짜 데이터)에는 그대로 두기로 선생님이 결정한 3가지**입니다(2026-10-11, "M1 한정 수용"). 구글 연결 프로그램은 이미 만들어졌지만(8장) **실제 구글에 연결해 쓰기 전에 이 3가지를 다시 판단해야 합니다.** 다시 판단했다는 기록은 확인하지 못했습니다 [확인 필요]. 아래 번호는 점검 보고서의 항목 번호입니다.

### 7-1. 프로그램 안의 컨테이너가 이 PC에서 열려 있는 다른 서비스에 닿을 수 있음 (보고서 항목 9-011)
- **무엇이 위험한가**: Docker 컨테이너가 자기 네트워크의 "문 앞 주소(게이트웨이)"로 이 PC에서 모든 곳에 열려 있는 서비스(예: 원격 데스크톱, 파일 공유, 개발용 DB)에 접속할 수 있다는 것이 클라우드 Linux에서 측정되었습니다. 인터넷으로 나가는 길은 막혀 있습니다. 위험이 실제가 되려면 **먼저 컨테이너 안에서 공격자의 코드가 실행**되어야 하는데, 컨테이너는 권한을 최대한 줄여 놓아 가능성은 낮습니다. 지금은 가짜 데이터뿐이라 피해도 작습니다.
- **Windows Docker Desktop에서의 실제 동작은 사용자 PC 실측이 필요합니다.** Docker Desktop은 Linux 가상 머신 안에서 돌아서 결과가 다를 수 있고(더 막혀 있을 수도, 아닐 수도 있음), 클라우드에서는 확인할 수 없었습니다. 10단계(선생님 PC 구동 검증) 때 개발 담당이 확인합니다.
- **선생님이 지금 할 일**
  1. **Windows 방화벽을 켜 둔 상태로 유지**하세요(시작 > 설정 > 개인 정보 및 보안 > Windows 보안 > 방화벽 및 네트워크 보호에서 "켜짐" 확인).
  2. 이 PC에서 "모든 곳에서 접속 가능"하게 열려 있는 프로그램이 있는지 한 번 보세요. PowerShell에서 `Get-NetTCPConnection -State Listen | Where-Object { $_.LocalAddress -in '0.0.0.0','::' } | Sort-Object LocalPort | Format-Table LocalAddress,LocalPort,OwningProcess` (이 명령은 Windows에서 실행해 확인하지 못했습니다 — 내 PC에서 확인 필요). 8080(이 프로그램은 127.0.0.1에만 열림)을 뺀 목록에서 모르는 프로그램이 있으면 `Get-Process -Id 번호` 로 이름을 보고, 필요 없으면 끄거나 알려 주세요.
  3. 그 외에 지금 해야 할 조치는 없습니다.
- 다시 판단하는 때: 실제 구글에 연결하기 전, 다중 사용자, 외부 접속(다른 기기에서 접속)을 허용하기 전.

### 7-2. 감사 로그가 "DB 관리자 계정이 기록을 고치고 다시 계산"하는 것은 알아채지 못함 (보고서 항목 9-014)
- **무엇이 위험한가**: 감사 로그(누가 언제 무엇을 승인·변경했는지)는 기록마다 앞 기록의 해시(지문)가 이어져 있어, 중간 기록을 고치거나 지우면 화면의 검사가 알아챕니다. 하지만 **지문 계산에 비밀 키가 쓰이지 않아서**, DB 관리자(소유자) 비밀번호를 가진 사람이 기록을 고친 뒤 지문을 처음부터 다시 계산(재계산)하면 알아채지 못하고, 맨 마지막 몇 건을 통째로 지워도 알아채지 못합니다. 또 앱 계정이 감사 로그 외의 표(변경 이력·승인 등)는 수정할 수 있습니다(앱이 해킹당한 경우).
- **왜 지금은 그대로 두는가**: DB 관리자 비밀번호는 이 PC의 `web\secrets` 폴더에 있어, 그것을 가진 사람은 이미 이 PC를 장악한 것입니다. 한 사람이 혼자 쓰는 데모에서는 감수할 수 있는 수준으로 판단했습니다.
- **선생님이 지금 할 일**: 필수는 없습니다. `web\secrets` 폴더를 남에게 보내거나 공유 폴더에 두지 마세요. (선택) 중요한 작업을 한 날에는 감사 로그의 마지막 기록 건수를 메모해 두면 나중에 맨 끝이 지워졌는지 눈으로 비교할 수 있습니다.
- 다시 판단하는 때: **실제 구글에 연결하기 전**, **다중 사용자**가 생길 때, **외부 접속**을 허용할 때. 해결 방법 후보는 비밀 키를 쓰는 지문(HMAC) 또는 마지막 지문을 다른 곳에 따로 보관하는 것입니다.

### 7-3. 데이터 보관 기간·삭제·백업 암호화가 아직 없음 (보고서 항목 9-013)
- **무엇이 위험한가**: 작업 기록, AI 실행 기록, 감사 로그, 되돌리기용 원래 제목 조각은 **지우지 않고 계속 쌓입니다**. 백업 파일(`web\backups\*.dump`)은 **암호화되어 있지 않습니다**(파일 접근 권한은 현재 사용자로 제한하도록 만들었으나 Windows에서는 실측하지 못했습니다). 지금은 가짜 영상 데이터와 승인자 이름뿐이라 문제 소지는 낮습니다. 실제 채널 데이터(구글에서 가져온 정보)가 들어오면 얼마나 보관할지 정해야 합니다.
- **보관 기간 가정**: 되돌리기(롤백)용 데이터는 **30일** 보관을 가정해 설계했지만 **확정된 결정이 아닙니다**(질문 Q-W2·Q-W4 답변 대기).
- **개인정보 해당 여부**: 이 데이터가 개인정보 보호법 등에서 말하는 개인정보에 해당하는지는 **이 프로젝트가 판단하지 않습니다. 전문가 확인이 필요합니다.** 이 문서는 법률 자문이 아닙니다.
- **선생님이 지금 할 일**
  1. 백업 파일을 USB·클라우드 등 다른 곳에 복사할 때는 **암호화되지 않은 파일**이라는 점을 기억하고, 남과 공유하지 마세요.
  2. 실제 채널을 연결하기 전(**실제 구글 연결 전**)에 ① 보관 기간(30일 가정을 그대로 쓸지) 결정, ② 개인정보 해당 여부를 전문가에게 확인할지 결정을 해 주셔야 합니다. 그때 다시 질문드립니다.

> 위 3가지는 모두 "선생님이 지금 해야 할 큰 일"은 없고, 방화벽 확인(7-1)만 권장입니다. 결정 기록은 `docs/harness/decisions.md`(2026-10-11 보안 결정 항목), 원 보고서는 `docs/harness/security-web-m1-test.md` 입니다.

## 8. (선택) 구글 계정 연결 준비 — 2026-10-11 추가

> **먼저 읽어 주세요 — 정확한 상태**
> - **한 것**: 구글 연결(읽기)과 제목 수정(쓰기) 처리 코드를 만들고, **가짜 구글**로 자동 시험했습니다(코드 시험만 통과).
> - **안 한 것**: 실제 구글 서버에 접속해 본 적 없음. 실제 내 채널 영상을 불러온 적 없음. 실제 제목을 바꾼 적 없음. 선생님 PC(Windows)에서 이 8장의 절차를 실행해 본 적 없음. 아래 절차는 코드와 스크립트를 읽고 쓴 것이라 **내 PC에서 확인 필요**입니다.
> - 이 8장을 하지 않으면 지금까지처럼 데모 모드(가짜 영상, 외부 전송 없음)로 계속 쓸 수 있습니다.
> - **실제 제목 변경(배포 포함)은 선생님이 명시적으로 승인하기 전에는 하지 않습니다.**

### 8-1. 구글 쪽 준비 (한 번만)
자세한 클릭 순서는 `03_manual_setup.md` 2~5장을 따릅니다. 이 프로그램에 필요한 핵심만 다시 적습니다.
1. 구글 클라우드 프로젝트 **1개**를 만들고 "YouTube Data API v3"를 켭니다. (프로젝트를 여러 개 만들어 사용량 한도를 늘리는 것은 하지 마세요.)
2. 동의 화면: 게시 상태는 처음에는 **테스트**, **테스트 사용자에 본인 구글 계정을 추가**합니다. 테스트 상태에서는 로그인이 약 7일마다 만료될 수 있습니다(`03_manual_setup.md` 4-1, 이 내용 자체가 [확인 필요] 표시된 항목입니다).
3. 필요한 권한(범위) 2가지: 읽기 `youtube.readonly`, 제목 수정 `youtube.force-ssl`. 동의 화면의 범위 목록에 제목 수정 권한이 없으면 구글 로그인 때 막힐 수 있습니다 — 실제 동작은 **확인 필요**.
4. 클라이언트 ID 만들기: **애플리케이션 유형은 "데스크톱 앱"** 을 고릅니다. ("웹 애플리케이션"이 아닙니다. 데스크톱 앱이면 로그인 복귀 주소를 따로 등록하지 않아도 되도록 정했습니다. 다만 구글이 이 프로그램의 복귀 주소 `http://127.0.0.1:8080/api/v1/google/callback` 을 실제로 받아 주는지는 실제 접속을 해 보지 않아 **확인 필요**입니다.)
5. 만들면 나오는 JSON 파일을 내려받습니다. 이 파일은 **비밀번호와 같습니다.** 메신저·메일·깃허브에 올리지 마세요.

### 8-2. 내 PC에 파일 저장하고 다시 시작
1. 내려받은 JSON 파일의 이름을 **`google_client.json`** 으로 바꿔 저장소 폴더의 **`web\secrets\google_client.json`** 에 넣습니다. (`web\secrets` 폴더는 `start.ps1` 이 처음 실행될 때 비밀번호 파일용으로 만들어 둔 폴더입니다. 폴더가 없으면 먼저 `start.ps1` 을 한 번 실행하세요.)
2. PowerShell 에서 `.\web\scripts\start.ps1` 을 **다시 실행**합니다. 이 파일이 있으면 스크립트가 자동으로 구글과 통신할 수 있는 설정(`web/compose.online.yaml`)을 함께 씁니다. 파일이 없으면 쓰지 않아 외부 통신이 없는 상태 그대로입니다. 별도 옵션은 필요 없습니다.
3. 브라우저 홈 화면의 **"구글(유튜브) 연결"** 카드에서 "실제 유튜브에 연결하려면 web\secrets\google_client.json 을 저장한 뒤 .\web\scripts\start.ps1 을 다시 실행하세요." 안내가 사라지고 "구글 연결 준비가 됐습니다. [구글 계정 연결]을 눌러 로그인하세요. 읽기 전용이라 영상 제목은 바뀌지 않습니다."와 [구글 계정 연결] 버튼이 보이면 준비된 것입니다. (실제로 그렇게 보이는지는 내 PC에서 확인 필요.)

### 8-3. 화면에서 연결하고 영상 불러오기
화면 사용법은 `WEB_USER_MANUAL.md` 9장을 보세요. 요약: [구글 계정 연결] → 구글 로그인 → 홈으로 돌아옴 → [내 영상 불러오기]. 이 단계는 **읽기만** 하며 제목은 바뀌지 않습니다.
- 데모 영상에 승인·반영·롤백 기록이 이미 있으면 "데모 기록이 있어 불러올 수 없습니다"가 나옵니다. 이때는 `.\web\scripts\reset-demo.ps1` 로 데모 데이터를 초기화한 뒤 다시 불러옵니다(초기화는 데이터베이스를 비우는 작업이며 확인 문구를 입력해야 하고, 스크립트가 먼저 자동 백업을 합니다 — `reset-demo.ps1` 소스 기준, 실행해 본 적은 없음).

### 8-4. 실제 제목 수정을 켜는 방법
**전체 순서: 설치 → 시작 → 구글 연결(읽기) → 제목 수정 권한 연결 → `web\.env` 설정 → 다시 시작.** 실제 수정은 아래 **3가지가 모두** 맞을 때만 켜집니다. 하나라도 아니면 가짜(모의) 방식으로만 동작합니다.
1. 서버 설정 `YTWEB_LIVE_WRITE=1` (기본은 꺼짐)
2. 화면에서 [제목 수정 권한 연결]을 눌러 쓰기 권한을 허용함
3. 서버 설정 `YTWEB_LIVE_ALLOWED_VIDEOS` 에 **허용 영상 ID가 1개 이상** (영상 ID 여러 개는 쉼표로 구분)

**방법** (코드 확인과 `docker compose config` 로 값이 api·worker 에 전달되는 것까지 확인했습니다. **Windows PC 에서의 실제 동작은 내 PC에서 확인 필요**)
1. 8-2~8-3 을 끝내 구글 읽기 연결과 [내 영상 불러오기]까지 되는지 확인합니다.
2. 홈 "구글(유튜브) 연결" 카드의 **[제목 수정 권한 연결]** 을 눌러 구글에서 허용합니다(위 2번). 이것만으로는 제목이 바뀌지 않습니다. 카드에 "제목 수정 권한이 연결돼 있습니다."와 "실제 수정은 아직 꺼져 있습니다(수정 허용 영상 0개)." 및 부족한 것 안내가 나옵니다.
3. `web` 폴더의 `.env.example` 파일을 같은 폴더에 `.env` 라는 이름으로 복사합니다. (`.env` 는 저장소에 올라가지 않습니다.)
4. `.env` 를 메모장으로 열어 `YTWEB_LIVE_WRITE=1`, `YTWEB_LIVE_ALLOWED_VIDEOS=테스트영상ID` 로 고치고 저장합니다. (비밀번호·키가 아닌 스위치와 영상 ID뿐입니다.)
5. PowerShell 에서 `.\web\scripts\start.ps1` 을 다시 실행합니다. (구글 연결 파일이 있을 때만 이 값이 전달됩니다. 구글 로그인 정보는 저장 공간에 남아 있어 다시 로그인하지 않아도 됩니다 — 이 부분은 내 PC에서 확인 필요.)
6. 화면 맨 위 띠가 "실제 수정 모드 — 허용된 영상의 제목이 실제 유튜브에서 바뀝니다"로 바뀌고 홈 카드에 "실제 수정 모드가 켜져 있습니다"가 보이면 3가지가 모두 맞은 것입니다.
7. 켜기 전·후에 빠진 것이 없는지 보려면 `.\web\scripts\live-check.ps1` 을 실행하세요. 구글 연결 파일·읽기 로그인·제목 수정 권한·실제 수정 스위치·수정 허용 영상을 하나씩 확인해 빠진 것과 할 일을 알려 줍니다(아무것도 바꾸지 않고 구글에도 접속하지 않습니다). 이 스크립트는 Windows 에서 실제로 실행해 보지 못했습니다 — 내 PC에서 확인 필요.

### 8-5. 처음에는 테스트 영상 1개만 허용하는 절차 
1. 실제 채널에 **테스트용 영상 1개**를 정합니다(공개해도 문제없는 영상, 조회수가 중요하지 않은 영상 권장). 그 영상의 ID(유튜브 주소 `watch?v=` 뒤 11자리)를 확인합니다.
2. 허용 영상 목록에는 **그 1개만** 넣습니다. 목록이 비어 있으면 실제로는 아무것도 바뀌지 않습니다.
3. 서버 설정을 켠 뒤 `start.ps1` 로 다시 시작하고, 홈 카드에 "실제 수정 모드가 켜져 있습니다 … 수정 허용 영상 1개"가 보이는지 확인합니다.
4. 그 영상 1개로 제안 → 승인 → 배치 → 반영(확인 문구 `실제 실행 1건`)을 해 보고, 유튜브 Studio 에서 제목이 바뀐 것과 이력의 "되돌리기"가 되는 것을 확인합니다.
5. 문제가 없을 때만 허용 목록을 넓힙니다.
6. 끄려면: 화면의 [연결 해제] → [해제]를 누르면 됩니다(쓰기 로그인 정보도 함께 지워져 실제 수정이 바로 멈춥니다). 또는 `web\.env` 에서 `YTWEB_LIVE_WRITE=0` 으로 고치거나 `YTWEB_LIVE_ALLOWED_VIDEOS` 를 비운 뒤 `start.ps1` 을 다시 실행합니다. 끈 뒤에도 이미 바뀐 제목은 저절로 돌아오지 않으니 이력에서 먼저 되돌리세요.
