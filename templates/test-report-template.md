## 작성 보충 규칙 (ORCHESTRATOR.md 규칙 C 보칙)
- **9절 판정**은 `PASS` / `PASS (수용된 알려진 제한 포함)` / `CONDITIONAL PASS` / `FAIL` 중 하나로 쓴다. Open 결함이 있으면 PASS가 아니다.
- **6절 결함**: 결함이 0건이어도 "무엇을 어떻게 확인했는지"를 쓴다. ID는 `DEF-<단계>-<nnn>`, 신고된 결함은 `BUG-xxx`. 샘플 행(DEF-001)은 예시이므로 실제 결함이 없으면 삭제하고 0건 근거를 적는다. Deferred(사용자 수용)는 Low·Medium만 가능하며 DEC-ID를 병기한다.
- **해당 없음**은 사유 유형(업무 유형상 생략 N/A / 대상 자체가 없음)을 구분해 쓰고, **미수행**은 사유·잔여 위험과 함께 PASS로 세지 않는다.
- **7절 Teardown**: `git status` 원문을 첨부하고 변경 항목마다 소유 단계(또는 소유 조각)를 표기한다. 임시 환경을 만들지 않았다면 "생성하지 않음"을 명시한다.
