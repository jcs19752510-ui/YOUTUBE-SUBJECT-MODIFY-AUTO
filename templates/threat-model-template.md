# 위협 모델 (Threat Model) — 3단계 설계 시점 산출물

> `docs/harness/03-threat-model.md`로 작성한다. 9단계(구현 후 점검)가 "구현이 끝난 뒤에야 위협을 처음 생각하는" 구조가 되지 않도록, **설계 시점에** 자산·신뢰 경계·위협을 먼저 식별하고 대응을 `SEC-xxx`로 등록한다(규칙 H). 시스템이 작아도 생략하지 않으며, 작으면 짧게 쓴다(Tier로 완화되지 않음). 규칙 B(최소 2회 검증)를 적용한다.

## 1. 범위와 자산
| 자산 ID | 자산 (데이터/기능/계정/키) | 민감도 (공개/내부/민감/개인정보) | 소유 컴포넌트 |
|---|---|---|---|

## 2. 데이터 흐름과 신뢰 경계
(텍스트 또는 mermaid로 외부 사용자 → 프론트 → API → DB/외부 API 흐름을 그리고, 신뢰 경계를 넘는 지점을 표시한다.)

## 3. 위협 식별 (STRIDE: 위장·변조·부인·정보노출·서비스거부·권한상승)
| 위협 ID | 신뢰 경계/컴포넌트 | STRIDE 유형 | 위협 시나리오 | 가능성 (H/M/L) | 영향 (H/M/L) | 위험도 | 대응 방안 | 대응 SEC-ID | 잔여 위험 |
|---|---|---|---|---|---|---|---|---|---|

## 4. LLM/AI 기능이 있는 경우 추가 위협 (규칙 J)
프롬프트 인젝션(직접/간접), 도구 권한 오남용, 출력 렌더링 XSS, 시스템 프롬프트 유출, 비용 소진 공격 — 해당 여부와 SEC-ID를 표로 연결한다. 해당 없으면 사유.

## 5. 수용하는 잔여 위험
| 위협 ID | 수용 사유 | 수용 결정자 (사용자 응답 / 근거) | decisions.md ID |
|---|---|---|---|
- 위험도 High 위협을 대응 없이 수용하는 결정은 규칙 A 질문 대상이다(에이전트 임의 수용 금지).
