🛠️ 이 프로젝트는 어떻게 개발됐나

저장소 ORCHESTRATOR.md 기준 13단계 개발 하네스 파이프라인 — 기능 하나가 아니라 "작업 단위(unit)" 단위로 순차 진행됨

  • 1~4단계 — 기획/설계/디자인

    트렌드 분석 → 기획서(02-planning.md) → 시스템 설계서(03-system-design.md) → UX 디자인서. 여기서 REQ-001~039 요구사항 ID가 확정되고, docs/harness/traceability.md에 REQ→설계→작업단위(unit) 매핑표가 만들어짐.

  • 5단계 — 구현(unit 단위)

    기능 하나를 통째로 만들지 않고, Feature A~I를 다시 unit-1~unit-21로 쪼개 한 번에 하나씩 구현. 예: LLM 파이프라인은 unit-7 하나가 전담(services/llm_engine.py 등).

  • 6단계 — 단위테스트 + 결함 재작업 루프

    구현 직후 바로 테스트. 예컨대 unit-7(LLM 파이프라인)은 1차 테스트에서 결함 11건(오프닝 질문 품질 불량, Redis 무인증 노출 등)이 나와 재작업 v2를 거쳐 10건 수정 — worker/tasks.py 상단 주석(DEF-001~011)에 그 이력이 그대로 남아있음.

  • 7~8단계 — 통합/전체 시스템 테스트

    업무 단위(Feature) 내부 통합 → 시스템 전체 E2E. 현재 다수 REQ가 "L1 경량판 PASS, 08 착수 전 정산 필요"로 표기되어 있어, 정식 통합/전체테스트는 진행 중 단계.

  • 9~13단계 — 보안감사 / 배포검증 / 문서화 / 배포 / 배포후 검증

    REQ-035~039(AI 안전장치)가 미착수인 것과 연결 — 9단계 보안감사 이전에 반드시 먼저 채워야 하는 항목.
