랭체인/랭그래프/RAG 적용 검토

3개 모두 필수 사용 조건 기준 · 모의면접 프로젝트 PROD_SCH fb6e73c · 코드는 수정하지 않은 검토 결과

결론: 3개 모두 사용할 수 있습니다. 다만 "모든 메뉴"가 아니라 AI 호출이 있는 두 곳(면접장, 리포트 생성)에 붙이는 것이 현실적입니다.

  • RAG는 이미 면접장에서 동작 중이라 추가 작업이 거의 없습니다.
  • 랭체인은 패키지와 검증용 모듈이 이미 있습니다. 운영 경로에 연결만 하면 됩니다.
  • 랭그래프는 아직 없지만, 현재 코드의 "재시도, 폴백, 검증" 분기가 그대로 그래프 구조라 잘 맞습니다. 기존 패키지 버전과 충돌하지 않는 것도 확인했습니다.
  • 나머지 메뉴(이력서 검토, 최종 합격, 관리자 등)에는 현재 AI 호출이 없어서 붙일 대상 자체가 없습니다. 억지로 넣으면 기능 없는 장식이 됩니다.

20년차 관점의 위험과 대책

위험내용대책
모델 한계모델이 Qwen2.5 1.5B 양자화판이라 함수 호출·도구 사용 에이전트가 불안정합니다. 기존 모듈도 같은 이유로 with_structured_output을 쓰지 않았습니다.ReAct 같은 에이전트형은 쓰지 않고, 순서가 정해진 고정 그래프만 씁니다. 출력은 지금처럼 JSON 모드 + Pydantic 수동 파싱을 유지합니다.
운영 안정성 회귀llm_engine.py는 실측 결함 11건을 거쳐 안정화된 코드입니다. 통째로 바꾸면 같은 결함이 되살아날 수 있습니다.서버 기동·GPU→CPU 폴백 로직은 그대로 재사용하고(기존 모듈 방식), 환경변수 스위치로 "기존 경로/그래프 경로"를 전환할 수 있게 둡니다. 기존 테스트를 그대로 통과시킨 뒤 동등성 테스트를 추가합니다.
응답 시간생성 제한 25초, 질문당 처리 시간 예산이 있습니다. 그래프 오버헤드는 작지만 재시도 횟수가 늘면 초과할 수 있습니다.재시도는 현재와 같이 최대 1회로 고정하고, 노드별 소요 시간을 로그로 남깁니다.
패키지 호환기존 핀(langchain-core 0.3.x, langchain-openai 0.2.x, pydantic 2.x)과 랭그래프가 맞아야 합니다.임시 가상환경에서 의존성 해석을 확인했습니다. langgraph 1.0.1이 langchain-core 0.3.86, langchain-openai 0.2.14와 함께 설치 가능합니다. 실제 프로젝트 환경에 설치하거나 테스트를 돌린 것은 아닙니다.
실행 환경Celery를 --pool=solo로 쓰는 동기 방식, 상태는 DB에 저장합니다.그래프는 동기 invoke()로 실행하면 그대로 맞고, 랭그래프 체크포인터(별도 저장소)는 필요 없습니다.

권장 적용 범위

  • 1순위 면접장 꼬리질문: RAG + 랭체인 + 랭그래프를 모두 적용. "3개 필수" 조건을 충족하는 핵심 지점입니다.
  • 2순위 리포트 생성: 랭체인 + 랭그래프 적용. 분기가 가장 복잡해서 그래프의 효과가 가장 큽니다.
  • 그 외 메뉴: 현재 AI 기능이 없으므로 적용하지 않습니다. 이력서 AI 요약·적합도 같은 신규 기능을 만들 때 함께 붙이는 것이 맞습니다.

이 문서는 코드와 의존성을 검토한 결과이며, 프로젝트 코드는 변경하지 않았습니다. 실제 전환 시 응답 품질과 처리 시간은 로컬 모델로 실측해야 하고, 이 세션에서는 측정하지 않았습니다.
