온프리미스 변경 가능여부 절차

모의면접 프로젝트 · PROD_SCH 최신 소스 코드 검토(실행·성능 측정은 하지 않음) · 2026-10-12

결론: 전환 가능합니다. 이미 운영 경로는 대부분 로컬(온프리미스형)이고, 남은 일은 "서버 분리·모델 상향·외부 연결 차단·운영 체계"입니다.

  • 면접 LLM은 지금도 회사 밖 API가 아니라 같은 PC에서 뜨는 llama.cpp 서버(Qwen2.5 1.5B)를 씁니다. 지원자 답변이 외부 LLM으로 나가지 않습니다.
  • 다만 지금 구조는 "개인 PC 1대용"입니다. 앱이 모델 서버를 직접 띄우고(Windows 실행파일), 주소가 코드에 고정돼 있어, 별도 GPU 서버로 옮기려면 코드 수정이 필요합니다. 규모는 작습니다(파일 3~4개).
  • 가장 큰 숙제는 코드가 아니라 모델 품질입니다. 1.5B는 한국어 면접 품질이 낮아 보호 장치가 많이 붙어 있습니다. 온프리미스 서버로 옮기는 김에 7B~14B급으로 올리는 것이 정석입니다.
  • 데이터가 밖으로 나갈 수 있는 경로 1개(Deepgram 음성인식)가 키 설정 시 열립니다. 온프리미스 목적이라면 반드시 차단해야 합니다.

"온프리미스 LLM 서버"가 되기 위한 격차

항목현재온프리미스 서버 기준심각도
서버 분리앱이 exe를 직접 기동·종료(PID 파일). 주소 127.0.0.1:8091이 코드에 고정LLM 서버를 별도 호스트/서비스로 상시 운영, 앱은 URL 설정으로 접속높음
모델 품질1.5B. 질문 품질 가드·재시도·폴백이 많이 붙은 이유7B~14B급 한국어 강한 모델로 상향, 한국어 면접 평가셋으로 선정높음
동시 처리워커가 한 번에 1건(solo), 서버도 단일 슬롯 기준. 큐 상한 50동시 면접 수 기준으로 GPU·슬롯·워커 수 산정중간
외부 유출 차단Deepgram 키 설정 시 음성 전송 가능. 미연결 외부 어댑터 코드 존재외부 호출 코드·키 제거 또는 "온프리미스 모드"에서 강제 차단, 방화벽 아웃바운드 차단높음
서버 인증·보안로컬 호스트 전용이라 인증 없음내부망 분리, 서버 접근 키/mTLS, 요청 로깅 정책중간
모델 거버넌스모델 파일 1개를 수동 배치모델 버전·해시·라이선스 기록, 반입 절차, 롤백 가능한 버전 관리중간
운영 체계상태 확인은 기동 시 헬스체크 위주상시 헬스체크, 지연·오류 모니터링, 장애 시 폴백/알림중간
플랫폼Windows exe 전제서버는 Linux + NVIDIA GPU가 일반적(드라이버·컨테이너 운영 용이)선택

단계핵심 작업완료 기준
0. 요구사항동시 면접 수, 일일 면접 수, 망분리 수준(완전 폐쇄 / 아웃바운드 제한), GPU 예산, 데이터 보관 정책 확정수치로 적힌 요구서
1. 기준선현재 1.5B 기준으로 질문 품질, 턴당 응답 시간, 리포트 생성 시간, 실패율 측정비교 가능한 기준 수치
2. 코드 준비LLM_BASE_URL 설정화(두 호출 경로 모두), "외부 서버 모드"에서는 앱이 서버를 기동하지 않고 헬스체크만 수행, 요청 헤더 인증, 외부 어댑터 차단 플래그URL만 바꿔 같은 코드가 로컬·원격 양쪽에서 동작
3. 모델 평가후보(7B/14B급) 3개 이내를 같은 평가셋으로 비교: 한국어 질문 자연스러움, JSON 형식 준수, 지연, 메모리. 라이선스 원문 확인선정 근거 문서
4. 서버 구축GPU 서버 설치, 추론 엔진 선택(소규모는 llama.cpp 서버, 동시 사용자가 많으면 vLLM 같은 배치 엔진), 모델 반입, 내부망 연결앱 서버에서 헬스체크 통과
5. 보안 잠금Deepgram 코드 차단(완료, 2026-10-12) 및 미사용 외부 어댑터 정리, 서버 인증, 방화벽 아웃바운드 차단(SMTP 메일 외부 발송은 처리 제외, 메일 서버만 예외 허용), 프롬프트·응답 로그 보관 정책외부 접속 시도 0건 확인
6. 병행 검증신구 경로를 스위치로 비교, 동시 면접 부하 테스트, 장애 주입(서버 다운 시 폴백 문구 동작)기준선 대비 품질 동등 이상, 응답시간 예산 충족
7. 전환운영 모델 교체. 이전 경로는 롤백용으로 일정 기간 유지롤백 리허설 완료
8. 운영지연·오류 모니터링, 모델 버전·해시 기록, 정기 품질 재평가운영 점검표 가동

기존 보호 장치(질문 품질 가드, 재시도, 질문은행 폴백, 레이트리밋, 큐 상한)는 그대로 두고 재사용합니다. 모델이 좋아져도 폴백은 서버 장애 대비로 계속 필요합니다.

착수 전 확인이 필요한 항목

  • 동시 면접 수와 일일 면접 수: GPU 사양과 추론 엔진 선택을 결정합니다. 이 숫자가 없으면 서버 용량을 정할 수 없습니다.
  • 망분리 수준: 완전 폐쇄망인지, 아웃바운드만 제한하는지에 따라 모델 반입 방법과 메일 발송 방식이 달라집니다.
  • GPU 보유·예산: 대략적으로 7B급 4비트 양자화는 VRAM 수 GB대, 14B급은 10GB 안팎이 필요합니다(일반적인 수치이며 모델·컨텍스트에 따라 달라지므로 후보 모델로 실측해야 합니다).
  • 모델 라이선스: 상용·내부 사용 조건을 선정한 모델의 원문으로 확인해야 합니다. 이 검토에서는 확인하지 않았습니다.
  • 면접 데이터 보관 정책: LLM 요청·응답 로그를 남길지, 얼마나 보관할지 결정이 필요합니다.

이 문서는 검토 결과이며 코드는 변경하지 않았습니다. 위 확인 항목이 정해지면 2단계(코드 분리 준비)부터 바로 착수할 수 있습니다.
