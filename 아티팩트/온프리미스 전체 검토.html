결론: 면접 핵심 기능은 전부 내부망에서 동작합니다. 외부망이 필요한 곳은 5가지였고, 코드 에디터(Monaco)는 2026-10-12에 해결했습니다. 메일 발송은 지원자에게 보내야 해서 외부로 나가는 것이 본질이므로 조치 대상에서 제외합니다. 음성인식 키 차단과 설치물 반입을 조치하고 방화벽으로 확인하면, 메일 외에는 모두 내부망에서 동작합니다.

방화벽 점검 쉬운 설명

비유: 건물 출입문입니다. 들어오는 사람을 막는 것(인바운드)은 흔하지만, 여기서는 건물 안에서 밖으로 나가는 사람(아웃바운드)을 막습니다. 직원(프로그램)이 몰래 밖에 전화를 걸어 자료를 보내는 일이 없는지 출입 기록으로 확인하는 것입니다.

단계하는 일쉬운 설명
1. 허용 목록 만들기밖으로 나가도 되는 곳을 정함예: 메일 서버(smtp.gmail.com의 587번 포트) 하나뿐. 나머지는 전부 막을 대상
2. 기록부터 켜기막기 전에 방화벽 로그만 켜고 평소처럼 면접을 한 번 진행누가 어디로 나가려 하는지 먼저 관찰. 막았다가 서비스가 멈추는 사고를 방지
3. 기록 읽기로그에서 목적지가 사내망이 아닌 접속을 찾음메일 서버 외에 보이는 주소가 있으면 "어떤 프로그램이 왜 나가는지" 추적
4. 차단하기허용 목록 외 외부 나가는 통신을 기본 차단이제 숨은 외부 호출이 있어도 나가지 못하고 "차단됨"으로 기록
5. 다시 면접 + 차단 기록 확인면접 전 과정(로그인, 질문, 음성, 코드, 리포트, 메일)을 다시 진행차단 기록이 없거나 예상한 것뿐이고, 기능이 모두 정상이면 통과

서버는 백엔드·워커·모델이 도는 PC, 클라이언트는 면접자·채용담당자가 쓰는 PC입니다. 서버는 위 절차로, 클라이언트는 "서버 주소로만 접속 가능"한지(코드 에디터 등이 인터넷을 요구하지 않는지) 같은 방식으로 확인합니다. 차단을 걸 때는 사내 DB·DNS·원격접속 같은 필요한 통신을 허용 목록에 먼저 넣어야 서버에 접속이 끊기지 않습니다.

확인하지 못한 것

  • 실제 운영 PC의 .env 값(Deepgram 키 설정 여부)과 방화벽 상태는 이 환경에서 볼 수 없습니다.
  • Monaco는 해결 후 인터넷을 차단한 브라우저로 에디터 표시·입력·언어 전환을 확인했습니다(개발 서버·운영 빌드 모두). 다만 로그인 후 실제 면접 진행과 코드 제출까지의 전체 흐름은 이 서버에서 검증하지 못했으므로 PC에서 확인이 필요합니다.
  • DeepFace 가중치와 웹캠 화상의 외부 STUN 사용 여부는 소스에서 설정을 찾지 못했다는 수준의 확인이고, 실제 네트워크 캡처로 검증하지 않았습니다.
