TTS→ElevenLabs
벡터DB→Pinecone자원 필요		 TTS는 면접관 음성에 감정(격려/압박 톤)을 실어 몰입감을 높이고, 벡터DB는 질문은행이 커질 때 매니지드 확장성을 제공. 어댑터 코드는 전부 작성 완료(unit-32). 2026-09-23(DEC-059) 사용자가 "원안에 유료는 모두 진행하지 않겠다"고 명시 선언 — 예산 문제가 아니라 사용자의 선택. WebRTC 실제
영상 기능 완성하드웨어·시간 한계		 AI 면접관이 지원자의 실제 영상을 "보고" 비언어적 신호(DeepFace 등)를 분석하는 최종 목표 — 현재는 시그널링(연결 수립)만 되고 영상 자체는 전송되지 않음. unit-28에서 시그널링 서버(SDP/ICE 중계)만 실제 구현·검증. 실제 미디어(RTP 오디오/비디오) 처리는 별도의 대규모 작업(aiortc 미디어 서버). 2026-09-24(DEC-072) 사용자가 "지금은 그대로 두겠다"고 명시 확정. ① aiortc 기반 미디어 서버 프로세스 신설 → ② 프론트엔드에 RTCPeerConnection/getUserMedia 코드 작성(현재 전무) → ③ STUN/TURN 서버 구성 → ④ 실제 브라우저로 검증. 수주 단위 전담 작업 필요 — 사용자가 원할 때 재개.
GDPR/CCPA
완전 준수법무 필요		 해외(EU/미국 캘리포니아) 사용자 대상 서비스 확장 시 법적 리스크 회피. 코드로 가능한 부분(적법근거·CCPA고지·데이터이동권)은 전부 구현·검증 완료. 2026-09-24(DEC-071) 재조사 결과 남은 항목(DPO 지정, 역외이전 안전조치)은 실행할 코드·엔드포인트 자체가 없는 조직적·법적 행위임을 확인 — 이 항목은 유일하게 "코드로 더 갈 수 없는" 항목. ① 실제 법무 자문으로 이 서비스가 EU/CA 거주자를 대상으로 하는지부터 확인 → ② 필요 시 사람을 DPO로 지정 + SCC 등 이전계약 체결(둘 다 소프트웨어 작업이 아님).

VAD 기반 실시간 끼어들기 ● 대 근본 재설계 필요 해당없음 "턴제"는 §4.3 설계서가 명시적으로 확정한 아키텍처 전제(WS는 서버→클라이언트 푸시 전용). 클라이언트→서버 실시간 오디오 스트림 채널 신설 + VAD 통합 + TTS 재생 중단 로직까지 전면 재설계. 2026-09-23(DEC-059 재평가) 막힌 이유가 예산이 아니라 순수 개발 시간(대규모 재설계) 문제임을 재확인.
메인DB → Oracle ● 대 비권장 해당없음 JSONB, pgvector(Vector 타입) 등 PostgreSQL 전용 기능을 스키마 전반에서 사용 중 — Oracle은 미지원(23ai 벡터타입 쓰려면 드라이버·마이그레이션 전면 재작성). 상용 라이선스 비용도 별도 발생 — 순수 예산 문제.
500명 동시접속 처리 ● 대 현 하드웨어로 사실상 불가 해당없음 단일 GPU·단일 LLM 서버 직렬 처리 구조. GPU 인스턴스를 요청량만큼 수평확장하지 않는 한 대기열이 선형으로 쌓여 지연이 폭증 — 코드 문제가 아니라 물리적 컴퓨팅 자원의 한계(순수 예산 문제).

'대(大)' 판정 항목들이 공통으로 부딪히는 5가지 제약. 코드 몇 줄로 해결되지 않는 이유

1. 하드웨어 물리적 한계

LLM(Qwen2.5-1.5B)이 이미 GPU VRAM을 598MiB → 1,717MiB까지 점유(실측). 로컬 GPU 1개(가용 예산 약 3,387MiB) 안에서 실시간 영상 감정분석·다중 동시추론까지 얹으면 자원 경합이 발생합니다.

Celery 워커가 --pool=solo(단일 프로세스 직렬)로 고정된 것도 "GPU는 물리적으로 1개"라는 전제 때문 — 동시접속 500명은 코드 최적화가 아니라 GPU 인스턴스를 요청량만큼 늘리는 하드웨어 투자로만 해결됩니다.

2. 라이선스 · 법적 제약

DeepFace류 감정인식 AI는 EU AI Act가 특정 감정인식 활용을 금지 목록에 올리는 논의가 진행 중이고, 국내법상 얼굴·음성은 민감정보(생체인식정보)라 별도 동의·안전조치 의무가 가중됩니다.

💳

3. 예산 제약

Deepgram·Hume AI·ElevenLabs·Pinecone·GPT-4V·Oracle·AWS/GCP는 전부 유료 서비스입니다. 현재 프로젝트는 이미 문서화된 결정(DEC-004~007)으로 "예산 없음"을 전제로 전량 오픈소스/로컬 대체를 확정했습니다.

역으로 말하면, 예산만 확보되면 TTS·STT·벡터DB 전환은 대부분 '소' 난이도입니다 — 진짜 제약은 코드가 아니라 예산인 항목이 많습니다.

🏗

4. 아키텍처 근본 차이

원안은 5계층 이벤트기반 마이크로서비스(영상 스트리밍용 Signaling/Media Server 포함)였지만, 실제는 단일 FastAPI 모놀리스입니다. 영상 스트림 자체가 없으므로 감정분석·VAD 끼어들기·GPT-4V 화이트보드분석은 전부 "없는 전제" 위에서 설계된 기능입니다.

되돌리려면 새 계층을 처음부터 신설해야 하고, 이는 기존 "턴제 REST 단일경로"(§4.3에서 이미 확정한 설계 결정)를 뒤집는 근본적 재작업입니다.
